Колонка C «Динамики финансы» = `F−SUM(H:N)+P+Q` должна сходиться с **W**
(«Итого к оплате ВБ» из сводного excel, его ставит `pay-compare.js`; рядом X —
`=C/W*100`). Подписи этих колонок стоят во ВТОРОЙ строке листа. Писать сверку в
AG/AH нельзя: AG — это «PnL» верхнего блока листа, туда она уезжала до
04.08.2026, а W/X оставались пустыми.
Разложение недели 27.07–02.08.2026 (сумма двух отчётов):

```
К перечислению за товар      287 627,17   = F − I (выручка минус комиссия)
− логистика                   53 826,02   H
− хранение                     8 476,19   J
− удержания «WB Продвижение»  77 173,00   N  ← реклама, УДЕРЖАННАЯ ВБ
− штрафы                          70,00   L
+ добровольная выплата        20 000,00   Q  ← компенсация за пострадавший товар
+ мелочь по лояльности             6,60   P
= Итого к оплате             168 088,56
```

Ключевое: **в N нужна реклама, удержанная ВБ, а не потраченная в кабинете.**
`ads.js` даёт расход кабинета (за ту неделю 81 625 ₽), ВБ удержал 77 173 ₽ —
остаток он переносит в следующий отчёт. Для юнит-экономики (колонка V вкладки)
правильна кабинетная цифра, для «к перечислению» — удержанная. До 27.07 они
почти совпадали, поэтому расхождения не было видно.

В отчёте эти суммы лежат в колонке «Удержания» (индекс 60), вид — в «Виды
логистики, штрафов и корректировок ВВ» (индекс 42): строки «Оказание услуг
"WB Продвижение"» и «Добровольная выплата за товары, пострадавшие…» (со знаком
минус, то есть выплата НАМ).

С 04.08.2026 это автоматизировано: `pay-compare.js` сам ставит L, M, N, P, Q по
неделям, чьи отчёты лежат в `reports/extracted` (старые недели без файлов не
трогает), а `reports-dynamics.js` больше НЕ пишет N — иначе затирал бы
удержанную рекламу ссылкой на `V302`. После этого недели 13.07, 20.07 и 27.07
сходятся с ВБ до копейки.
