Скрипт `C:\Users\User\dolphin_anty\instagram_hashtag_dashboard.py` собирает посты по
хэштегу Instagram (профиль Dolphin 859648353), фильтрует по лайкам > порога и делает
скриншот каждого прошедшего поста для дашборда-сводки по тренду (артефакт вида
таблицы/карточек, публикуется в Claude Artifact).

**Правильный источник:** страница хэштега — `https://www.instagram.com/explore/tags/<tag>/`,
а НЕ `/explore/search/keyword/?q=%23<tag>` (та отдаёт мусорные ссылки на комментарии,
а не сами посты).

**Как реально доставать число лайков (новый интерфейс IG, 2026):** текста "X likes" на
странице поста больше нет. Число лайков — это `<span role="button" tabindex="0">` сразу
после `svg[aria-label="Like"|"Unlike"]` внутри его `closest('section')`. Формат текста:
голое число ("298") или сокращённое ("1.9K", "12K", "27.9K", "1.2M"). Старый способ
(парсить голые числа перед строкой даты) ЛОМАЕТСЯ на постах с сокращёнными лайками —
регекс по чистым цифрам перед датой вместо лайков хватает число КОММЕНТАРИЕВ (напр. пост
amnasijercic/DFCooqdN4QD: реальные лайки 1.9K, а старый парсер вернул 409 — это на самом
деле число комментариев). Использовать только DOM-метод через `page.evaluate`.

**Рилы на странице хэштега:** `/explore/tags/<tag>/` в текущем интерфейсе НЕ отдаёт ссылок
вида `/reel/...` вообще (проверено на #plaidskirt — 0 из 24). Нет и явной вкладки
"Top/Recent/Reels". Если нужны именно рилы — либо считать видео-посты (`<video>` в DOM)
рилами независимо от URL, либо заходить в Reels-вкладку профиля каждого автора отдельно.
Решение по этому вопросу пользователь давал на лету (сессия 2026-09-14) — сверяться с ним,
если задача повторится.

**Критичная грабля — `start_with_retry` перезапускает браузер:** в `dolphin.py` функция
при ошибке "already running" делает `api.stop()` + ждёт + `api.start()` заново — это
СБРАСЫВАЕТ все открытые вкладки профиля. Если дёргать её из отдельных Bash-вызовов подряд
(каждый со своим `python -c ...`), профиль постоянно перезапускается, вкладки теряются,
скриншоты уходят пустыми/чужими. **Правило: делать всё в ОДНОМ запуске скрипта** (один
`with sync_playwright()` блок, все шаги последовательно с `time.sleep` внутри), не дёргать
`start_with_retry` из серии отдельных команд.

**Скриншоты постов = уже готовый вид карточки:** `page.screenshot()` на viewport
~1120x860 после захода на `/p/<code>/` даёт ровно то, что просил пользователь — фото +
сайдбар с лайками, как в примере `Desktop\55.PNG`. Резать/кадрировать не нужно, только
сжать (Pillow, resize до ~640px ширины, JPEG q=82) для веса дашборда.

**Риск блокировки:** при частых подряд переходах между постами IG иногда подменяет
страницу на заставку-сплэш (защита от автоматизации) — тогда `inner_text`/`eval_on_selector_all`
возвращают пусто. Если это случилось — сделать паузу (несколько минут), не долбить чаще.

**Результаты по #plaidskirt (2026-09-14):** из 48 просканированных постов реальных рилов
на странице хэштега не нашлось вообще (только фото/карусели); максимум лайков — 32.2K
(`CL3FYksH3PV`), порог >1000 прошли примерно 8-9 постов. Первый дашборд-артефакт
"Plaidskirt Pulse" был опубликован ДО починки парсера лайков — числа там не точные
(старый баг с комментариями вместо лайков), пересобрать заново починенным скриптом.

**How to apply:** [[dolphin-anty-scripts]] — использовать `instagram_hashtag_dashboard.py`
как основу для новых хэштегов/трендов, не писать парсер лайков заново.
