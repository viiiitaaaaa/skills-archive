# prove-it

Скилл для Claude Code и других агентов. Одно правило: **не говорить «готово»
без доказательства.**

Агент, который использует этот скилл, прикладывает к результату короткий
отчёт — что проверил, чем именно и что вернула проверка. Плюс отдельно
пишет, что осталось непроверенным.

Вместо этого:

> Готово! Всё работает, тесты проходят.

Приходит это:

```
Готово: фильтр по датам в отчёте починен.

Проверено:
  тесты не падают        → pytest tests/reports, 34 passed, 0 failed
  исходный баг ушёл      → запрос за 31.03 возвращает 12 строк,
                           до правки возвращал 0
  правки в файлах        → git diff: reports/filters.py, +14 −6
Не проверено:
  поведение на годовом диапазоне - выходит за рамки задачи
```

## Зачем

Агент собирает картину из того, что успел посмотреть, а остальное
достраивает по контексту. Достроенное выглядит в ответе ровно так же
уверенно, как проверенное: тот же тон, та же убедительность.

Поэтому просьба «перепроверь» так часто заканчивается фразой «повторный
аудит переворачивает мои выводы». Скилл убирает этот шаг: доказательства
приходят сразу, спрашивать не нужно.

## Установка

Claude Code:

```bash
git clone https://github.com/kophysty/prove-it.git ~/.claude/skills/prove-it
```

Windows (PowerShell):

```powershell
git clone https://github.com/kophysty/prove-it.git "$env:USERPROFILE\.claude\skills\prove-it"
```

Другие агенты: положить `SKILL.md` туда, где агент читает инструкции,
или просто дать ему прочитать файл.

После установки скилл включается сам, когда агент собирается заявить
о завершении работы. Можно позвать и явно: «отчитайся о проверке»,
«точно готово?», «проверь, что сделано».

## Что внутри

```
Отчёт о проверке          формат, который прикладывается к «готово»
Пять вопросов приёмки     что спросить, принимая чужую работу
Таблица доказательств     какое заявление чем закрывается
Ловушка успешного ответа  «отправлено» ≠ «получено», зелёный тест ≠
                          тест что-то проверил
Красные флаги             слова, за которыми обычно нет проверки
```

Отдельные разделы про то, как проверки обманывают сами себя: проверка,
которая ни разу не срабатывала; поиск нужного без поиска лишнего; сверка
имён вместо содержимого; две «независимые» проверки с общим источником.

## Безопасность

Это обычный markdown-файл с инструкциями. Он ничего не запускает,
никуда не отправляет данные и не требует доступов. Всё, что делает
скилл — меняет то, как агент отчитывается о работе.
