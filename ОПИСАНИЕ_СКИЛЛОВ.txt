14. trend-radar — ТРЕНД-РАДАР ЖЕНСКОЙ ОДЕЖДЫ (v2, переписан 22.09.2026)

===============================================================================

Что делает: проверяет вещи-кандидаты (config/candidates.csv, 22 шт.) шестью

независимыми «свидетелями» — Google, Pinterest, YouTube (поиск + YouTube

Data API), TikTok Creative Center, Amazon, новинки брендов (Zara, ASOS,

Aritzia, Free People) — и решает: 4+ подтверждения — тестировать, 3 —

наблюдать, меньше — отказ. Плюс метка «сезон» и подсказки поиска (что люди

дописывают к названию вещи: цвет, фасон). Всё выводится в дашборд с кривыми

за 2 года (Artifact + локальный dolphin_anty\trend_radar_dashboard.html).



Принцип: рост считается по двум годам — среднее за последние 8 недель

против тех же 8 недель год назад, порог +15%. «Сезон» — если год назад в

эти же недели был такой же подъём, а в этом году не выше. Редкие фразы

(данные меньше чем в половине недель) в решение не идут — иначе «0→12 =

+1000%». Одна выстрелившая неделя ничего не решает.



Правила: никаких автозапусков — сбор только по команде; Dolphin строго

профиль 859648353; TikTok — окно не меньше 90 дней; защиту сайтов не

обходим (никаких неофициальных библиотек с логином/маскировкой); AliExpress

из логики убран; ключи только в .env проекта.



API на 22.09: YouTube — работает; Trends MCP — подключён (поиски на Amazon в месяц,

крупные хэштеги TikTok; бесплатно 100 запросов/мес, 90 дней истории); Etsy — ключ забанен,

канал закрыт; Reddit — исключён

(коммерческое использование требует письменного одобрения); Merchant Center

и Meta Ad Library — нужна карта; Instagram Graph API — путь через аккаунт

«Автор» + страницу Facebook + приложение Meta в режиме разработки.



Проект: C:\Users\User\fashion-trend-radar\fashion-trend-radar

Пересчёт и дашборд: .\.venv\Scripts\python.exe run_radar.py, затем

build_dashboard.py. Логика и история решений — TZ_trend_scoring.md.

Бэкап кода: GitHub automation-scripts / fashion-trend-radar.
