27.09.2026 я сверила 215 юбок PDD с 38 из «Отбора» глазами по одному главному фото-миниатюре и написала «точных
совпадений нет» — она: «плохо сделал вывод».

**Why:** одна модель у разных продавцов снята по-разному; миниатюра 230 px и одно фото не доказывают ни «да», ни «нет».
Вывод «нет» по такой сверке — ложная уверенность.
**How to apply:** доказательная сверка = для каждого товара PDD поиск по фото на 1688 → список offerId и магазинов
→ пересечение с ID и магазинами листа «Отбор» (тот же магазин может продавать модель под другим ID) → совпадения
сверить всеми фото. Визуальную сверку подавать только как «кандидаты», не как вывод. Темп 1688: 3–4 поиска
подряд, пауза ~1 мин, вкладка Chrome видимая.
27.09 вечер: после дневного антибота поиск по фото через URL (s.1688.com/youyuan…imageAddress=) снова ушёл в
punish уже на 4-м поиске, а 3 предыдущих вернули «空空如也» — пустая выдача при антиботе = НЕ «нет результатов».
РЕШЕНИЕ 27.09: результаты сверки писать ТОЛЬКО в лист «Отбор» главного документа (столбцы L–N) через
cj\otbor_pdd.tsv + otbor_pdd.ps1; лист «Сверка» она отвергла («не туда»). Поиск — загрузкой фото (imageId), её способ.
ПЕРВОЕ СОВПАДЕНИЕ (нашла она, 27.09): лист 3 №24 (строка 25, замша на резинке + шифоновый подол в клетку) = O34
1077320460261 (滁州言言, 52 ¥, от 1 шт, 12 продаж, выложена 19.08.2026, 66% по выгрузке). Я его пропустила: сравнила O34
с №92/№38, а не с №24. Урок: кроме фото сверять КЛЮЧЕВЫЕ СЛОВА названий (麂皮 + 拼接 + 松紧 и т.п.) — перевод
листов PDD лежит в столбце «Что это», китайские названия — в pddN\pdd_items_skirts.json.
ЕЁ ПРОВЕРКА (27.09, отметки в «Отборе»): O34 ↔ лист3 №24 — ДА; O14 ↔ лист3 №34 — НЕТ; O17 ↔ лист1 №45/102/46/106 —
«НЕТ ИЛИ ЧАСТИЧНО ПОХОЖИЕ». Вывод: одна съёмка/фабрика и похожий крой ≠ та же модель; «вероятно» ставить только
при совпадении деталей (фурнитура, вставки, подол), не по фону и силуэту. Её ДА/НЕТ стоят в свободных ячейках
справа (P, S) — скрипт их не трогает, картинки ставит только в O–R.
Её находка: лист3 №49 (строка 50, клетка с бахромой) → 1688 1079640464336 — перекупщик, рейтинги плохие, <10 продаж,
выложена 27.08.2026 → «нет», фабрику не нашли. Она ищет сама через панель расширения по открытым вкладкам Chrome.
Если в открытом файле её несохранённые правки — мои записи всё равно попадают в открытую книгу; просить её Ctrl+S,
копии _vN удалять, чтобы не было двух версий.
Готово для запуска: cj\sverka\queue_p3.json (99 юбок листа 3 по продажам), otbor_keys.json; скрипт сравнения
хранится в localStorage air.1688.com ('otbK' ключи, 'otbF' код) → `await eval(localStorage.getItem('otbF'))`
возвращает только пересечения с «Отбором». Не пройдено ни одной юбки (№98 — пусто из-за блокировки). Связано: [[plan-pdd-vs-1688-otbor]], [[sessiya-27-09-itogi]].
