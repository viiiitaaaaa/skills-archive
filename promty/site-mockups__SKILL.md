# Подложка сайта через ComfyUI Cloud

Полный цикл: собрать workflow в облаке, прогнать все экраны одним рецептом, отобрать удачные, свести в дизайн-систему и галерею.

Первоисточник постановки — `comfyui_base_theme_guide.md` в Downloads. Структура разделов и типы сетов — `tz_site_structure.md` там же. Стили коллекций берутся из скилла `style-collections`.

## Как гонять генерацию

Через браузер в ComfyUI Cloud, не через голый HTTP: прямые вызовы `/api/*` отбиваются авторизацией, а `api.fetchApi` внутри страницы уже подписан.

Полный рецепт вызовов, сборка графа и опрос статусов — `comfy_api.md` в папке скилла. Кратко:

1. Открыть вкладку с воркспейсом, дождаться загрузки (первый рендер ~10 с).
2. `const api = window.comfyAPI?.api?.api || window.app.api` — точка входа.
3. Собрать API-формат графа (`CheckpointLoaderSimple → CLIPTextEncode → FluxGuidance → EmptySD3LatentImage → KSampler → VAEDecode → SaveImage`) и слать `api.queuePrompt(-1, {output, workflow:{}})`.
4. Опрашивать `api.getJobDetail(id)`, забирать файлы через `api.getJobAssets(id)` и `api.fetchApi('/view?filename=<hash>')`.
5. Смотреть результат — рисовать blob в оверлей поверх страницы и делать скриншот. Картинки живут только внутри вкладки, пока не скачаны.

Ограничение среды: `javascript_tool` падает по таймауту на 45 с. Циклы ожидания резать на куски по 5–6 итераций с паузой 5–6 с и вызывать повторно. Расширение иногда отваливается — переподключить и продолжить, задачи в облаке при этом не теряются.

## Рецепт генерации — не менять между экранами

| Параметр | Значение |
|---|---|
| Модель | `flux1-dev-fp8.safetensors` |
| Sampler / scheduler | `euler` / `simple` |
| Steps / CFG / guidance | 25 / 1.0 / 3.5 |
| Latent | `EmptySD3LatentImage`, десктоп 1344×768, мобайл 832×1216 |
| Seed | одна серия подряд идущих чисел на весь прогон |

Негативный промт бесполезен: у Flux CFG = 1.0, он игнорируется. Всё управление — только позитивным текстом.

Холодный старт машины — до 2–3 минут на первую задачу, дальше ~40 с на картинку. Пачку из 11 экранов ставить в очередь целиком, не по одной.

## Как писать промт

Промт = «голова» экрана + общий «хвост» стиля. Хвост одинаковый слово в слово во всех генерациях, меняется только голова.

Голова обязана начинаться с `Full desktop web page screenshot of ...` (или `Mobile phone screen mockup of ...`) и перечислять элементы интерфейса: навбар, карточки, кнопки, поля. Добавлять `flat full width web page layout without any device frame`, иначе модель рисует макбук или монитор вокруг страницы.

**Главная ловушка.** Атмосферные формулировки в хвосте — «луч солнца через карточки», «cinematic lighting», «gallery calm» — перебивают интерфейс, и модель выдаёт фотографию освещённой стены вместо экрана. Так был потерян целый прогон из 11 картинок. Свет описывать только внутри карточки: `product photos lit by a crisp directional spotlight from the upper left with a long soft shadow inside the cards`.

Вторая ловушка: без слов `home decor`, `vases`, `ceramics`, `no clothing, no people` модель уводит каталог в одежду.

Готовые головы всех экранов и рабочие хвосты — `prompts.md`.

## Дизайн-система: два слоя

Ключевое требование заказчика, проверено на трёх итерациях. Рамка не должна принадлежать ни одной коллекции.

**Оболочка** — ахроматическая, одинаковая везде: фон `#F4F4F3`, карточка `#FFFFFF`, текст и графитовая кнопка `#141414`, вторичный `#6F6F6D`, линии `#E0E0DE`. Ни одного цветного значения.

**Коллекция** — два токена, подставляются на страницах коллекций, сетов и карточках товара: акцент (кнопка, активный чип, круглые стрелки) и подложка фото. Значения по десяти стилям 25–26 — в `design_system.md`.

Характер несут свет, сериф, капслок-микроподписи и скругление 24px — не оттенок. Именно поэтому одна оболочка держит все стили.

История правок, чтобы не повторять: первая версия была нейтрально-серой и получила «скучно, как миллион других»; вторая ушла в тёплый алебастр с бронзой и получила «это палитра одной коллекции». Рабочий ответ — характер через свет и типографику, цвет через токены.

## Порядок работы

1. Прочитать гайд и ТЗ, если они в задаче упомянуты.
2. Если направление не задано — сгенерить хиро в 3–4 разных ДНК и дать выбрать глазами, а не словами. Описания вариантов словами работают плохо.
3. Зафиксировать хвост, прогнать все экраны одной пачкой.
4. Отсмотреть сеткой, перегенерить провальные с уточнённой головой и другим seed. Норма — 2–4 экрана из 11 с первого раза мимо.
5. Скачать PNG (нужно разрешение пользователя), разложить по папке.
6. Обновить `DESIGN_SYSTEM.md` и собрать галерею-артефакт: HTML с картинками, вшитыми в base64 через PowerShell — иначе пользователь их не увидит, скриншоты вкладки в чат не долетают.

Сборка галереи: шаблон с плейсхолдерами `{{IMG_N}}` → PowerShell читает PNG, `[Convert]::ToBase64String`, замена в тексте, запись UTF-8 без BOM. 16 картинок дают ~12 МБ, лимит артефакта 16 МБ.

## Экраны

Базовый набор: хиро, свотчи стилей, каталог с фильтрами, карточка товара, категория в едином стиле (тип 2), комнатный сет (тип 1), мини-сет (тип 3), страница стиля, корзина, чекаут, 404, мобильная главная, мобильная карточка.

Не покрыто и стоит добавить при следующем заходе: раздел «Сеты и коллекции» с фильтром, пустые состояния (пустая корзина, ноль результатов фильтра), футер.
