# Оценка скилла (как текста)

Главная формула: **ценность скилла = то, чего Claude не знает сам − то, что он знает и так.**
Скилл — не учебник. Абзац «что такое PDF» только тратит лимит; абзац «этот шаг делать ДО того, а не после, потому что …» — ценен.

## Три вида абзацев (пометить каждый раздел)
- **Своё знание** — Claude этого не знает (её правила, её данные, порядок шагов, ловушки этого ПК). Оставить.
- **Напоминание** — знает, но может не вспомнить. Оставить, если коротко.
- **Лишнее** — точно знает (основы, общие слова «пиши чисто», «учти ошибки»). Удалить.

## 8 мерок (100 баллов)
| Мерка | Баллы | Что смотрим |
|---|---|---|
| 1. Своё знание, а не общеизвестное | 20 | доля «своего» в тексте; красный флаг — «что такое X», «как писать цикл» |
| 2. Как думать + шаги, которых Claude не знает | 15 | вопросы «перед действием спроси себя…» и порядок шагов, не очевидный без подсказки |
| 3. Список «НЕ делать» с причиной | 15 | конкретные запреты и ПОЧЕМУ; «будь осторожен» не считается |
| 4. Описание (первая строка) | 15 | сказано ЧТО делает, КОГДА включать, какие ФРАЗЫ вызывают; нет «когда включать» — скилл не сработает |
| 5. Не раздут | 10 | главное в SKILL.md, редкое — в `references/`; в тексте есть указатели «когда открыть файл» |
| 6. Свобода по месту | 10 | хрупкое (удаление, отправка, деньги) — жёсткие шаги; творческое — подсказки, не рельсы |
| 7. Узнаваемый образец | 5 | знакомая форма: порядок шагов / проверочный лист / примеры «вход → выход» |
| 8. Можно применить сразу | 10 | пути, команды, файлы существуют; нет «см. выше» в никуда; нет противоречий с CLAUDE.md |

Оценка: 90+ — отлично, 80–89 — хорошо, 70–79 — терпимо, 60–69 — слабо, ниже — переписать.

## Порядок
1. Прочитать SKILL.md целиком и, по указателям, нужные файлы `references/` (не все подряд).
2. Пометить абзацы: своё / напоминание / лишнее. Посчитать долю.
3. Проверить, что пути и команды существуют (`ls`, `--help`) — «не проверила» писать прямо.
4. Безопасность: нет ли хуков, скачивания и выполнения, ключей, фраз-команд для ИИ (для чужих — сначала `skan_karantin.py`).
5. Описание: проверить, включился бы скилл на её живую фразу (взять 3 реальных её просьбы, угадать, подойдёт ли описание).
6. Отчёт: оценка по 8 меркам, итог, ТРИ главные правки по убыванию пользы. Правки не вносить — это отдельный шаг (`uluchshit-skill`).

## Чего не делаем
- Не хвалим за длину и красоту формата: длинный скилл с долей «лишнего» > 50% — слабый.
- Не снижаем балл за то, что скилл «короткий», если он весь «своё знание».
- Не правим оцениваемый файл. Оценку не отдаём без строки «что осталось непроверенным».
- Свою же оценку проверяет не автор: для важного — отдать `proverka` («совпало N из M»).
