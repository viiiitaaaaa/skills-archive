# Мукминов, «Claude Code: Полное руководство» — рабочий скилл «как делать»

Источник правды: текст книги (`knigi_kupleno\chunks_vse\Claude_Code_Полное_pdf_01..06.txt`). Книга написана для программистов; здесь — только то, что годится новичку без кода. Адреса — «стр. N» книги. Главы подробно — `references\glavy.md`.
Что такое «токен» — кусочек текста, которым считается и память модели, и стоимость (стр. 14–15, 247). «Контекст» — всё, что Claude Code сейчас «держит в голове» в этом диалоге (стр. 38).

## Что делать, если…

1. **Нужно дать большую задачу.** Не просить «сделай всё». Шаги: (1) описать проект словами, не кодом; (2) попросить предложить план/архитектуру и согласовать; (3) делать по одной части за раз; (4) после каждой — запуск и проверка. Зачем: чем больше задача, тем хуже каждая часть (стр. 80–81, 228, 229).
2. **Запрос получается мимо.** Писать в три блока: «Контекст → Задача → Ограничения» (что есть, что нужно, что нельзя менять). Добавить пример ожидаемого результата, при желании роль («выступи как…») (стр. 46, 66–67). Плохо: «сделай логин»; хорошо: что за страница, какие поля, что при ошибке, что не трогать (стр. 65–66).
3. **Хочу сначала увидеть план, ничего не меняя.** Написать: «покажи, как ты собираешься изменить X, но пока не меняй файлы» (стр. 46). Для сложного — «подумай внимательно и составь детальный план» (стр. 58). Для обсуждения без правок — «НЕ пиши код, обсудим» (стр. 230).
4. **Claude «запутался», забыл раннее, повторяет ошибки.** Это переполнение контекста. Шаги: `/compact` (сжать историю, можно с фокусом: «/compact сфокусируйся на …»), а если тема другая — `/clear` и новый диалог. Смотреть заполнение командой `/status`; при 70–80% — оптимизировать (стр. 36–39, 232).
5. **Хочу экономить деньги/лимит.** Шаги: (1) начинать с Sonnet, Opus — только на трудное, Haiku — на простое и массовое (`/model`) (стр. 31, 58–60); (2) просить конкретные файлы, не «весь проект» (стр. 38); (3) `/compact` после крупного блока; (4) не менять CLAUDE.md и не делать `/clear` без нужды — это сбрасывает кэш (стр. 62); (5) `/cost` — смотреть расход (стр. 36, 32).
6. **Не хочу объяснять одно и то же каждый раз.** Завести файл `CLAUDE.md` в корне проекта: описание, стек, структура, команды запуска/тестов, правила, «чего НЕ делать». Он читается автоматически в начале каждой сессии. Шаблоны — стр. 70–72, 243–246. Можно вложенные CLAUDE.md в подпапках: они дополняют, не заменяют (стр. 73).
7. **Хочу продолжить вчерашнюю работу.** `claude --continue` (или `-c`) — последний диалог; `claude --resume` — выбрать из списка. Один диалог — одна задача; перед сохранением длинного — `/compact` (стр. 34, 47). У Claude Code нет памяти между сессиями кроме CLAUDE.md и настроек (стр. 62).
8. **Он просит «Allow? [Y/n/always]».** Y/Enter — разрешить один раз; n — отказать; always — запомнить для этого типа команд. Безопасное чтение идёт без вопросов, удаление/sudo/`curl | bash` — всегда спрашивает (стр. 35, 43, 55–56). Настроить заранее — `/permissions` (стр. 29, 36, 241) или `.claude/settings.json` с `allow`/`deny` (стр. 55).
9. **Хочу запретить опасное.** В `.claude/settings.json` в `deny` вписать, например, запись в `.env`, `rm -rf`, `sudo` (стр. 24, 55). Ключи/пароли — только в переменных окружения и `.env` в `.gitignore`, не в запросах (стр. 21, 56, 180, 235).
10. **Одна и та же инструкция в каждом запросе.** Сделать свою команду: файл `.claude/commands/<имя>.md` с текстом и `$ARGUMENTS`; вызов — `/project:<имя> аргумент`. Личные — в `~/.claude/commands/`, вызов `/user:<имя>` (стр. 63, 78–79, 164–165, 241). Примеры: «утренний ритуал», «проверка готовности к деплою» (стр. 165).
11. **Хочу, чтобы что-то происходило автоматически (формат файла после записи, уведомление).** Hooks (крючки) — команда, срабатывающая до/после действия Claude. Настройка в `settings.json`, разделы PreToolUse / PostToolUse / Notification (стр. 165–167). Предупреждение: в книге на стр. 63–64 написано иначе (`preToolUse`), синтаксис в книге не единый — сверять с официальной справкой.
12. **Хочу подключить внешний сервис (БД, GitHub, Slack, браузер).** Это MCP — «магазин приложений» для Claude Code. Шаги: вписать сервер в `mcpServers` в settings.json; проверить запросом «какие MCP-серверы подключены, покажи инструменты»; давать минимум прав (например, пользователь БД только на чтение), токены — в переменных окружения (стр. 155–157, 162–163).
13. **Нужно запускать Claude Code из скрипта/по расписанию.** Режим headless: `claude -p "запрос"` (то же, что `--print`), вывод `--output-format json`, предел шагов `--max-turns N`; данные можно подать через конвейер: `cat error.log | claude -p "найди причину"` (стр. 33–34, 168, 241–242). В CI ключ — в секретах (стр. 169).
14. **Ошибка в программе, не пойму почему.** Дать: текст ошибки/лог целиком, файл, шаги воспроизведения, ожидаемое и фактическое, «что уже пробовал». Цикл: описание → гипотеза → проверка → исправление. Потом попросить регрессионный тест (стр. 68, 105, 114).
15. **Одна ошибка не лечится с 5-й попытки.** Остановиться: это антипаттерн «бесконечные исправления» (стр. 74). Дать больше контекста, начать новый диалог, попросить альтернативные объяснения причины; ограничитель шагов `maxTurns` защищает от зацикливания (стр. 58).
16. **Хочу, чтобы он сам себя проверил.** После работы: «проведи code review кода, который ты только что написал, найди проблемы» (приём «Критик», стр. 75); «исправь и запусти тесты» (стр. 46); сравнить два варианта (стр. 75).
17. **Работа с чужим/старым кодом.** Сначала обзор («что это, стек, как устроено, есть ли тесты»), потом модуль, потом карта зависимостей. Менять поэтапно, приложение после каждого шага должно работать; перед переделкой — тесты, фиксирующие текущее поведение (стр. 93, 103–104, 223–226).
18. **Он выдал несуществующую функцию/пакет.** Это «галлюцинация». Признаки: функции нет в документации, пакета нет в каталоге, решение «слишком удобное». Шаги: спросить «ты уверен, что она существует?», сверить с официальной документацией, запустить код/тесты, указать версии в запросе (стр. 15, 233, 92, 234).
19. **Работа с картинками/скриншотами.** Можно передать макет, скриншот ошибки, схему и попросить сделать по ним (стр. 45).
20. **Установка и неполадки.** Пакет `@anthropic-ai/claude-code` через npm, проверка `claude --version`; «command not found» — проверить PATH; 401 — проверить ключ, `claude logout` / `claude login`; «rate limit» — подождать, `/compact`, разбить задачу (стр. 19, 30). Подробности и оговорки — раздел «Не проверено».

## Ошибки новичка (из книги)

- «Рыхлый» запрос («сделай что-нибудь, он медленный») (стр. 73).
- Микроменеджмент: диктовать строку и замену вместо цели (стр. 73).
- «Вся кодовая база за раз» — вместо конкретной папки/вопроса (стр. 73).
- Слепое доверие: скопировал и выложил, не проверив — отвечаешь за результат ты (стр. 73, 229, 235).
- Бесконечные исправления одной ошибки (стр. 74).
- Переключение темы в одном диалоге («ещё поправь стили, и давай на TypeScript») (стр. 74).
- Контекстная амнезия: диалог на 100+ сообщений без `/compact` (стр. 229).
- «Сделай всё»: огромная задача одним запросом (стр. 229).
- Вставлять в запрос реальные ключи/пароли (стр. 180, 235).
- Забыть, что результат — черновик, а не готовый продукт (стр. 15).
- Не указывать версии библиотек — получить устаревший код (стр. 92, 234).
- Автоматизировать разрушительное (удаление, force push) без защиты (стр. 235).

## Что не проверено / в книге нет

- В источнике нет: цены в рублях и актуальные тарифы подписок; книга говорит про оплату по токенам API и «10–50 долларов в месяц» (стр. 32) — как это соотносится с твоим планом, в книге нет.
- В источнике нет: работы Claude Code на Windows без WSL2 (книга утверждает «официально только через WSL2», стр. 20). У тебя Claude Code уже работает — не сверено, насколько это утверждение устарело.
- Команды в книге местами искажены при переводе из PDF: двойной дефис выглядит как длинное тире («–version» вместо «--version»). Реальный флаг — с двумя дефисами; сверять на своей системе.
- Названия настроек (`autoApprove`, `defaultModel`, `maxTurns`) и формат hooks в разных местах книги расходятся (стр. 24–25, 63–64, 165–166) — не проверено по официальной документации.
- Книга внутренне противоречива: предисловие обещает проекты «мобильное приложение, Data Pipeline, микросервисы» (стр. 6), а в Части IV другие шесть (SaaS, API маркетплейса, Telegram-бот, CLI на Go, Chrome-расширение, миграция) (стр. 199–226). Оценка токенов: «1000 строк = 10–20 тыс.» (стр. 38) против «4000» (стр. 232).
- Раздел 4.4 называет цикл «AGI (Act-Grounded-Iterate)», а описывает Think–Act–Observe–Iterate (стр. 57) — название сомнительно, смысл (думает → действует → смотрит → повторяет) понятен.
- В источнике нет: Skills (скиллы), субагенты, plan mode как отдельный режим, Hermes, работа с Google Диском/Excel/Word. Скиллы Claude Code в этой книге не описаны.
- Главы 15–24 (DevOps, языки, проекты) написаны для программистов; для тебя практически не нужны, кроме общих приёмов.
