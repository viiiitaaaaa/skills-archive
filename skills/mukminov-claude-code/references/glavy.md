# Мукминов, «Claude Code: Полное руководство» — по главам (простыми словами, со стр.)

Пометка: «токен» — кусочек текста, по которому считаются память модели и цена. «Контекст» — всё, что модель сейчас «держит в голове». «Промпт» — твой запрос.

## Предисловие (стр. 5–6)
- Книга называет Claude Code «напарником», а не просто подсказчиком кода. Адресована программистам, тимлидам, менеджерам.
- Пять частей: основы, практика, продвинутое, проекты, лучшие практики. Советует держать терминал и пробовать на практике.

## Часть I. Основы
**Гл. 1. Что такое Claude Code (стр. 7–17).** История Anthropic и моделей Claude (Haiku/Sonnet/Opus). Claude Code — «агентный» инструмент: читает файлы, пишет, запускает команды, а не только подсказывает. Сравнение с Copilot, Cursor, Q Developer, Gemini Code Assist (кто что умеет). Философия «человек в цикле»: он просит подтверждение, объясняет шаги, ты руководишь. Сценарии: прототип, рефакторинг, отладка, тесты, документация, DevOps, обучение. Ограничения (стр. 14–15): конечное окно контекста, галлюцинации (уверенные ошибки), стоимость, устаревшие знания, слабее на редких языках.

**Гл. 2. Установка и настройка (стр. 18–32).** Требования: Node.js 18+, npm, git; Windows — через WSL2 (по книге). Установка: `npm install -g @anthropic-ai/claude-code`, проверка `claude --version`. Вход: через браузер, через API-ключ в переменной окружения, через AWS Bedrock или Google Vertex. Ключи не хранить в файлах, попадающих в Git. Настройки по уровням: командная строка выше переменных, выше проекта, выше пользователя. Файл CLAUDE.md и папка `.claude/` (settings.json, commands/). Интеграции с VS Code, JetBrains, Vim, Emacs. Типичные ошибки установки (command not found, EACCES, 401, rate limit, прокси/VPN, WSL). Экономия: `/compact`, Sonnet по умолчанию, конкретные запросы, CLAUDE.md, дробить задачи, `/cost`. Бюджет по книге: 10–50 долларов в месяц обычно (стр. 32).

**Гл. 3. Первые шаги (стр. 33–48).** Режимы: интерактивный, `--print`/`-p` (один запрос), `--continue`/`--resume`, конвейер (`cat файл | claude -p …`). Пять фаз диалога: запрос → план → инструменты → подтверждение → итог. Слэш-команды: /help, /clear, /compact, /status, /cost, /model, /permissions, /config. Горячие клавиши. Управление контекстом (~200 тыс. токенов): быть избирательной, регулярно сжимать, дробить, использовать CLAUDE.md, следить за % заполнения. Первый проект (менеджер заметок) итерациями. Работа с файлами и терминалом, система безопасности команд. Картинки как вход. Паттерны запросов: «Контекст–Задача–Ограничения», «Обзор–Детализация–Реализация», «Покажи перед изменением», «Исправь и проверь», «Объясни как учителю». Сессии. Упражнение «Книжная полка» из 8 запросов.

**Гл. 4. Архитектура (стр. 50–64).** Как он понимает проект: метаданные → структура папок → выборочное чтение («ленивая загрузка») → смысл кода. Инструменты: чтение, запись, точечная правка, Bash, поиск, веб, MCP. Он сам выстраивает цепочки действий. Разрешения в четыре уровня (встроенные запреты модели, категории, настройки allow/deny, живое подтверждение). Журнал действий, откат через Git. Секреты: в переменные окружения, `.env` в `.gitignore`, запрет записи в `.env`. Агентный цикл «думать–действовать–смотреть–повторять»; предел шагов `maxTurns`; «подумай внимательно» включает расширенное планирование. Модели: Opus (сложное), Sonnet (повседневное, по умолчанию), Haiku (простое и массовое). Структура контекста и приоритеты; кэширование запросов (не менять CLAUDE.md зря, не делать /clear без нужды, `/compact` вместо `/clear`). Границы: нет памяти между сессиями, нет фона, нет GUI, таймауты, не заменяет тесты и аудит безопасности. Расширяемость: свои команды, hooks, MCP.

**Гл. 5. Общение с ассистентом (стр. 65–79).** Три уровня запросов: наивный, структурированный, экспертный. Принципы: конкретность, контекст (не перегружать), разделение на этапы, примеры, роль. Шаблоны запросов для генерации, отладки, рефакторинга, ревью, документации. CLAUDE.md — «память проекта»: структура, длинный пример, иерархия по папкам. Шесть антипаттернов (рыхлый запрос, микроменеджмент, весь проект сразу, слепое доверие, бесконечные исправления, смена темы). Итерации: «Да, но», «Расширение горизонта», «Критик», «Сравнение». Продвинутые: пошаговое рассуждение, примеры формата (few-shot), запреты («НЕ используй…»), условия. Большие проекты: «Фокусная линза», «Проводник», «Карта зависимостей». Русский язык понимает хорошо; имена в коде лучше по-английски. Свои шаблоны-команды (component, fix-bug, review).

## Часть II. Практика
**Гл. 6. Написание кода с нуля (стр. 80–92).** Метод из пяти этапов: описание → архитектура → каркас → реализация → интеграция и тест. Примеры запросов на React, Next.js, Vue, FastAPI, Express, Go, Django, NestJS, Flask, Spring Boot (для программистов). Спецификация API без реализации; схема GraphQL. Паттерны: «слой за слоем», «сначала тесты» (TDD), «скопируй стиль» существующего модуля, «прототип → продакшен». Генерация конфигов (TypeScript, ESLint, Docker, CI). Ошибки: устаревшие API (указывай версии), лишний код (просить минимализм), «дрейф» стиля, забытые граничные случаи (перечислять их).

**Гл. 7. Рефакторинг (стр. 93–104).** Первый контакт с чужим кодом: обзор, модуль, зависимости, поиск «скелетов» (TODO, мёртвый код, дубли). «Запахи кода» (слишком большие классы/функции и т.п.) и аудит. Переименование, вынос функций/классов. Модернизация старого кода, переход JS→TS, обновление зависимостей. Ускорение (SQL, бэкенд, фронтенд). Разделение «монолита» на модули. Аудит обработки ошибок. Практический кейс: разбить файл на 1200 строк по шагам, после каждого — проверка («рефакторинг как миграция»).

**Гл. 8. Отладка (стр. 105–115).** Отладка = расследование: описание → гипотеза → проверка → исправление. Claude анализирует код статически, отладчиком шаг за шагом не ходит. Разбор stack trace (Python, Node). Типовые баги: двойное списание, утечки памяти, гонки (race condition), забытый `await`, необработанные промисы, взаимные блокировки. Конфигурация: Docker, переменные окружения, CORS. Производительность: последовательные вызовы → параллельные. Стратегии: бинарный поиск по коммитам (`git bisect`), «резиновый утёнок», воспроизведение. Кейсы: «призрачные данные» (общий кэш без учёта пользователя), периодические таймауты, редкая ошибка NaN. Скрипт диагностики и регрессионные тесты.

**Гл. 9. Тесты (стр. 116–127).** Тесты — страховка; Claude хорошо знает граничные случаи. Виды: unit, интеграционные, E2E. Примеры для Vitest, supertest, Playwright, pytest. TDD: Red → Green → Refactor (сначала только тест, потом код). BDD (Gherkin). Покрытие кода, mutation testing, тестовые данные (фабрики), snapshot-тесты.

**Гл. 10. Базы данных (стр. 129–137).** От требований к схеме SQL и Prisma. ORM: Prisma, SQLAlchemy, TypeORM. Оптимизация запросов (индексы, N+1, партицирование). Миграции, в том числе данных (с таблицей для невалидных записей). Redis и кэш, MongoDB, безопасность БД (параметризованные запросы, права, шифрование).

**Гл. 11. Документирование (стр. 138–146).** Хорошая документация объясняет «почему» и «как», а не «что». JSDoc/docstring, README, OpenAPI/AsyncAPI, ADR (запись архитектурных решений), CHANGELOG из git, диаграммы Mermaid, комментарии про бизнес-логику (не «увеличиваем счётчик»), автопроверка актуальности документации.

**Гл. 12. Git и совместная работа (стр. 147–154).** Коммиты по формату conventional commits, разбивка изменений на несколько коммитов, отмена. Разбор конфликтов слияния с объяснением каждого решения. Описание и ревью pull request. История: rebase, blame, cherry-pick. GitFlow и trunk-based, git-хуки (Husky). Monorepo, submodules. Что делать, если закоммитила секрет: убрать из истории и обязательно отозвать ключ (стр. 152). Правила для команды: AI-код проходит тот же ревью, покрытие 80%, не больше ~200 строк за раз, единый CLAUDE.md (стр. 153).

## Часть III. Продвинутое
**Гл. 13. MCP (стр. 155–163).** MCP — открытый стандарт подключения внешних инструментов («магазин приложений» для Claude Code). Сервер даёт инструменты, ресурсы, шаблоны. Настройка в settings.json (`mcpServers`). Популярные: PostgreSQL, GitHub, Slack, Sentry, браузер Puppeteer. Свой MCP-сервер (пример на TypeScript). Паттерны: мост к внутренним системам, агрегатор, автоматизация. Безопасность: минимум прав, отдельный процесс, токены в окружении, аудит, блок разрушительного, пользователь БД только на чтение.

**Гл. 14. Автоматизация (стр. 164–171).** Свои команды (проектные и личные), примеры «утро», «готов ли к деплою», ревью PR. Hooks на события (PreToolUse, PostToolUse, Notification): автоформат, проверка команд, уведомления. Headless-режим `-p` и SDK для программ. CI/CD: ревью PR и changelog через GitHub Actions. Скрипты: обновление зависимостей с откатом при падении тестов, аудит безопасности, задачи по расписанию (cron).

**Гл. 15. DevOps (стр. 173–179).** Docker (многоступенчатая сборка, непривилегированный пользователь), Compose, Kubernetes, Terraform, CI/CD, мониторинг (Prometheus/Grafana), логи, Nginx, скрипты деплоя и бэкапов (ежедневно, ротация, проверка восстановления). Для программистов/админов.

**Гл. 16. Безопасность (стр. 180–185).** Защита данных: по книге Claude Code маскирует похожие на секреты строки и спрашивает разрешение на действия (стр. 180) — не проверено; всё равно не вставлять реальные секреты. Аудит кода: SQL-инъекции, XSS, инъекции команд, слабая аутентификация, конфигурация, зависимости. Пароли (bcrypt), токены с коротким сроком, роли (RBAC), OAuth, лимиты запросов, валидация, заголовки безопасности, шифрование, CSRF/CORS, проверка пакетов, журнал событий безопасности, предрелизный чек-лист.

**Гл. 17. Разные языки (стр. 187–193).** Claude знает идиоматику многих языков (Python, Go, Rust, TypeScript, C#); может переводить код с языка на язык «по-местному», а не «Python на Go». Примеры запросов, в том числе анализ данных и асинхронный сборщик страниц на Python (стр. 187–188).

**Гл. 18. Предметные области (стр. 194–198).** Мобильные приложения (но эмулятор он запустить не может), анализ данных и ML, реальное время (WebSocket), блокчейн, IoT (MQTT), простая игра на Canvas, анализ текста, финтех-скоринг. Примеры запросов.

## Часть IV. Проекты (стр. 199–226)
**Гл. 19.** SaaS «TaskFlow» (Next.js, Prisma, NextAuth, Pusher, Vercel): постановка → стек → каркас → модели → вход → доска → реал-тайм → деплой. Уроки (стр. 202): план перед кодом («расскажи, что собираешься делать»), по одной фиче, типы, тесты на каждом шаге, проверка каждого файла.
**Гл. 20.** REST API маркетплейса: архитектура, модели, корзина/заказы/платежи (Stripe), поиск, тесты, масштабирование.
**Гл. 21.** Telegram-бот на Python (aiogram): учёт расходов «500 кофе», автокатегории, бюджеты, графики, деплой. Ближе всего к твоим ботам.
**Гл. 22.** CLI-утилита на Go (cobra): init, env, health, deploy, сборка под разные системы.
**Гл. 23.** Chrome-расширение (Manifest V3): закладки и сниппеты, хранилище, экспорт в GitHub Gist, тесты.
**Гл. 24.** Миграция старого приложения: исследование → тесты, фиксирующие текущее поведение → перенос данных → поэтапный перенос кода («Удушающее дерево»: старое и новое работают рядом, маршруты переключаются по одному) → проверка. Уроки (стр. 226): тесты до миграции, поэтапно, данные отдельно, не улучшать при переносе, план отката.

## Часть V. Практики и будущее
**Гл. 25. Лучшие практики (стр. 227–231).** Пять правил: контекст — всё (что, где, зачем); CLAUDE.md — стратегический актив (с блоком «определение готово»); маленькие шаги; всегда проверять; итерации. Антипаттерны: «сделай всё», слепое доверие, «промпт вместо навыков» (инструмент умножает твои навыки), контекстная амнезия. Режимы общения: Архитектор, Наставник, Pair Programmer, Ревьюер. Команда: единый CLAUDE.md, общие команды, AI-код проходит то же ревью, автор отвечает за него.

**Гл. 26. Ограничения (стр. 232–236).** Контекстное окно (симптомы: забывает правила, повторяет ошибки; решения: `/compact`, новые сессии, CLAUDE.md). Галлюцинации (как распознать и проверить). Слабые места: новые технологии, малые фреймворки, закрытые системы (1С, Битрикс), дата среза знаний — указывай версии. Большие проекты. Безопасность: не вставлять секреты. Когда лучше другой инструмент (дизайн, сеть, профилирование, бизнес-решения, финальная проверка безопасности). Ответственность за код на тебе.

**Гл. 27. Будущее (стр. 237–240).** От ассистента к агенту, мультимодальность, долгая память. Какие навыки будут ценны: архитектура, чёткие требования, ревью, тестирование, безопасность, понимание предметной области. Советы: фундамент знаний, понимание ИИ, свои инструменты, следить за новостями, пробовать новое. Главный вывод: Claude Code умножает твои навыки.
