## Мукминов «Claude Code» (10)


### Новости, данные, Claude Code

- **Разовый запуск с ограничениями: только чтение и потолок шагов.** Для `claude -p` по логам и таблицам добавлять ограничение инструментов (в книге `--allowedTools`) и лимит шагов (`--max-turns`): например «только Read, не больше 5 шагов». Тогда разовый запуск ничего не изменит и не уйдёт в долгий цикл. Флаги сверить с `claude --help`. (прил. А, стр. 241–242; стр. 168) (дополняет 1-й №13) → `claude-code-priemy`
- **Чек-лист чтения чужого репозитория перед установкой.** Пять вопросов: что делает; на чём написан; как разложен; какие модули и как связаны; есть ли документация и тесты. И «скелеты»: TODO/FIXME, закомментированный код, неиспользуемые импорты, дубли, файлы без тестов, вписанные прямо в код адреса и ключи. Применять к плагинам и скиллам-кандидатам вместе с нашим правилом «ставить после чтения кода». (стр. 93–94) → `claude-code-priemy`
- **Команда «новый сборщик» — скелет с нашими обязательными частями.** По образцу команды `new-feature` из книги: папка; `CLAUDE.md` на 4 раздела (dop №57); `.env.example` (dop №48); `diagnose.py` (1-й №7); логи через `log_setup.py`; файл прогресса «N из M»; первый коммит. Зачем: каждый новый сборщик сразу со всеми «предохранителями». (стр. 164) → `claude-code-priemy`, `knowledge-library`
- **«Claude не отвечает» — три проверки до смены сервера Happ.** 1) статус-страница Anthropic (status.anthropic.com) — может, сбой у них; 2) `nslookup api.anthropic.com` — работает ли DNS; 3) прокси и VPN. Сервер не переключать в середине работы (правило против бана в `claude-code-priemy`). (стр. 22, 31) → `claude-code-priemy`
- **Незнакомая поломка — вопрос из трёх частей.** «Какие команды выполнить для диагностики? Какие типичные причины? Как исправить?» Пример из книги — Kubernetes. У нас: принтер, Happ, Dolphin, бот. Ответ — план, а не догадка. (стр. 175) → `claude-code-priemy`, `pc-check`
- **Статус всех веток — до любого действия с репозиторием.** Если ветки разошлись (как dev в artmellio-system): сначала «покажи статус каждой ветки: впереди/позади удалённой, вмержена ли», потом решать. Никаких команд «на удачу». (стр. 152) → `claude-code-priemy`
- **Утренняя сводка по своим проектам — вручную, по команде.** По образцу «утреннего ритуала»: что изменилось в `claude-skills` за сутки; есть ли ошибки в последних логах сборщиков; какие задачи открыты в чек-листах `[>]`. Это команда по её слову, не расписание. (стр. 165) (дополняет dop №34) → `claude-code-priemy`
- **Журнал технических отказов с датой — перепроверять раз в месяц.** Только технические блоки (капча при создании Reddit-приложения, «команда не найдена в этой версии», сайт не открывается), а не её решения. Раз в месяц: «что из журнала уже заработало?». (стр. 240) → `claude-code-priemy`
- **README для своих репозиториев — короткий состав.** Для `case-bot`, `disk-hygiene`, `claude-skills`: что это (1–2 строки); быстрый старт в 3–5 шагов; требования; основные команды; структура папок; откуда берутся ключи (`.env.example`). Без значков и «как участвовать». (стр. 139–140) → `claude-code-priemy`
- **Удобные сокращения запуска в PowerShell.** По образцу алиасов книги (`cc`, `ccc` = продолжить, `ccr` = выбрать сессию) завести функции в профиле PowerShell, например `function ccc { claude -c }`. Делать только по её слову. (стр. 28) → `claude-code-priemy`

## Котлер «Marketing 4.0» (2)


### Новости, данные, Claude Code

- **Эмпатическое исследование → субагенты с разными ролями.** В эмпатическом исследовании каждый участник смотрит со своей профессиональной стороны (психолог, дизайнер, инженер, маркетолог) и находит своё, а потом общий мозговой штурм собирает выводы. (гл. 8, стр. 163–164) → claude-code-priemy, kursy-konspekty
- **Автоматизировать слушание, но не ответ.** Книга: социальный CRM «почти не автоматизируется», а машины нужны для продуктивности, люди — для вовлечения. Правило для нас: Claude собирает, фильтрует и пишет черновики ответов клиентам; отправляет и отвечает на жалобу живой человек. Когда: при любой автоматизации поддержки или бота. (гл. 4, стр. 71; гл. 11, стр. 223, 226) → claude-code-priemy, dropship-lessons

## Dickey «Mastering Claude AI» (6)


### Тренд-радар и отбор 1688

- **Проверка сборщика на крайние случаи.** Для скриптов 1688, радара и новостей просить проверку: «что будет при пустой выдаче, 0 продаж, капче, обрыве сети, пустом списке?». Это вопрос из ревью кода в книге: «а если список пуст?». Зачем: сборщик не должен молча записывать нули как настоящие данные. (гл. 7, стр. 111, 119) → sourcing-1688, tg-news, claude-code-priemy

### Новости, данные, Claude Code

- **Своя экспертиза вместо роли модели.** Вместо «ты эксперт по …» писать «учитывая мой опыт в [монтаже и осушении бассейнов / отборе на 1688], помоги разобрать [вопрос], опираясь на [наши объекты / наши выгрузки]». Совпадает с её правилом «без „ты эксперт“»: контекст задаёт её знание, а не придуманная роль. В глоссарии книги «экспертиза» Claude — это имитация по шаблонам, а не опыт (стр. 337). (гл. 19, стр. 313) → claude-code-priemy
- **Чек-лист перед подключением нового сервиса.** Перед тем как встроить новый API (Trends MCP, новый актор Apify, treg) пройти 9 пунктов из книги: стабильный доступ (в том числе через Happ); резервная копия данных; ручной запасной путь; какие данные туда уходят (🟢/🟡/🔴); учёт версий; совместимость форматов; кто имеет доступ к ключу; учёт трат и лимитов; совместимость с нашими скриптами. Полный список — в «Моделях». (гл. 12, стр. 204–205) → claude-code-priemy, trend-radar
- **Квота необычных идей.** В любом запросе на идеи писать: «10 вариантов, из них минимум 3 необычных». Без квоты модель выдаёт десять вариаций одной очевидной идеи. Отличается от «5 направлений» (dop №3) тем, что работает одной строкой. (прил. A, стр. 346) → dropship-lessons, claude-code-priemy
- **Запас времени в важных процессах + «кажется сложным — значит, сложно».** Из принципов построения процесса: (а) в процессах со сроком (подача в суд, ответ поставщику, сбор перед решением) закладывать запас на случай, когда Claude или API тормозит или упирается в лимит, и держать ручной путь; (б) процесс начинать с 3–5 шагов, а если схема «кажется сложной, то она и есть сложная», и её надо резать. Зачем: срок не должен зависеть от того, работает ли сегодня сервис. (гл. 12, стр. 207) → claude-code-priemy, dela
- **Просить простое объяснение простыми словами.** Чтобы получить объяснение «как новичку», сам вопрос писать коротко и без терминов. Если вставить сложный текст и приписать «объясни просто», ответ всё равно выйдет сложным (тезис №13). Совпадает с её правилом «объяснять как новичку». Для субагентов: в задании для «объясни ей» давать образец простой фразы, а не только требование. (гл. 3, стр. 28) → claude-code-priemy

## Fraser «SaaS Marketing Playbook» (2)


### Новости, данные, Claude Code

- **Балл лида от Claude.** Как замену «ИИ-оценке лидов» (Einstein): Claude по досье lead-engine ставит балл 1–5 по согласованным критериям (тип объекта, стадия, бюджет, триггер) с одной строкой «почему»; лиды с баллом ≥4 — менеджеру сразу. Только по нашим собранным данным, без отправки персональных данных наружу (🟡). (When to send leads) → b2b-sbor, claude-code-priemy
