## Gulli «Agentic Design Patterns» (12)


### Новости, данные, Claude Code и агенты

- **Право агента «поторговаться» до старта.** В задании субагенту разрешать вернуть вопрос/препятствие до работы («источник X недоступен — заменить на Y?»), а не молча делать по-своему. Зачем — дешевле, чем переделка. (гл. 19, стр. 318) → claude-code-priemy
- **Субподряды.** Большую задачу главный агент делит на «субконтракты» с собственными критериями приёмки для каждого субагента (как здесь: Hermes — пересказ, я — проверка и приёмы). (гл. 19, стр. 320) → claude-code-priemy
- **Лимит кругов в любом цикле.** Любой наш цикл «сделай → проверь → исправь» (сборщики, правки сайта, Hermes) — с потолком итераций (книга: 3, 5, 10) и выходом «не получилось — сообщить». (гл. 4, стр. 71; гл. 7, стр. 123; гл. 11, стр. 192) → claude-code-priemy
- **Контекст для субагента — короткий и отобранный.** Не передавать субагенту весь разговор, а «упаковать» только нужное: цель, пути файлов, её правила по теме, формат ответа (пример с кофейней: в поиск — только список улиц). (стр. 17) → claude-code-priemy
- **Рефлексия над процедурной памятью — по её подтверждению.** После длинной сессии просить агента предложить правки в инструкции скилла по итогам ошибок (как «update_instructions»), но вносить только после её «да» (решённое не пересматривать). (гл. 8, стр. 147) → claude-code-priemy
- **Сжатие старого контекста.** Длинные сессии: держать в окне главное, старое — резюме в файл; это и есть «управление краткой памятью». Связано с её правилом «перезапусти перед большой задачей». (гл. 8, стр. 132) → claude-code-priemy
- **Учёт токенов на вызов.** В скриптах, зовущих модели (Hermes, разборы Apify), считать токены входа/выхода и писать в журнал — видно, что съедает лимит. (гл. 19, стр. 309) → claude-code-priemy
- **Контрольные точки и откат.** Длинные правки (сайт, таблицы, массовые изменения Shopify) делать с «коммитами» — сохранённым проверенным состоянием, к которому можно вернуться. (гл. 18, стр. 302) → claude-code-priemy
- **Ревью перед deploy: критика + рефлексия.** Роль «главный инженер»: сначала подробная критика правок, потом короткая выжимка самого важного по приоритету, мелочи отбросить. Применять к правкам сайта Frivent/скриптов перед deploy. (прил. G, стр. 412–413) → claude-code-priemy
- **Пять ролей для кода.** Для своих скриптов разделять роли: реализатор, автор тестов, документатор, оптимизатор, ревьюер — разные субагенты/промпты, а не один «сделай всё». (прил. G, стр. 412–413; гл. 11, стр. 193) → claude-code-priemy
- **Точки остановки для неё — только критические.** HITL в 4 местах: утверждение плана большой задачи, действие с деньгами/последствиями, настоящая неясность, финальная проверка перед отправкой наружу. Совпадает с её CLAUDE.md. (FAQ, стр. 480) → claude-code-priemy
- **OpenRouter — справочно.** Умеет `openrouter/auto` и список запасных моделей одним ключом — если когда-то понадобится платный доступ к разным моделям. Не ставить без её решения. (гл. 16, стр. 255–256) → claude-code-priemy

## Hur, Song «Build an AI Agent (From Scratch)» (14)


### Новости, данные, Claude Code и агенты

- **Аудит скилла/агента по 5 стратегиям контекста.** Для каждого нашего агента (tg-news, радар, бот «Дела», Hermes-пересказ): Generate (есть ли план/самопроверка?), Retrieve (подтягивает ли нужное сам?), Write (пишет ли промежуточное в файл?), Reduce (сокращает ли старое?), Isolate (вынесены ли тяжёлые подзадачи в отдельный контекст/субагента?). (гл. 1, стр. 35–36) → claude-code-priemy
- **Меньше 20 инструментов на агента.** Больше — ошибки выбора. У нас подключены сотни MCP-инструментов (Chrome, Playwright, stealth-browser, Inspo…) — агенту-исполнителю давать только нужные. Ср. Гулли №62 (`tool_filter`) — здесь число-ориентир. (гл. 3, стр. 77) → claude-code-priemy
- **Ошибки инструмента — разная реакция по коду.** В сборщиках: 401/403 — не повторять, звать её (ключ/доступ); 429 — повтор с растущей паузой; таймаут — повтор с упрощённым запросом; сетевая ≠ ошибка API. Наружу агенту — строка `Error: …`, а не падение скрипта, чтобы цикл продолжился. (гл. 3, стр. 80) → claude-code-priemy
- **Журнал событий — источник правды, модели — проекция.** В агентах/сборщиках хранить полный журнал на диске (вызовы, аргументы, результаты, статус success/error), а в модель отправлять отобранное и сжатое; журнал не правится. Ср. Гулли №56 — новое: разделение «хранение ≠ показ», от которого строятся все сжатия. (гл. 4, стр. 104; гл. 6, стр. 173–174) → claude-code-priemy
- **«Опасные действия» — список + хук до вызова.** Аналог `approval_callback`: в Claude Code PreToolUse-хук на список действий (удаление, отправка в бот от её имени, push, оплата) — спросить её, а отказ вернуть агенту текстом «пользователь отклонил», чтобы он продолжил без этого шага. Настраивать только по её команде (скилл update-config). (гл. 5, стр. 163–164) → claude-code-priemy
- **Компакция — до суммаризации.** Старые результаты чтения файлов и поиска заменять строкой-ссылкой «Содержимое файла X. Перечитай при необходимости» / «Поиск по запросу Q обработан. Повтори при необходимости». Детерминированно, бесплатно, обратимо. Пересказывать моделью — только если и после этого много. (гл. 6, стр. 178–185) → claude-code-priemy
- **Не трогать середину истории ниже порога — бережём кэш.** Кэш промптов даёт до −90 % цены по одинаковому началу; правка старого сообщения = промах кэша для всего после. Для скриптов к Claude API и сессий: чистить историю только выше порога (книга: 50 000 токенов), шапку промпта держать неизменной. (гл. 6, стр. 180–181) → claude-code-priemy
- **Шаблон «итоги сессии» — 3 пункта.** Для файлов `sessiya-*-itogi.md` и передачи работы новому агенту: (1) ключевые находки, (2) какие инструменты/скрипты использованы, (3) текущий статус — что сделано и что осталось; «кратко, только то, что поможет продолжить». (гл. 6, стр. 181–182) → claude-code-priemy
- **Диагностика зависшего агента по 4 сбоям ReAct.** Хватается за всё сразу → дать план; забыл найденное → статус в плане; рано объявил ответ → критерии завершения + самопроверка; повторяет провальное → рефлексия «почему и чем заменить». (гл. 7, стр. 221–222, 233) → claude-code-priemy
- **Код как действие для массовой работы.** Когда задача — «N похожих действий» (переименовать 200 файлов, обойти 31 страницу, посчитать по 500 строкам), просить модель написать один скрипт с циклом/условиями, а не делать N вызовов: CodeAct +20 п.п. успеха и −30 % ходов; чем сильнее модель, тем больше выигрыш. (гл. 8, стр. 240–242) → claude-code-priemy
- **Когда код НЕ нужен.** Один простой вызов или очень быстрая операция — накладные расходы скрипта/песочницы больше выгоды. Код окупается при больших данных с итоговым агрегатом и цепочках ≥ 3 зависимых шагов. (гл. 8, стр. 255–256) → claude-code-priemy
- **Три уровня инструментов — ядро держать неизменным.** Ядро (выполнить код, команда, загрузить файл) — фиксированные схемы, «дружат с кэшем»; скиллы — только сводка в промпте; разовое — генерировать кодом. Не менять набор базовых инструментов посреди сессии. (гл. 8, стр. 268–269) → claude-code-priemy
- **Что писать в журнал агента — 6 полей и 7 метрик.** Поля: запрос, промежуточные рассуждения, порядок вызовов, результаты инструментов, итог, время/вызовы/токены/цена. Метрики: задержка вызова инструмента, время задачи, частота вызовов, токены, цена задачи, заполнение окна, доля ошибок вызовов. Ср. Гулли №56, 59 — здесь полный перечень. (гл. 10, стр. 309–311) → claude-code-priemy
- **Правку скилла/промпта выпускать через малый тест-набор.** Перед заменой промпта классификатора новостей, задания Hermes или текста правил — прогнать 20–50 сохранённых примеров и сравнить с прошлым итогом; хуже — не выкатывать. Для сайта Frivent это уже `qa_site` после deploy. (гл. 10, стр. 323) → claude-code-priemy

## Mollick «Co-Intelligence» (8)


### Новости, данные, Claude Code и агенты

- **Застряла — 10 вариантов в разных стилях.** Когда не идёт текст (письмо, раздел, пост), просить «10 вариантов этого абзаца в разных профессиональных стилях, сильно разных»; брать не текст, а направление. (гл. 6, стр. 119–120) → claude-code-priemy
- **Соредактор, а не одна кнопка.** Лучшие результаты — в диалоге с правками («второй абзац ярче», «короче», «закончи на тревожной ноте»), а не с первого запроса. (гл. 3, стр. 62; гл. 5, стр. 103) → claude-code-priemy
- **Не спрашивать «почему ты ошибся».** Объяснение будет сочинено; вместо этого давать конкретную ошибку, лог или правильный образец и просить исправить. (гл. 5, стр. 90–91) → claude-code-priemy
- **Охота на мелкие ошибки.** В итоговых документах и таблицах проверять каждое утверждение с цифрой, датой, именем — крупное замечаешь сам, мелкое правдоподобное пропускаешь. (гл. 5, стр. 91–92) → claude-code-priemy
- **Журнал «не получилось» на перепроверку.** Задачи, где ИИ не справился, записывать и пробовать снова с новыми моделями — «это худший ИИ, что у тебя будет». (гл. 3, стр. 62–64) → claude-code-priemy
- **Узкая цель и лимит шагов для агента.** Ранний агент на «одну фразу» построил план из 21 шага и сдался; агентам давать конкретный итог, рамки и потолок шагов. (гл. 6, стр. 118) → claude-code-priemy
- **Код — лучший кандидат на автомат.** Где ИИ пишет код, ошибка видна сразу (не запускается), и ИИ сам чинит по тексту ошибки — такие задачи можно отдавать с минимальным присмотром. (гл. 6, стр. 118) → claude-code-priemy
- **Приватность загружаемого.** Загруженное в ИИ может пойти в будущее обучение; приватным режимам решай, доверять ли (дополняет её правило 🟢/🟡/🔴). (гл. 3, стр. 56) → claude-code-priemy

## Whalen «Design for How People Think» (4)


### Новости, данные, Claude Code и агенты

- **ИИ-помощник по шести умам.** При проектировании агента/инструмента спрашивать: что он подсветит (внимание), как покажет «где я» (ориентирование), подстроит ли слова под уровень (язык), разложит ли решение на микровопросы (решения), снизит ли объём при перегрузке (эмоции). (гл. 19, стр. 222–224) → claude-code-priemy
- **Против «мы и так знаем, что строить».** Перед большим скиллом/сайтом набросать 2–3 варианта результата (у себя или у агентов) — если наброски сильно разные, задача не согласована. (гл. 17, стр. 200–201) → claude-code-priemy
- **«Через плечо» вместо опроса.** Когда скилл/панель неудобны, полезнее разобрать один реальный сеанс её работы (что открыла, где задержалась, что искала, какие обходные пути, сколько раз переключилась), чем спрашивать «что улучшить?». Её обходные пути — главные подсказки. (гл. 8, стр. 86, 89, 103) → claude-code-priemy
- **Вопросы до и после шага.** При проверке новой панели/скилла: до — «как, по-твоему, это сработает?»; после — «этого ждала? что должно было произойти? удивило?». (гл. 11, стр. 132) → claude-code-priemy

## «The 0→1 Loop Engineering Playbook» (2026) (15)


### Новости, данные, Claude Code и агенты

- **Потолок шагов по формуле, а не «круглый».** Потолок = 95-й процентиль фактических шагов на пробах + 30 % (6 → 9). Гибкий вариант: старт 20, после 5 шагов: готово ≥ 80 % → осталось 3, < 20 % → до 25. Уточняет Gulli №38 числом. (гл. 1, стр. 10; паттерн 15, стр. 286) → claude-code-priemy
- **Не больше 15 инструментов на виду.** Больше — группировать в один с параметром-подкомандой или показывать по задаче; вопрос перед новым: «может, это подкоманда существующего?». (гл. 6, стр. 53, 65) → claude-code-priemy
- **Единый «конверт» ответа у наших скриптов.** Скрипты, которые зовёт агент, возвращают `{success, data, message, metadata}`; ошибка = что не так + как правильно (список допустимых значений, нужный формат). (гл. 6, стр. 52, 60) → claude-code-priemy
- **Выход инструмента в контекст ≤ ~2 000 токенов.** Длинное — обрезать с «показано 10 из N, дальше — параметр page», логи — хвост + сводка, поиск — пути и строки, а не целые файлы. (гл. 6, стр. 59, 63) → claude-code-priemy
- **Сторож бюджета на 90 %.** Остаток проверять до вызова; на 90 % — «вынужденный итог» из собранного, последние 10 % — только на него. Согласуется с её «лимит 70 % — стоп и в скилл». (гл. 4, стр. 32) → claude-code-priemy
- **Вехи при сжатии.** При сжатии длинной сессии/журнала дословно переносить: её решения, смены плана, ошибки и как обошли, дорогие шаги; остальное — сводкой (промпт сводки — «Модели» №6). (гл. 8, стр. 82–84) → claude-code-priemy
- **Пакетные вопросы ей с цветом риска.** Не спрашивать по одному действию: сводка 5–10 действий одним вопросом; зелёное — одна кнопка, жёлтое — подробно, красное — с объяснением. Деньги и отправка от её имени — всегда отдельно. (гл. 9, стр. 92) → claude-code-priemy
- **Набор проверок до скилла/сборщика.** Сразу 10–50 случаев в 4 категориях (обычные, пограничные, «вредные» — пост с чужими инструкциями внутри, прошлые баги); каждый баг → тест; для скиллов — `claude plugin eval`. (гл. 10, стр. 103, 110) → claude-code-priemy
- **Пять классов причины сбоя в журнале.** MODEL (модель ошиблась), TOOL (инструмент вернул ошибку/мусор), PROMPT (неясное задание), STATE (переполнение, устаревшие данные), EXTERNAL (сайт/API лёг, VPN) — сразу ясно, где чинить. (гл. 11, стр. 139–140) → claude-code-priemy
- **Запрет на молчаливую ошибку.** В скриптах нет `except: pass`: ошибка либо исправлена с записью, либо в блок «⚠️ не собрано» (её правило «неизученное — писать прямо»), либо честный частичный итог с оговоркой. (гл. 12, стр. 155) → claude-code-priemy
- **Дерево решений при ошибке.** Временная → повтор с паузой (≤ 3); есть запасной путь → он + отметка; можно частично → частично с оговоркой; известная → известный фикс + тест; иначе → ей: что случилось, что пробовали, что нужно (ключ / разрешение / действие). Дословно — «Модели» №12. (гл. 12, стр. 158–159) → claude-code-priemy
- **Самопроверку включать только для важного.** Отдельный круг «найди ошибки» стоит как вторая генерация: да — итоги ей, документы, код перед deploy, письма наружу; нет — черновики и пересказы. Промпт — «Модели» №11. (гл. 12, стр. 149–150) → claude-code-priemy
- **Ранний выход.** После каждого шага — «цель достигнута?»; да → стоп, без шагов «на всякий случай» (съедают 30–50 % бюджета). (паттерн 2, стр. 284) → claude-code-priemy
- **Раскладка цены дорогого прогона.** Обычно 40 % — основная модель, 30 % — раздутые выходы инструментов, 20 % — повторы и ошибки, 10 % — системный промпт; резать начинать со 2-го и 3-го. (прил. F Q12, стр. 316) → claude-code-priemy
- **Выключатель у каждого фонового процесса.** Бот «Дела», сборщики, мониторы: один способ остановить всё за секунды (например, файл `STOP` в папке проекта, который скрипт проверяет на каждом шаге); проверять раз в квартал. (паттерн 75, стр. 295) → claude-code-priemy

## Crist, Keijser «Mastering OpenVPN» (4)


### Новости, данные, Claude Code и агенты

- **Риск бана Claude: при обрыве VPN трафик молча уходит напрямую.** С `def1` (так работают почти все VPN-клиенты) при разрыве туннеля Windows «автоматически» возвращает старый шлюз — Claude видит то российский адрес, то адрес VPN посреди одной сессии. Перед долгой сессией проверить внешний IP; если VPN-клиент умеет «kill switch» (блок интернета при обрыве) — это то, что закрывает дыру (функция клиента, в книге её нет). Tunnelblick в книге умеет предупредить, если IP не сменился. (гл. 4, стр. 143–144; гл. 5, стр. 202, 208) → claude-code-priemy
- **Маскировка протокола не прячет адрес.** DPI легко узнаёт OpenVPN даже на 443, поэтому против блокировок сейчас используют xray/Reality (Happ).
