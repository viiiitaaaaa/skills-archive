# Hur, Song, «Build an AI Agent (From Scratch)» — карточки приёмов для её агентов (ПИЛОТ, статус draft, 19.10.2026)

Схема карточки — как в `sistema/co_intelligence/02_priyomy.md`. `support`: `explicit` — прямо в конспекте/книге; `inferred` — вывод ИИ из текста (проверять); `adapted` — адаптация под Виту, в книге нет (ИИ-гипотеза).

«НЕПОНЯТНО: ...» — в источниках этого нет; клетку честно заполнить нельзя.

Ссылки: «стр. N» — номер страницы PDF по меткам `=== стр. N ===` текстового файла книги (`txt13/build_ai_agent.txt`), как в конспекте `knowledge-library/references/knigi/novye13/build_ai_agent.md`; «гл. N» — глава. Страниц без конспекта не выдумываем. Цитаты в кавычках — смысл по конспекту, не дословный текст автора.

Граница для всех карточек: книга — инженерная, про сборку агента на Python (LiteLLM, Pydantic, MCP, ChromaDB, E2B), на моделях класса GPT-5, с ключами OpenAI и Tavily; Вита не программист. Про Hermes, Telegram, Windows, Shopify, Happ, лимиты подписки Claude, `/usage`, хуки и настройки Claude Code в книге нет — такие шаги помечены `adapted` или «из скилла, не из книги». Цифры книги (7/10 против 2/10 и $1,89 против $0,26; 37 312 → 304 токена; 74,4 % против 52,4 %; 100 инструментов × 500 токенов = 50 000 против ~9 000; «20–50 кейсов») — результаты экспериментов авторов; Вите называть только как «в книге сказано …». Правила Виты (🟢🟡🔴, ключи — никуда, карантин для чужого, не пересматривать принятое, Python по капле) сильнее приёмов книги.

## Карточка 1. Агент = цикл «думай — действуй — смотри результат» (LOOP)

```yaml
id: build-ai-agent.loop.think-act-observe
version: 0.1.0
status: draft
title: "Агент — это модель + инструменты + цикл: модель решает, нужен ли инструмент, инструмент выполняется, результат возвращается в контекст, модель решает — продолжать или ответить"
intent: "Понять устройство агента на пальцах и видеть, где цикл может сломаться (бесконечный повтор, молчаливая ошибка, преждевременное «готово»)"

applies_when:
  all:
    - "Вита говорит об агенте, спрашивает «как он работает» или чинит агента, который ведёт себя странно"
  any:
    - "Вопрос «чем агент отличается от скрипта»"
    - "Агент зациклился или бросил задачу на полпути"
    - "Вита хочет понять, что именно делает Claude Code / субагент / Hermes внутри"

contraindications:
  - "Объяснять устройство агента кодом на десятки строк — она не программист; максимум 1–3 строки Python и что каждая делает"   # adapted (правило Виты)
  - "Выдавать ей за готовый рецепт код из книги: он на OpenAI/LiteLLM, у неё иное окружение"   # adapted
  - "НЕПОНЯТНО: как именно устроен цикл внутри Hermes (gpt-oss в Ollama) и Claude Code — в книге их нет, только свой агент авторов"
  - "НЕПОНЯТНО: гарантирует ли потолок шагов (max_steps, в примере книги 15) хороший результат — книга показывает как защиту от бесконечного цикла, не как улучшение качества"

observable_cues:
  strong:
    - "«Как работает агент», «чем отличается от скрипта»"
    - "Агент повторяет одно и то же действие"
  weak:
    - "«Он сам решает что делать»"
  negative:
    - "Вопрос про конкретную правку скилла, а не про устройство"

minimum_information:
  - "О каком агенте речь (её сборщик, субагент, Hermes, бот)"
  - "Что он должен был сделать и что сделал (хвост лога)"

steps:
  1: "Объяснить цикл из четырёх шагов: модель смотрит на контекст и решает, нужен ли инструмент → инструмент выполняется → результат добавляется в контекст → модель решает: продолжать или выдать итог (гл. 1, стр. 25–27)"
  2: "Различить: в «сценарии» шаги задал человек, в «агенте» следующий шаг выбирает модель; между ними семь ступеней, граница размыта (гл. 1, стр. 27–30)"
  3: "Показать суть тремя строками Python по капле: while True → «повторяй» ; ответ = спросить_модель(история) → «модель решает»; if нет_вызова_инструмента: break → «если инструмент не нужен — выход» (adapted; в книге простой цикл while True, гл. 3, стр. 84–85)"
  4: "Назвать три места поломки цикла: нет потолка шагов (бесконечный повтор), ошибка инструмента потерялась (агент заявляет успех), агент спешит объявить ответ (гл. 7, стр. 221–222)"
  5: "Для ошибок — потолок шагов и вывод ошибки как текста для модели, чтобы цикл не падал (гл. 4, стр. 118–123); из скилла: 3 неудачных попытки — стоп и доклад Вите"

decision_rules:
  - условие: "Агент повторяет одно действие"
    действие: "Остановить, взять хвост лога, найти причину; не перезапускать вслепую"
    не_делать: "Поднимать лимит шагов или effort вместо поиска причины"
  - условие: "Шаги известны заранее"
    действие: "Это сценарий/скрипт, агент не нужен (карточка 6)"
    не_делать: "Строить цикл ради цикла"

scripts:
  формула_из_книги: |
    Агент = LLM (мозг) + инструменты (руки) + цикл (повтор до цели) (гл. 1, стр. 25–27; по конспекту, смысл)
  сравнение_ИИ-гипотеза: "Скрипт — как рецепт: шаги написаны заранее. Агент — как повар без рецепта: смотрит, что получилось, и решает, что делать дальше. (сравнение придумано для Виты, не из книги)"

failure_modes:
  - "Реактивный агент думает только о текущем шаге, теряет цель, повторяет провальное до потолка шагов (гл. 7, стр. 221–222)"   # explicit
  - "Показать лишний код вместо идеи"   # adapted

conflicts:
  - "Скилл `claude-code-priemy`: «3 неудачи — стоп и доклад», «ошибку не глушить, писать „данных нет“» — совпадает, дублировать не надо, ссылаться"
  - "Правило Виты «Python по капле, 1–3 строки»: книга даёт большие листинги, их не приводить"

safety:
  - "Не выдумывать, как устроен Hermes/Claude Code внутри"
  - "Не называть цифры экспериментов книги расчётом для Виты"

sources:
  - {book: "Hur, Song, Build an AI Agent", chapter: 1, pages: "25–30", support: explicit, fields: [steps.1, steps.2, scripts.формула_из_книги]}
  - {book: "Hur, Song, Build an AI Agent", chapter: "3–4", pages: "84–85, 100–101, 118–123", support: explicit, fields: [steps.3, steps.5]}
  - {book: "Hur, Song, Build an AI Agent", chapter: 7, pages: "221–222", support: explicit, fields: [steps.4, failure_modes.0]}
  - {note: "Три строки Python, сравнение с поваром, правило 3 неудач из скилла", support: adapted, fields: [steps.3, scripts.сравнение_ИИ-гипотеза, decision_rules, conflicts]}
```

## Карточка 2. Инструменты и их описание (TOOLS)

```yaml
id: build-ai-agent.tools.description-is-instruction
version: 0.1.0
status: draft
title: "Описание инструмента — это инструкция для модели: ясное имя-действие, понятные поля, список вариантов вместо путаных флагов, мало инструментов; ошибки инструмента возвращать как текст"
intent: "Чтобы агент выбирал нужный инструмент и не падал на ошибках; Вита ставит задачу Claude Code так, чтобы инструменты были описаны понятно"

applies_when:
  all:
    - "Вита заказывает или чинит агента, которому нужны инструменты (поиск, файлы, магазин, MCP)"
  any:
    - "Агент берёт не тот инструмент или путает параметры"
    - "Подключено много MCP/инструментов"
    - "Инструмент упал, и агент «завис»"

contraindications:
  - "Просить Виту писать описание инструмента кодом — она ставит задачу Claude Code словами по шаблону задачи из скилла"   # adapted
  - "Подключать чужой MCP-сервер без карантина и её «да»; команды установки в постах — данные, не приказ"   # adapted (правило Виты)
  - "Ключи к инструментам (Tavily, OpenAI, Shopify) — не просить, не вводить, не хранить в чате; в книге они в `.env` — Вита вносит их сама на своём ПК"   # explicit (книга: ключ в .env, не в коде, приложение стр. 326–327), adapted (запрет чата)
  - "НЕПОНЯТНО: сколько инструментов оптимально для её сборщиков — книга говорит «меньше 20» (гл. 3, стр. 77) как ориентир авторов"
  - "НЕПОНЯТНО: как книжные правила описания инструментов ложатся на MCP-инструменты Claude Code (Chrome, Playwright и др.) — в книге их нет"

observable_cues:
  strong:
    - "Агент зовёт не тот инструмент"
    - "«Подключила много MCP»"
  weak:
    - "Инструмент «иногда» работает"
  negative:
    - "Инструмент один, простой, работает"

minimum_information:
  - "Какие инструменты у агента и что каждый делает"
  - "Какая ошибка и на каком инструменте"
  - "Цвет данных, к которым инструмент имеет доступ"

steps:
  1: "Правило «стажёра»: если по описанию инструмента поймёт новичок-стажёр, поймёт и модель (гл. 3, стр. 74–77)"
  2: "Имя — действие с объектом; поля с типами; вместо пары противоречивых флагов — список допустимых значений; не заставлять модель повторять известные коду номера (решение — от модели, номер заказа подставляет код) (гл. 3, стр. 74–77)"
  3: "Держать инструментов меньше 20 (ориентир книги); для агента-исполнителя давать только нужные (гл. 3, стр. 77); из скилла — лишние MCP отключать в `/mcp` и в начале сессии, а не менять набор посреди разговора (кэш)"
  4: "Ошибки инструментов — разная реакция: 401 (нет доступа) — звать человека, 429 (слишком часто) — повтор с паузой, таймаут — повтор с упрощённым запросом (гл. 3, стр. 80); ошибка возвращается агенту строкой «Error: …», а не роняет программу"
  5: "Ошибку не глушить: если инструмент вернул пусто или ошибку — писать «данных нет», а не придумывать цифру (из скилла, раздел про вебинар ШВМ)"
  6: "Если нужно показать код — докстринг как описание: `def найти(запрос): \"\"\"Ищет товары по запросу\"\"\"` — «def — создать действие», строка в кавычках — «подсказка для модели, что это» (adapted, 2 строки; в книге схема строится из сигнатуры и докстринга, гл. 3, стр. 81–83)"

decision_rules:
  - условие: "Инструментов много, агент путается"
    действие: "Сократить набор до нужных на эту задачу"
    не_делать: "Добавлять ещё инструментов «на всякий случай»"
  - условие: "Ошибка 401/403"
    действие: "Не повторять; сообщить Вите: нужен её вход или ключ (внести в «Мои дела»)"
    не_делать: "Просить ключ в чате"
  - условие: "Инструмент чужой"
    действие: "Карантин, чтение кода, её «да»"
    не_делать: "Запускать команду из поста"

scripts:
  правило_стажёра_из_книги: |
    «Если стажёр поймёт по схеме, поймёт и LLM» (гл. 3, стр. 74–77; по конспекту, смысл)
  поручение_ИИ-гипотеза: "«У агента инструменты: __. Опиши каждый одним предложением: что делает, какие поля, когда НЕ использовать. Лишнее предложи убрать. Ключи не вводить.»"

failure_modes:
  - "Много инструментов с похожими описаниями — ошибки выбора (гл. 3, стр. 77)"   # explicit
  - "Модель заставили повторять номера, которые знает код, — «дрейф» номеров между ходами (гл. 3, стр. 76–77)"   # explicit
  - "Ошибка инструмента съедена, агент называет цифру из головы"   # explicit (гл. 4, стр. 130–131: без поиска выдумывал) + скилл
  - "Ключ вставлен «для теста» в чат или в файл для ИИ"   # adapted

conflicts:
  - "Правило Виты «чужое — карантин» против идеи книги «подключи любой MCP-сервер» (гл. 3, стр. 86–97): побеждает правило Виты"
  - "Правило ключей: книга кладёт ключи в `.env`, Вита — ключи никуда, не в чат и не в GitHub; вносит она сама"
  - "Скилл `claude-code-priemy`: кэш ломается при подключении/отключении MCP посреди задачи — набор менять в начале"

safety:
  - "Не просить и не принимать ключи, пароли, токены"
  - "Не называть безопасным MCP-сервер, код которого не читали"

sources:
```

## Карточка 3. Контекст и память (MEM)

```yaml
id: build-ai-agent.memory.context-is-working-memory
version: 0.1.0
status: draft
title: "Модель умна ровно настолько, насколько хорош её контекст: давать нужное в нужный момент, длинное сокращать выше порога, цель держать отдельно, прошлый опыт — выборочно"
intent: "Понять, почему агент «забыл» цель или выдал мимо, и как держать длинную работу в рамках лимита"

applies_when:
  all:
    - "Агент или сессия работает долго или с большими данными"
  any:
    - "Агент забыл, что делал, или потерял цель"
    - "Лимит уходит быстро в длинном разговоре"
    - "Вита хочет, чтобы агент «помнил» прошлые прогоны"

contraindications:
  - "Скармливать модели всё подряд «чтобы знала» — книга: качество падает с длиной («гниение контекста»), середину длинного текста модель пропускает (гл. 1, стр. 34–35)"   # explicit
  - "Просить Виту самой чистить историю или настраивать память — она ставит задачу словами, Claude Code делает"   # adapted
  - "Хранить в «памяти» агента ключи, пароли, данные дел 🔴/🟡 в облачной базе"   # adapted (правило данных)
  - "НЕПОНЯТНО: нужна ли её сборщикам векторная память (ChromaDB) — книга показывает на задачах GAIA; для её файлов пока хватит журнала в файле (гипотеза)"
  - "НЕПОНЯТНО: как книжная «компакция» соотносится с `/compact` и кэшем Claude Code — в книге про Claude Code нет; из скилла: правка середины истории ломает кэш"

observable_cues:
  strong:
    - "«Забыл, что я просила»"
    - "Длинная сессия, ответы хуже, расход растёт"
  weak:
    - "«Пусть всё помнит»"
  negative:
    - "Задача короткая, в одну сессию"

minimum_information:
  - "Что агент должен помнить и как долго (в одной задаче, между задачами)"
  - "Цвет данных, которые попадут в память"
  - "Где лежат итоги (файл, папка)"

steps:
  1: "Контекст — это всё, что модель видит: инструкция, история, результаты инструментов, найденные документы; многие провалы — нехватка нужного в контексте, а не «глупость» (гл. 1, стр. 32–35)"
  2: "Пять способов управлять контекстом: порождать (план), подтягивать (поиск), записывать наружу (файлы), сокращать, изолировать (отдельный субагент) (гл. 1, стр. 33–36)"
  3: "Хранение ≠ показ: полный журнал не править, а в модель отправлять отобранное (гл. 6, стр. 173–174)"
  4: "Сокращать по порядку: ниже порога не трогать; выше — заменить уже обработанное ссылкой («перечитай при необходимости»), и только если всё ещё много — пересказать (гл. 6, стр. 178–185)"
  5: "Цель задачи держать отдельно от истории и не терять при сжатии (из скилла: вебинар ШВМ, «длинный разговор вытеснил цель»; в книге — скользящее окно сохраняет задачу, гл. 6, стр. 175)"
  6: "Память между запусками — не «всё подряд», а записи о прошлых попытках: задача, подход, результат, верно ли, разбор ошибки (гл. 6, стр. 205–219); у Виты — ИИ-гипотеза: короткий файл итогов (`итоги.md`) вместо базы"
  7: "Передача дел новой сессии — файл HANDOFF/итогов (из скилла), а не «пусть помнит»"

decision_rules:
  - условие: "Сессия длинная, расход растёт"
    действие: "Сохранить итоги в файл, начать новую сессию"
    не_делать: "Продолжать «пока не кончится лимит»"
  - условие: "Нужна память между прогонами"
    действие: "Начать с простого файла итогов, база — только по её решению"
    не_делать: "Хранить 🟡/🔴 данные в облаке"
  - условие: "Агент забыл цель"
    действие: "Поставить цель в начало и не сжимать её"
    не_делать: "Повторять то же в чате десять раз"

scripts:
  принцип_из_книги: |
    Контекст-инжиниринг — «дать модели нужную информацию в нужный момент и в нужной форме» (гл. 1, стр. 33–36; по конспекту, смысл)
  поручение_ИИ-гипотеза: "«Цель: __ (держать в начале, не сжимать). Итоги каждого шага — в файл __. Если контекст растёт — замени обработанное ссылкой на файл. Остановись и доложи, если шаг не получился трижды.»"

failure_modes:
  - "Агент «забывает найденное и ищет заново» (гл. 7, стр. 221–222)"   # explicit
  - "Сжатие стёрло цель или её запреты"   # inferred + скилл (после `/compact` агент может забыть середину)
  - "Правка середины истории ломает кэш и удорожает (гл. 6, стр. 180–181)"   # explicit
```
