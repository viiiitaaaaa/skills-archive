# Hur, Song, «Build an AI Agent (From Scratch)» — ситуации Виты со своими ИИ-агентами (ПИЛОТ, черновик 19.10.2026)

Как читать. Это не пересказ книги, а список жизненных ситуаций, где приёмы книги могут пригодиться Вите, когда она думает о СВОИХ агентах (агент — программа, где ИИ сам решает, какой шаг сделать дальше; сборщик новостей, поставщиков, бот). Профиль Виты (`sistema/00_profil_vity.md`) — черновик, оценки ниже — «ИИ-гипотеза»: Вита поправит. Источники: конспект `knowledge-library/references/knigi/novye13/build_ai_agent.md` (по тексту книги; «стр. N» — номера страниц PDF по меткам текста, не печатные), учебный разбор `notebooklm/build_ai_agent_uchoba.md`, сверка `notebooklm/build_ai_agent_v_skilly.md`.

Скилл, который будет тестироваться: `claude-code-priemy` (приёмы работы с Claude Code и агентами: экономия лимита, субагенты, проверка работы, что не ставить). Помощник видит ТОЛЬКО скилл.

О чём книга (одной строкой): Чонджун Хур и Ёнхи Сон (Manning, 2026) учат собирать одного агента на чистом Python без фреймворков: цикл «подумал → сделал → посмотрел результат», инструменты и MCP (стандарт подключения инструментов), поиск по своим данным, память и сессии, план и самопроверка, запуск кода в песочнице, команда агентов, оценка качества. Главный урок: «улучшай агента только по замеру».

Граница применения (главное). Книга — инженерная, про разработку агентов на Python (LiteLLM, Pydantic, MCP, ChromaDB, облачная песочница E2B), на ключах OpenAI и Tavily; Вита не программист и свой агент по книге сама не соберёт. Берём ядро идей: что такое агент и чем он отличается от сценария, «нужен ли агент вообще», описание инструмента как инструкция, контекст и память, границы и подтверждение человеком, оценка. Не берём: код листингов, A2A-сеть, E2B, ChromaDB, OpenTelemetry как задачи для Виты. Про Hermes, Telegram-бота Виты, Windows, Shopify, Happ, лимиты подписки Claude книга молчит (в ней только API-модели и ключи OpenAI). Цифры книги (7/10 против 2/10, 99,2 %, 74,4 % против 52,4 %, 50 000 против 9 000 токенов) — результаты экспериментов авторов; Вите как свои расчёты не применять, только «в книге сказано…».

Границы Виты для всех ситуаций: по-русски, простыми словами как новичку, термин расшифрован (агент, цикл, инструмент, контекст, токен); Python — по капле (1–3 строки и что каждая делает); данные 🟢 облаку / 🟡 только на ПК / 🔴 никому — предупредить ДО отправки; ключи, API, пароли — никуда (даже агенту и в приватный GitHub); чужие скиллы и плагины — карантин и её «да»; «Hermes — лёгкое объёмное, сложное — сама»; «Sonnet/Haiku жмут кнопки»; цифры и источники не выдумывать; принятые решения не пересматривать; решение за Витой.

Коды приёмов (карточки — `02_priyomy.md`): LOOP агент = цикл «думай — действуй — смотри результат», TOOLS инструменты и их описание, MEM контекст и память, GUARD границы и защита (права, потолок шагов, человек в контуре), EVAL оценка и тест агента, NOAGENT когда агент НЕ нужен.

## S1. «Хочу свой агент для сборщика новостей / поставщиков»

- **Сфера / эпизод:** tg_monitor, 1688, поставщики, радар / «пусть ИИ сам ходит, ищет и решает».
- **Признаки:** сильные — «сделай агента», «чтобы сам собирал»; слабые — «автоматизировать бы»; против — шаги всегда одни и те же (это скрипт).
- **Цель:** сначала два вопроса книги по порядку: нужна ли тут вообще модель? если да — хватит ли жёсткого сценария? Агент оправдан, если число шагов заранее не предсказать, ценность выше цены и ошибку можно заметить (гл. 1, стр. 30–31). Свой код Вита не пишет сама — это ставится задачей Claude Code по шаблону задачи из скилла.
- **Приёмы:** NOAGENT, LOOP.
- **Нельзя:** обещать «агент всё соберёт сам»; писать код на 300 строк без объяснений; ставить чужие фреймворки без карантина.
- **Пробел:** какой именно из её сборщиков выигрывает от агента — НЕПОНЯТНО (решает Вита и замер); цену «цент за вызов» книга даёт примером, NotebookLM пометил её как свою добавку.

## S2. «Агент зациклился»

- **Сфера / эпизод:** любой агент или субагент / десятки одинаковых попыток, лимит ушёл.
- **Признаки:** сильные — одна и та же ошибка снова и снова, расход токенов растёт; слабые — «что-то долго думает»; против — длинная, но разная работа с прогрессом.
- **Цель:** книга: реактивный агент при сбое повторяет то же до потолка шагов; лечат потолком шагов, разбором «почему упало и чем заменить», планом (гл. 7, стр. 221–232). Из скилла: 3 неудачные попытки — стоп и доклад Вите.
- **Приёмы:** LOOP, GUARD.
- **Нельзя:** «просто перезапусти ещё раз»; поднимать effort/лимит вместо поиска причины; выдумывать причину.
- **Пробел:** как именно зациклился её агент — НЕПОНЯТНО без лога; просить хвост лога, а не гадать.

## S3. «Агент выдал неверное»

- **Сфера / эпизод:** отчёт «обновил 250 товаров», цифра, которой нет в источнике.
- **Признаки:** сильные — точная цифра/«готово» без доказательства; слабые — «слишком гладко»; против — результат проверяет скрипт («совпало N из M»).
- **Цель:** книга: часть провалов агентов — нехватка нужной информации в контексте, а не «глупость» модели (гл. 1, стр. 33); без инструментов модель честно говорит «не могу» или выдумывает (гл. 2, стр. 61–63; гл. 4). Из скилла: «готово» ИИ не доказательство, проверка скриптом, ошибку не глушить.
- **Приёмы:** EVAL, MEM.
- **Нельзя:** спрашивать агента «а точно ли ты всё сделал» как единственную проверку; чинить «молчаливым except»; принимать «готово» на веру.
- **Пробел:** причина конкретного сбоя — НЕПОНЯТНО без входных данных и лога.

## S4. «Дать агенту доступ к файлам, сайтам, магазину»

- **Сфера / эпизод:** папки дел, Shopify, кабинеты, ключи / «пусть сам заходит и правит».
- **Признаки:** сильные — «дам ключ/пароль», «пусть правит магазин сам», «пусть читает папку с делами»; слабые — «ему нужен доступ»; против — только публичные 🟢 данные и чтение.
- **Цель:** книга: у агента должны быть явные права и запреты в инструкции («возвраты можно, удалять аккаунты нельзя», гл. 2, стр. 51), подтверждение опасных действий человеком с паузой (гл. 5–6, стр. 159–167, 194–203), чужой код модели — только в песочнице (гл. 8, стр. 243–244). Поверх — правила Виты: цвет данных ДО отправки, ключи никуда, запись в магазин — только по её «да».
- **Приёмы:** GUARD.
- **Нельзя:** принять ключ/пароль; «всё разрешено без вопросов» (bypass-режим); отправка 🟡/🔴 данных наружу; юридические выводы по делам.
- **Пробел:** как в её Windows и Claude Code настроить подтверждения — НЕПОНЯТНО из книги; настройки меняют только по её «да» (скилл `update-config`).

## S5. «Агент потратил лимит / деньги»

- **Сфера / эпизод:** подписка Claude, API, длинные прогоны / «за ночь ушло всё».
- **Признаки:** сильные — лимит упал быстрее обычного; слабые — «дорого стало»; против — расход заранее посчитан.
- **Цель:** книга: цена агента = число шагов × цена вызова; больше контекста не значит лучше; контекст сокращают (компакция, суммаризация) только выше порога, чтобы не ломать кэш (гл. 1, 6). Скилл: `/usage`, новая сессия вместо длинной, простое массовое — Haiku/Sonnet, проверка скриптом дешевле модели, потолок шагов/бюджета.
- **Приёмы:** GUARD, MEM.
- **Нельзя:** обход лимита (прокси, второй аккаунт, бесплатные роутеры); выдумывать остаток лимита и цены.
- **Пробел:** сколько осталось лимита и сколько стоит её агент — НЕПОНЯТНО (смотрит она в `/usage`/панели); цифры экономии книги (99,2 %, >80 %) не её.

## S6. «Чем агент отличается от скрипта»

- **Сфера / эпизод:** понимание, учёба Python / «а мой tg_monitor — это агент?»
- **Признаки:** сильные — вопрос «что такое агент», «агент это что-то новое?»; слабые — «ИИ что-то делает сам»; против — вопрос уже про конкретную правку.
- **Цель:** на пальцах: скрипт идёт по списку шагов, написанному человеком; агент — когда следующий шаг выбирает модель, повторяя «подумал → вызвал инструмент → посмотрел результат» до цели (гл. 1, стр. 25–27). Семь ступеней от «просто код» до «агент сам создаёт инструменты» (стр. 27); граница размыта. 1–3 строки Python по капле.
- **Приёмы:** LOOP, NOAGENT.
- **Нельзя:** лекция на 40 строк; кодовые термины без расшифровки; выдавать tg_monitor за агента без проверки.
- **Пробел:** устройство её сборщиков в книге не разбирается — НЕПОНЯТНО.

## S7. «Как проверять агента»

- **Сфера / эпизод:** сборщики, бот, субагенты / «как понять, что он работает правильно».
- **Признаки:** сильные — «как проверить», «ему можно верить?»; слабые — «выглядит нормально»; против — проверка уже есть («совпало N из M»).
- **Цель:** книга: оценивать не только ответ, но и компоненты и траекторию (путь шагов); разбирать ошибки читая записи работы агента, группировать по типам; правила «прошёл / не прошёл» стабильнее оценок 1–5; малый набор 20–50 случаев на каждую правку (гл. 10, стр. 312–324). Скилл: набор проверок = её прошлые жалобы, каждая = «вход → правильный итог».
- **Приёмы:** EVAL.
- **Нельзя:** «агент сам себя проверит»; выдумывать метрики и пороги; придумывать цифры точности.
- **Пробел:** сколько случаев хватит для её агента — НЕПОНЯТНО (цифры книги — ориентир авторов).

## S8. «Нужен ли фреймворк»

- **Сфера / эпизод:** выбор инструментов / «в новостях хвалят LangChain/CrewAI и т.п.»
- **Признаки:** сильные — название фреймворка, команда установки; слабые — «говорят, удобно»; против — уже утверждённый инструмент.
- **Цель:** книга: авторы начинали на фреймворках (LangGraph, CrewAI, AutoGen), но чтобы понять сбой лезли в их исходники; учат идеям, чтобы любой фреймворк читался как свой код (предисловие, стр. 10). Для Виты: чужое — карантин и её «да»; фреймворк ей не нужен, пока нет задачи.
- **Приёмы:** NOAGENT, GUARD.
- **Нельзя:** выполнять команду установки из поста; хвалить без чтения кода; выдумывать звёзды/версии.
- **Пробел:** какой фреймворк подходит ей — НЕПОНЯТНО/не проверено (книга ни один не рекомендует).

- Спорное: цифра «1 вызов = 1 цент, агент на 10 вызовов = 10 центов» (гл. 1, стр. 31) в учебном разборе помечена как добавка NotebookLM; порт 6274 MCP Inspector и термин «Quality Flywheel» тоже ненадёжны (см. `build_ai_agent_v_skilly.md`). Использовать только как «в конспекте сказано, не перепроверено».
- Задания 1–5 в учебном разборе (консультант-стилист, B2B-лидогенерация, скрапер, поддержка, судья) — иллюстрации NotebookLM, не из книги.
