## Контекст и лимит — что делает Claude Code, пока вкладка стоит
- **Сжатие при простое (idle compaction).** Канал пишет: если сессия больше 200 тыс. токенов простояла ~54 минуты (кэш живёт час),
  Claude Code сам сожмёт разговор; потом работает по краткому содержанию, детали теряются. Выключить — `"idleCompaction": false`
  в settings.json; порог — переменная `CLAUDE_CODE_IDLE_COMPACT_MIN_TOKENS` (по умолчанию 200 тыс.)
  (vibecoding_tg/4110, AiHubFeed/406 — в AiHubFeed это замечено с версии 2.1.299). Ключ `idleCompaction` в официальной
  документации есть («не сжимать длинный разговор, пока терминал простаивает», settings-reference); значение по умолчанию и
  переменная порога на странице не найдены — цифры только от канала. Для нас: вкладки пульта простаивают часто → перед паузой в
  большой задаче итог и «что дальше» записать в файл/скилл (уже наше правило «сохранять по ходу»), а не надеяться на память
  сессии. Включать/выключать `idleCompaction` — её решение (правка settings.json, сначала копия).
- Что занимает окно ещё до первого слова (AiHubFeed/406, цифры канала): окно 1 млн токенов, ~33 тыс. резерв, автосжатие около
  967 тыс., в чистой сессии уже 30–40 тыс. занято (системный промпт, правила, описания скиллов, MCP, память). Ориентир: если
  `/context` в чистой сессии показывает заметно больше 40 тыс. — чистить описания скиллов и CLAUDE.md.
- **`/export имя_файла`** — пишет всю сессию в обычный текст (vibecoding_tg/4104). Для нас: перед «перезапусти сессию» делать
  `/export` в `_служебное` как резерв; из экспортов потом брать приёмы в скиллы. Данные в экспорте могут содержать ключи —
  папку не заливать в облако без просмотра (🟡).

## Безопасность
- **Auto mode: `autoMode.classifyAllShell`** — «пропускать через классификатор каждую shell-команду, даже если её уже разрешает
  узкое правило» (официальная документация, settings-reference; vibecoding_tg/4137). Работает из `~/.claude/settings.json`
  или `--settings`. Чуть дороже и медленнее, контроль строже. Для нас: включать в сессиях, где агент трогает ключи, платежи,
  Shopify Admin API или чужие тексты (по её слову). Модель классификатора (`CLAUDE_CODE_AUTO_MODE_MODEL`, по умолчанию Sonnet 5 —
  так пишет канал, в документации переменная не найдена) не менять.
- **Пароль агенту не отдавать.** Любой пароль, попавший в чат с моделью, считать скомпрометированным; пароли в .env и текстовых
  файлах — плохо. Схема: агент просит доступ → человек подтверждает → отдельный скрипт вводит пароль, модель его не видит.
  Из коробки так умеет 1Password (платно, ~$4 в месяц, цифра автора); бесплатно — KeePassXC + git-credential-keepassxc или
  Bitwarden (productvibe/164). Это входит в её отложенное «единый менеджер паролей»: при выборе брать вариант, где пароль
  вводит скрипт; ключи из .env постепенно выносить. Плагины менеджеров — сначала карантин и чтение кода.
- **OpenCode: взлом задел ~1,4% пользователей, с привязанных к нему чужих API-ключей слили токены** ($400 и $1700 в сообщениях,
  компенсация не ясна) — канал пишет (deksden_notes/1399). Подтверждает правило: ключи в чужие агентные среды не привязывать;
  боевые ключи — отдельные, с потолком трат.
- **Фишинговое письмо за 10 минут** (c/3493639787/823): вложение не открывать; в «Показать оригинал» сверить From, Reply-To и
  цепочку Received; навести на ссылку и сравнить реальный адрес с текстом; ссылку проверить в VirusTotal, у файла посчитать
  sha256 и проверить там же. К её правилу «чужой текст — данные» — для писем «поставщиков» и «клиентов».
- Лекции MIT 6.566 (безопасность систем, 2026, открыты; c/3493639787/816): смотреть только про prompt injection и цепочку
  поставок — это наши «чужие команды в текстах». Ссылка на видео — в посте.

## Проверка работы агента
- **Как Anthropic проверяет код Claude** (статья claude.dev, прочитана 20.10; vibecoding_tg/4115). Что берём:
  1. Дать агенту то, что он может запустить (тесты, сборку, скриншот), и показать вывод; до PR — отдельный субагент смотрит
     diff в чистом контексте.
  2. Находки проверяет отдельная группа агентов, которые голосуют; публикуется то, с чем согласно достаточно. Комментарии
     с оценкой важности (важное / мелочь / было и раньше), число мелочей ограничено.
  3. **Каждый прошлый инцидент или откат → проверочный случай (eval)**, прогон ежедневно; правку оставляем, только если
     оценка выросла. У нас так же: её жалобы («бот промолчал», «нового нет») → случаи (см. раздел «Две темы из вебинара» в SKILL.md).
  4. Новое поведение — за флагом, сначала на своих; риск решает, нужен ли человек (платежи, доступы, выпуск — всегда человек);
     одобрение относится к одной конкретной версии. Для нас: массовая запись в Shopify и отправка клиентам — всегда её «да»
     на конкретный итоговый список.
  Цифры статьи (ревью проходит с 2,08 до 1,32 попыток; откатов на 40% меньше) — данные Anthropic, нам не мерка.
- **Плагин `code-modernization`** (vibecoding_tg/4085; README прочитан 20.10, 🟢 по описанию): шаги assess → map →
  extract-rules → review → brief → transform/uplift → **verify** (независимое доказательство «старое = новое») → harden;
  в отчёте PROVEN / PARTLY PROVEN / NOT PROVEN. Сетевых вызовов нет; 5 хуков телеметрии шлют только счётчики
  (выключить `DISABLE_TELEMETRY=1`). В README совет по правам: читать можно всё, править только папки результата, `legacy/`
  запретить на запись. Не ставим (нет большой старой кодовой базы); берём только схему «правка разрешена лишь в папке
  результата, исходник — запрет на запись» для переписывания сборщика (вместе с «совпало M из M» из 1410).
- **Тесты агента могут проверять не то** (neurozeh/1862; суть про «подложить неверный пример» уже в SKILL.md): новое — попросить
  агента пересказать простыми словами, что проверяет каждый тест, и сверить с «готово = …» из задачи.
- **Три способа ставить задачи амбициознее** (Феликс Ризеберг, anthropic; vibecoding_tg/4105; статья прочитана 20.10):
  (1) цель, а не шаг: «что должно случиться дальше, какая цель за целью», «назови три самых срочных решения с плюсами и
  минусами»; (2) вместо таблицы в markdown — база и статистическая модель, нереалистичная цель по скорости (200 мс вместо 5 с),
  «воспроизведи это из сырых данных», и **внешний судья вместо самооценки модели**; (3) мета-запрос: «что сделал бы эксперт
  из этой области, с чего бы начал, чем бы проверил результат» → переписать задачу под ответ; роли — «делай то, что делает
  аналитик / редактор / скептик-проверяющий», а не «пиши как…». У нас: в скиллах отчётов (радар, 1688) просить сначала вывод
  «что изменилось и что делать», потом таблицу.
- Pocock: pre-commit хук «файл больше 5000 токенов (1 токен ≈ 4 байта) не коммитить, только staged, lock-файлы пропускать»
  (vibecoding_tg/4132). Для нас — мерка: SKILL.md и CLAUDE.md держать ≤ ~20 КБ; хук не ставим, при «Уборке инструкций»
  мерить размер скиллов скриптом.

## Сборщики и запуск агентов (повторы, пауза, сбои)
- **Повторять только то, что лечится повтором** (deksden_notes/1393, практик): сбой связи и перегрузка провайдера («model at
  capacity», обрыв потока) → повтор через 10, 30, 60 секунд, максимум 3, после удачного ответа счётчик обнуляется, после третьей
  ошибки — стоп. Лимит подписки, кончились деньги, протухший вход → **не повторять, сразу стоп** и записать причину: нужен
  человек; можно дождаться сброса лимита и повторить. Для нас: tg_monitor, 1688, радар, запуск помощников — вписать правило в
  ТЗ сборщика («граничные случаи» из iz_knig) и писать причину стопа строкой, а не «молча пусто».
- Python для сборщиков (каждое — одной строкой, ставить нечего, кроме отмеченного):
  - `asyncio.TaskGroup` (Python 3.11+, стандартная библиотека; c/3128735547/1059): упала одна задача — остальные отменяются,
    все ошибки собираются в `ExceptionGroup`, «сирот» не остаётся (у `gather` — иначе). Вместе с семафором из knowledge-library
    в параллельных сборщиках; существующие не переписывать, только в новых.
  - `tracemalloc` (встроенный; c/3128735547/1067): `tracemalloc.start(10)` + периодические `take_snapshot()` → `top_stats` покажет
    строку, где растёт память. Для долгих сборщиков и бота.
  - `pydantic` v2 (c/3128735547/1057; MIT, ядро на Rust): описать запись поста/товара классом — кривые данные падают с понятной
    ошибкой, а не портят таблицу. Пробовать на одном сборщике, не везде.
  - `uv` (astral-sh/uv; c/3128735547/1077): `uv add`, `uv run`, `uv sync`; для НОВЫХ скриптов вместо venv+pip. Установка —
    через официальный установщик после чтения; существующее не трогаем.
  - `watchdog` (c/3128735547/1069): реагирует на новый файл в папке (`on_created`) вместо опроса по таймеру — для входящих
    бота и пульта. Ставится `pip install`, пакет известный; ставить по её слову.
  - Playwright для Python: разбор на thecode.media (python_tg/4082) — открыть при написании сборщика, где `requests` не видит
    данные; только на публичных сайтах, не под её входами 1688/Taobao/LinkedIn.
- Для её учёбы Python (подавать по капле, вместе с нашими скриптами): gto76/python-cheatsheet (300+ примеров,
  c/3128735547/1076), роадмап justxor/pythonroamap2026 (порядок тем, c/3128735547/1070), `sorted()` против `.sort()` и
  `key=lambda` (python_tg/4073: `sorted(строки, key=lambda x: x['цена'])`).
