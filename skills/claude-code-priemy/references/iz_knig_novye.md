## «8-Figure Ecommerce Engine» (10)


### Новости, данные, Claude Code

- **«5 почему» для сбоев скриптов.** При поломке сборщика/бота задавать «почему» до корня, а не латать симптом — быстрее чинить навсегда — при любой ошибке. (Вступление) → claude-code-priemy
- **ICE для очереди задач.** Хвосты (скиллы, скрипты, изучение) оценивать по Влиянию/Уверенности/Лёгкости и брать сверху — меньше «застрявших» дел — при разборе «что дальше». (гл. 4) → claude-code-priemy
- **ТЗ агенту — как поручение сотруднику.** Писать субагенту объём, что передать, формат, критерий готовности и срок; результат — в шаблон/скилл — согласуется с её правилом «сначала каким должен быть итог» — при каждом делегировании. (гл. 4) → claude-code-priemy
- **Пауза перед резким решением.** При сбое бота/сборщика — не удалять данные и конфиги сгоряча; сначала копия и разбор — не терять накопленное — при авариях. (гл. 4) → claude-code-priemy
- **SOP короткими шагами с видео на шаг.** Для её скиллов/инструкций: шаги по одному действию, при необходимости — короткая запись экрана на шаг, чтобы менять только изменившийся шаг — проще поддерживать — при написании скилла. (гл. 5) → claude-code-priemy
- **«SOP о том, как писать SOP».** Иметь шаблон скилла (цель, триггеры, шаги, итог, грабли) — все скиллы однородны — при создании нового скилла. (гл. 5) → claude-code-priemy
- **Спринт: одна задача — один ответственный — срок.** Для длинных задач: одна цель, один исполнитель (агент), жёсткий срок/лимит — меньше расползания — при запуске агентов. (гл. 5) → claude-code-priemy
- **Ограничение рабочего дня.** Фокус-блоки ~4 часа на главное; длинные сессии Claude дробить — согласуется с её правилом «новая сессия заранее» — при планировании дня. (гл. 7) → claude-code-priemy
- **Задача повторилась 2–3 раза — в скилл.** Если одно и то же делаем 2–3 раза — оформить скиллом/скриптом (согласуется с её «принятое → скилл») — постоянно. (гл. 8) → claude-code-priemy
- **«Дать системе отдышаться».** После серии больших изменений (радар, бот, скиллы) — пауза на стабилизацию и замер, прежде чем менять дальше — данные точнее — после крупных переделок. (гл. 11) → claude-code-priemy

## Bierut «How to Use Graphic Design to Sell Things» (4)


### Новости, данные, Claude Code

- **Свежий глаз за 3 минуты.** Застряли на задаче (дизайн, скрипт, отбор) — выложить всю работу + исходные фото/данные второму исполнителю (субагенту/новой сессии) с вопросом «что тут не так?»; не стыдиться выбросить месяцы работы. (стр. 283) → claude-code-priemy
- **Генерировать больше вариантов, чем нужно.** Для названий/слоганов/баннеров просить у ИИ заведомо много вариантов (Ted: 100+ имён → 5 финалистов с плюсами-минусами → лучший последним). (стр. 34, 225, 229) → claude-code-priemy
- **Журнал решений.** Записывать решения и наброски в один журнал (как 100 блокнотов Бирута) — первый эскиз будущей работы часто прячется среди списков дел; у нас — память + скиллы. (стр. 17) → claude-code-priemy
- **Ограничение как условие задачи.** В промптах на дизайн/текст давать жёсткие рамки (1 шрифт, 2 цвета, 1 носитель) — ограничения рождают идеи лучше, чем «полная свобода». (стр. 41, 113) → claude-code-priemy

## Grewal «Marketing» 8e (США), ч. A (2)


### Новости, данные, Claude Code

- **«Ключевые факторы успеха» в брифе длинной задачи.** По образцу плана PeopleAhead добавлять в бриф агенту короткий раздел «без чего задача провалена» (3–6 пунктов), рядом с описанием итога. Зачем: агент проверяет себя по ним в конце. Когда: при написании брифов субагентам. (прил. 2A, стр. 79) → claude-code-priemy
- **Агент-консультант сначала учится на всём каталоге и внешних данных.** Помощник The North Face сначала должен был «выучить» все товары и понимать их описания, плюс подтягивать внешнее (температура в Вермонте в декабре), иначе он бесполезен. Для нас: любому агенту, который пишет описания, подбирает модели или отвечает покупательницам, давать полный каталог с характеристиками и внешний контекст (сезон, климат штата), а не одну карточку — зачем: без контекста ответы общие и ошибочные — когда: при сборке такого агента или скилла. (гл. 5, стр. 172) → claude-code-priemy

## Hill «International Business», ч. B (2)


### Новости, данные, Claude Code

- **«Разморозить → сдвинуть → закрепить» для смены логики.** При переходе на новое правило отбора или новую структуру скиллов: сразу заметный шаг (пересчитать всё, не «понемногу»), быстро перенастроить скрипты/таблицы, затем закрепить правило в скилле и памяти, чтобы старое не вернулось. ## Dahlström «Storytelling in Design» (4)


### Новости, данные, Claude Code

- **Счастливый и несчастливый путь скрипта.** Для каждого сборщика (tg_monitor, радар, бот) расписать: что будет, если всё упало (нет сети, капча, лимит API) — и какое сообщение увидит она. (гл. 9, 10) → скилл claude-code-priemy

- **Три черновика.** Черновик-«рвота» для себя → структурный → шлифовка; не шлифовать первый. Для длинных документов и скиллов. (гл. 11) → скилл claude-code-priemy
