# Приёмы Claude Code из новостей (скилл `claude-code-priemy`)

Сюда — приёмы именно про работу Claude Code и скиллов. Уроки по магазину и общий список «когда будет время» —
скилл `dropship-lessons`; правила данных 🟢/🟡/🔴 — там же, раздел «ВСЕГДА». Инструменты здесь **не установлены**:
ставить только по её слову и после чтения репозитория (правило dropship-lessons «чужие скиллы»).
Источник у каждого пункта: канал/номер, пост N на панели, дата.

## ВСЕГДА

- **Аккаунт Claude — главный инструмент, беречь от бана.** Канал пишет: Claude вычисляет вход через VPN, китайских
  пользователей банили вместе со всей историей; пользователям из РФ приходили письма о блокировке за «неподдерживаемый
  регион» и «серую» оплату (PushEnter/13781, пост 819, 02.10). Что делаем:
  1. Входить в Claude всегда с одного и того же адреса/сервера Happ; не переключать серверы посреди работы с Claude.
  2. Всё важное держать вне claude.ai: скиллы и память — GitHub `viiiitaaaaa/skills-archive` через
     `claude-skills\sync_skills.ps1`; перед «споки» проверять, что синхронизация прошла.
  3. Важные переписки claude.ai выгружать в «переписка claude.ai <дата>.md» (как в делах), не держать только в чате.
- **Когда скилл ошибся — дописать «грабли» в сам скилл.** Подтверждение из исследования JIT-Agent: та же модель с
  хорошей «обвязкой» (память, план, инструменты, скиллы), которую чинят по ошибкам, обошла более сильные модели и
  потратила на 36% меньше (LLMScience/1064, пост 387, 30.08). Хороший скилл важнее «модели посильнее».

## Рабочие правила из изученного 14.10 (первоисточники открыты — `tg_monitor/study_1410/out_*.json`)

**Шаблон задачи помощнику (во всех скиллах):** цель → входные файлы → граничные случаи → что запрещено → «готово = …» и куда
положить → «если чего-то нет (файл, ключ, сайт) — назови точно и остановись, не подменяй и не угадывай» (Claude Projects docs) →
не больше двух попыток. Effort средний; провал лечить уточнением задачи, потом уровнем (замер share-md: low/medium/high на
задачах с тестом дают одинаковое качество, medium дешевле всех; правка 3 промптов подняла 11/15 → 15/15).
Простое массовое (разрезать, слить json, пересказ, классификация) — `model: haiku` (Haiku 5.5: $0,10 за млн входа против $2 у Sonnet;
на сложном коде слабее — 39% против 71% Terminal-Bench), сверив одну пачку.

**Проверка:** исполнитель не принимает свою работу (zeroshot) — проверяет скрипт (лучше) или отдельный агент с чистым контекстом
и списком критериев. Переписал скрипт — старый и новый на одних данных, «совпало M из M» + канарейка: одна намеренная поломка
должна покраснить проверку (Anthropic code-modernization). «Проверка прошла» ≠ правильно (arXiv 2610.08144): подложить
неверный пример + 2–3 значения пересчитать независимо. Пример: `tg_monitor/check_razbor.py`, повторы `tg_monitor.fetch_page`.

**Перед кодом — лестница** (ponytail): нужен ли код вообще → есть ли в проекте → стандартная библиотека → готовая зависимость →
минимум. Сначала прочитать затрагиваемый код. Упрощение — комментарий `shortcut:`. Починка — только после найденной причины;
**3 неудачные попытки → стоп и доклад ей** (gstack).

**Кэш (официальная дока code.claude.com/docs/en/prompt-caching):** кэш = совпадение начала запроса. Сбрасывают: смена модели,
добавление/удаление MCP, `/compact`, скилл с `model:` во frontmatter (не ставить без нужды). Правка CLAUDE.md посреди сессии не
применяется до `/clear`. Проверка — `/usage`, строка Prompt cache.

**Две модели в одном разговоре (дока code.claude.com/docs/en/advisor и model-config, проверено 16.10.2026):**
`opusplan` (`/model opusplan`) — Opus только в режиме плана, дальше сам переходит на Sonnet; смена модели на границе плана
сбрасывает кэш. `/advisor opus` (экспериментальный, подписка — в счёт лимита) — главная модель Sonnet делает рутину, а Opus
зовёт сама в трудных местах: перед выбором пути, при повторяющейся ошибке, перед «готово». Кэш НЕ сбрасывает; обычно дешевле,
чем Opus всё время. Пара Opus + Opus-советник — только для очень важного (дороже). Выключить — `/advisor off`.

**Claude Design: claude.ai/design работает до 14.12.2026** — дизайн-системы перенести со страницы Artifacts заранее; чаты и комментарии
не переносятся (статья Anthropic Dashboards & Motion). Docs/Slides/Design — на всех тарифах; Motion — только Team/Enterprise.

**Не ставить:** Quotio, CLIProxyAPI (прокси-ротация аккаунтов — бан); gstack целиком (его setup правит ~/.claude/settings.json и
CLAUDE.md, ставит Bun и Chromium) — только приёмы выше; zeroshot (пишет в ~/.claude, использует логин). Ссылки канала
`t.me/sIivaker/...` — подделка адреса slivaker («I» вместо «l»), пиратские архивы 4–7 ГБ — ничего не качать.

**Память по Карпати:** хороший ответ по теме — сохранять страницей знаний, а не оставлять в чате; раз в 2–3 недели — проверка
памяти и скиллов на противоречия и устаревшее (скилл znaniya).

## Экономия лимита и кэша

- **Гайд OpenAI по GPT-6 (прочитан 12.10 в Chrome, PushEnter/13792) — то же верно для Claude:** постоянные инструкции и
  справочники ставить В НАЧАЛО, меняющиеся детали — в конец (иначе кэш не срабатывает, а кэш до 95% дешевле);
  чрезмерно подробные инструкции новым моделям вредят; в описании скилла коротко «когда запускать», подробности
  подгружать по нужде; вместо «всегда спрашивай» — явные границы: что можно самой, что только с одобрения;
  «готово» = изменить, запустить, проверить, устранить сбои; мерить цену одной успешной задачи, а не одного запроса.
- **Кэш на подписке живёт 1 час** (на API-ключе — 5 минут; уточнено 07.10 по блогу Anthropic «Maximizing the value
  of your Claude Code sessions» и документации строки состояния: `prompt_cache.ttl = "1h"`). Пока кэш тёплый,
  продолжение дешёвое (чтение из кэша ≈ 5–10% цены); после паузы дольше часа весь разговор читается заново по полной
  цене. Пауза была долгой и сессия длинная — дешевле новая сессия (правило «перед большой задачей — перезапусти»).
  **Видно в строке состояния** (внизу Claude Code, поставлена 07.10): «кэш тёплый ещё N мин» / «кэш остыл ❄».
  Мод Cache Control показывает полоску кэша и шлёт напоминания (vibecoding_tg/4012, пост 851, 04.10).
  Когда будет время: `npx claude-code-templates@latest --mod observability/prompt-cache-control` — сторонний пакет,

## Две темы из вебинара ШВМ «AI-агенты» (19.10.2026; курс за 120 000 ₽ не берём — её решение)

Источник — бесплатный вебинар Василия Исаева (Wildberries), youtu.be/1QI6LTKdwmw; субтитры прочитаны целиком.
- **Проверка качества (evals) — пять поломок, которые «выглядят нормально»** (ответ правдоподобный, ошибки не видно):
  1) ИИ там, где хватит обычного запроса/скрипта — дороже и хуже; 2) устаревшие данные в источнике — цифра похожа
  на правду, но старая; 3) инструмент вернул пусто или ошибку, а модель всё равно назвала цифру (частая «починка»
  вайб-кодом: `except` молча возвращает значение) — ошибку не глушить, писать «данных нет»; 4) нет запасного пути
  (модель недоступна, лимит, прокси) — нужны повтор и запасная модель; 5) длинный разговор вытеснил цель — держать
  цель задачи отдельно и сжимать историю. Плюс личные данные: ушли в чужую модель — уже нарушение.
  Для нас: набор проверок = прошлые её жалобы («бот промолчал», «старую версию резюме переделал», «нового нет», когда
  лента не прочиталась) — каждую превратить в случай «вход → правильный итог» и прогонять после правок скилла/бота.
- **Стоимость запусков — «не разориться»**: каждое следующее сообщение тащит весь прошлый контекст и подтянутые
  документы, поэтому цена растёт с длиной разговора. Правило: модель — достаточно сильная, контекст — маленький,
  длинные разговоры вовремя сжимать (`/compact`, новая сессия), кнопки — дешёвым моделям (уже наше правило).
  Учёт: смотреть стоимость/токены каждого долгого прогона (`/cost`, `runs\` авторазбора), а не только виджет лимитов.

### Как писать скиллы и CLAUDE.md (writing-for-agents, Matt Pocock — выжимка, навык не установлен)

- **Описание скилла = «указатель».** Его формулировка, а не содержимое, решает, когда агент дойдёт до материала.
  Главное слово — в начало; один триггер на один отдельный случай (синонимы одного случая — сжать в один).
- **Две нагрузки:** всё, что загружено всегда (строка CLAUDE.md, описание скилла), стоит токенов в каждом ходе.
  Подробности — в отдельный файл за указателем; в главном файле — то, что нужно каждому сценарию.
- **Шаги и справка.** Шаги (что делать по порядку) — наверху; справка — ниже или в отдельном файле. Определение,
  правила и оговорки одной темы — под одним заголовком, не размазывать.
- **У каждого шага — признак «готово»**, проверяемый и полный («учтена каждая изменённая модель», а не «сделай список»).
  Размытый признак → агент «закругляется» раньше времени.
- **Говорить, что делать, а не что нельзя:** запрет тянет запрещённое в контекст. Запрет — только как жёсткий
  ограничитель и всегда в паре с правильным действием.
- **Одна мысль — одно место** (без дублей); то, что видно из файлов/`--help`, не переписывать в скилл — держать только
  неписаные правила и «грабли».
- **Удалять «пустые» строки:** инструкция, которую модель и так выполняет, ничего не меняет — удалить предложение целиком.
  Слабое слово («будь внимателен») заменить сильным понятием, а не добавлять текст.
- **Короткие «опорные слова»** вместо длинных повторов (как «грабли», «готово = …» у нас) — модель держит их как понятие.
Применять при «Уборке инструкций» (пункт выше про промпт Pocock) и при каждом новом скилле.

### Готовые блоки из гайда Fable 5.1 (platform.claude.com, prompting-claude-fable-5-1) — для субагентов и промптов
- **«Доделай до конца»** (против «Хотите, я…?» и «Дальше я сделаю…»), суть: «Ты работаешь автономно; для обратимых
  действий, вытекающих из задачи, — не спрашивай; стоп только перед разрушительным или сменой объёма. Перед концом
  хода проверь последний абзац: если там план/список шагов/обещание — сделай это сейчас». Это наш CLAUDE.md-правило
  «продолжай сама» — для промптов субагентам вставлять его.
- **«Объём = задача»**: найденную по пути чужую ошибку не чинить, а записать в итог как «на потом»; при неясности —
  самое прямое прочтение + назвать допущение.
- **Точечные правки**: «минимизируй токены на правку файла — правь точечно, а не переписывай весь файл».
- **Инструкция для сжатия** (`/compact …`): сохранить (1) проблемы и как решены, (2) варианты — что пробовали и
  почему отложили, (3) решения/запреты/предпочтения — дословно, (4) где мы сейчас, (5) что открыто, (6) имена, цифры,
  даты, ссылки — точно; её слова — близко к тексту, свои рассуждения — сжато. Короткий вариант:
  `/compact сохрани дословно её решения и запреты, цифры, ссылки, что сделано и что осталось`.
  После сжатия — проверочный вопрос «какие ограничения и что уже сделано/отправлено?»: ловит потерянные указания
  и дубли отправок (курс CMU 11-768, kursy-konspekty).
- **Чек-лист длинной задачи** (Vercel, kursy-konspekty): статусы `[ ] / [>] / [x]`, `[>]` только один; в новой
  сессии старый `[>]` сначала перепроверить, а не продолжать вслепую.
- **«Вычурная проза»**: если текст тяжёлый — «Убери вычурные обороты; где есть прямое слово — пиши его».
- Названия из быстро меняющихся областей (модели, инструменты ИИ) — сначала искать, а не отвечать по памяти.

### Сколько стоит задача и как экономить (claude.dev «What a task costs on Opus 5.5», «Spending your effort»; блог «Maximizing … sessions»)
- Цена = **число ходов** (каждый ход заново несёт всю историю) × доля кэша + выход (×5 к входу, включая размышления).
  Самый дешёвый ход — ненужный. Кэш 90% против 0% — разница в 7 раз.
- **Кэш ломается**: смена `/model`, смена `/effort`, переключение fast mode, подключение/отключение MCP посреди
  задачи, пауза дольше часа. Не ломают: `/rewind` (Esc Esc), `/compact`, новые результаты в конце.
- **Effort**: low — механика (переименовать, по образцу), medium — обычная работа (наш default в settings),
  high — когда medium буксует, баги, где важны крайние случаи (+~20 тыс. токенов размышлений ≈ одна переделка),
  max — автономные большие задачи. Выше effort ловит пропущенные крайние случаи, но **не чинит неверный подход**.
  Схема для фич: спецификация → «задай мне вопросы» → сделать на low → проверить и довести на high.
- Дать модели способ проверить себя (скрипт-проверка, тест, счётчик «совпало N из M») дешевле, чем поднимать effort.
- Команды: `/usage` в конце задачи — токены, доля кэша, цена; `/rename` перед `/clear`, если сессия ещё нужна;
  `/compact <что сохранить>` — до перерыва, пока кэш тёплый; `/mcp` — отключить лишние серверы в начале сессии.
  `MAX_THINKING_TOKENS=0` — сессия без размышлений для рутины; `BASH_MAX_OUTPUT_LENGTH` — потолок вывода команд.
- Модели: Haiku/Sonnet — поиск, чтение логов, субагенты (`model: haiku` в описании агента); Opus 5.5 — каждый день;
  Fable 5.1 (в 2,5 раза дороже) — только если Opus дважды не справился. `/loop` в главной сессии не крутить.

### Проверка скиллов: `claude plugin eval` (code.claude.com/docs/en/plugin-evals)
- Только для плагинов; для одиночного скилла — skill-creator со своим `evals/evals.json` (форматы не совместимы).
- `claude plugin eval init` — Claude сам расспросит, что такое хороший итог, предложит случаи и проверки;
  `claude plugin eval . --case <имя> --runs 1 --ablation none` — пробный дешёвый прогон;
  `--max-cost-usd 5` — потолок трат (по прейскуранту, не по подписке). Проверки `regex`, `tool_used`,
  `file_exists` бесплатные; `llm`/`baseline` вызывают модель-судью. Частая находка: дельта ≈0 и скилл не
  вызывается на обычных словах → править `description`.
- Для промптов в своих скриптах на API: `/claude-api build-eval` и `/claude-api hillclimb` (claude.dev «Automating
  eval design»): случаи из реальных ошибок, а не из «где модель сейчас падает»; разбивка train/test; провалы не
  вставлять в промпт дословно. Пример из статьи: поддержка 74%→99% точности и 4,6→1 ¢ за тикет.
- Из курсов (CMU 11-768 задание 2, Stanford CS329Z, Academy — kursy-konspekty): первые 20 тестов — из файлов памяти
  с её поправками (каждый = записанный провал); на каждый скилл 1 тест, где он **не должен** сработать; к тесту —
  эталонный итог, 3 из 3 провалов = сначала проверить сам тест; размеченные вручную 10–15 примеров, разобрать
  1 ложный успех + 1 ложный провал, «мутант», который проходит; сравнивать «со скиллом / без», одна правка за раз →
  те же 2–3 теста; ~8 прогонов, а не 1; задачи средней трудности (всегда 0 % или 100 % ничего не различают).
- Headless `claude -p --json-schema` — если разбор текста понадобится из Python-скрипта; в `-p` нет скиллов и
  CLAUDE.md, правила передавать в промпте; расписания не ставить (Academy Claude Code).
