## Мукминов «Claude Code» (5)


### Магазин одежды

- **Защита от параллельного повтора статусом «в работе».** Перед действием наружу (заказ посреднику, ответ в бот) ставить запись в статус «processing»; второй запуск такую запись пропускает; при ошибке статус возвращается в «pending». (стр. 107–108) → `shopify-admin`, `dela` (дополняет №4)

### Новости, данные, Claude Code

- **Периодические сбои — гипотезы списком.** «Раз в 2–3 часа бот отваливается, через 5 минут оживает. Мои версии: 1) Happ переключает сервер, 2) Drive ограничивает частоту, 3) утечка памяти. Составь план диагностики». Модель проверяет по очереди, а не гадает. (стр. 113) → `dela`, `tg-news`
- **Утечка памяти долгого процесса — 5 мест.** Обработчики, которые не снимаются; кэш без предела; замыкания, держащие большие объекты; глобальные списки, которые только растут (журнал запросов с заголовками); незакрытые соединения и браузеры. Для бота «Дела» и tg_monitor, если «через сутки всё тормозит». (стр. 108) → `dela`, `tg-news`
- **Бот «Дела»: автораскладка словарём + кнопки.** Словарь «слово → дело» (фамилии, номера дел, суды); совпало — положить и ответить подтверждением с кнопками «Отменить / Другое дело»; не совпало — кнопки выбора дела. Не ломает правило «раскладываю я по её подписям» — это подсказка, решение за ней. (стр. 210–211) → `dela`
- **Проверка живости бота в три уровня.** «Процесс жив» / «готов работать» (доступны Telegram API, Drive, есть место на диске) / «последнее сообщение обработано в HH:MM». (стр. 178) → `dela` (дополняет №12)

## Grewal «Marketing», гл. 9–13 (1)


### Frivent / B2B

- **Никаких договорённостей о ценах с конкурентами.** Даже «давайте не падать ниже X» с другими подрядчиками — сговор (Apple + издатели заплатили $450 млн). (стр. 342–343) → b2b-sbor, dela

## Dickey «Mastering Claude AI» (6)


### Frivent / B2B

- **Красные флаги в договоре (дополняет пункт про договоры в первом конспекте).** В договорах с поставщиками оборудования, подрядчиками и посредником искать отдельно: одностороннее расторжение; автопродление; механизм роста цены; пункты для торга; что снижает риск. (гл. 11, стр. 197) → b2b-sbor, dela

### Новости, данные, Claude Code

- **«Что здесь часто меняется?»** При вопросах о законах, пошлинах, правилах площадок спросить: какие части этого часто меняются; по каким поисковым словам найти официальный текст; какие детали надо сверить по месту (штат, регион). Зачем — модель сама размечает, что устарело в её памяти. (гл. 16, стр. 275) → dela, dropship-lessons
- **Сначала каркас, потом содержание.** В длинном документе (иск, лендинг, отчёт) первой просьбой: «дай сначала структуру, содержание наполним по разделам». Каркас она утверждает до текста. (гл. 13, стр. 226) → dela, site-design
- **Только нужное для задачи (дополняет пункт об обезличивании).** Передавать модели только те поля, которые нужны для этой задачи: для расчёта госпошлины — сумму и вид иска, без ФИО и адресов. Больше деталей не значит лучше, если это бьёт по приватности. (гл. 17, стр. 288) → dela
- **Шаблоны делового контекста при ложном отказе (дополняет №12).** Четыре заготовки: деловой анализ («как [должность] в [тип компании] готовлю [документ] для [законной цели]; он поможет решить [вопрос]»); техническая документация; учебная программа; научная работа. Полный текст — в «Моделях». Держать как библиотеку «что отказали и что сработало». (стр. 274–279) → dela, pc-check, claude-code-priemy
- **Иногда делать без Claude.** Раз в неделю одну привычную проверку делать руками (открыть карточку 1688 и посчитать выкуп, вычитать иск без модели), чтобы не потерять навык и заметить, если инструмент начал врать. (гл. 17, стр. 290) → sourcing-1688, dela
