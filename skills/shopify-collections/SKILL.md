# Коллекции магазина: три типа сетов

Магазин — `www.artmellio.com` (`kmfmxn-r4.myshopify.com`), тема в репозитории
`github.com/viiiitaaaaa/artmellio-theme`. Подробности темы — в памяти
`shopify-magazin-dekora`.

Один товар участвует **одновременно в нескольких коллекциях** — это требование ТЗ,
а не побочный эффект. Поэтому вся раскладка держится на тегах, а коллекции
собираются автоматически по условиям.

## Система тегов товара

Теги — единственный источник правды. Ставятся на товар в админке или импортом CSV.

| Префикс | Назначение | Примеры |
|---|---|---|
| `style:` | интерьерный стиль, один или несколько | `style:neo-japandi`, `style:quiet-luxury` |
| `room:` | комната | `room:bathroom`, `room:kitchen`, `room:bedroom`, `room:hallway`, `room:living` |
| `cat:` | категория предмета | `cat:dispenser`, `cat:vase`, `cat:mirror`, `cat:towel`, `cat:tray`, `cat:candle` |
| `set:` | принадлежность конкретному сету | `set:bath-neo-japandi`, `set:aroma-ritual` |
| `mat:` | материал | `mat:marble`, `mat:ceramic`, `mat:wood`, `mat:linen` |

Слаги стилей — ровно эти десять, они же классы в `assets/decor-shell.css`:

```
neo-japandi, warm-minimalism, organic-luxe, color-drenching, heritage-maximalism,
modern-mediterranean, quiet-luxury, sculptural, dark-academia, eclectic-collector
```

## Как определять теги по товару

**Теги подбирает Claude, не пользователь.** Пользователь не дизайнер и не обязан
различать интерьерные стили — он добавляет товары как есть, дальше работа Claude:
посмотреть карточки на витрине (`/collections/all`) и выдать готовый CSV для импорта
через `Products → Import`. Не просить пользователя проставлять теги руками и не
спрашивать «какой это стиль» — определять самому по фото и названию.

Первые четыре тега читаются с фото почти механически:

- `cat:` — что это за предмет. Из названия и формы.
- `mat:` — материал. Обычно прямо в названии (marble, ceramic, rattan) и виден на фото.
- `room:` — по сценарию использования. Дозатор геля → ванная, поднос для чая → кухня.
- `style:` — по палитре и форме, см. таблицу ниже.

Пятый, `set:`, — авторское решение: какие вещи собрать в связку. Механически не выводится.

### Опознание стиля по фото

| Признаки на фото | Стиль |
|---|---|
| натуральный камень, дерево, геометрическая простота, приглушённый серо-зелёный, ноль декора | `neo-japandi` |
| бежевый, кремовый, овсяный, мягкие скруглённые формы, матовая керамика | `warm-minimalism` |
| необработанное дерево, рогожа, глина, неровная фактура, земляные тона | `organic-luxe` |
| один насыщенный цвет на всём предмете, изумруд, винный, бутылочный | `color-drenching` |
| латунь, позолота, узор, бахрома, вензеля, сложный силуэт | `heritage-maximalism` |
| терракота, синий с белым, глазурь, средиземноморская керамика | `modern-mediterranean` |
| однотонный бежево-серый, дорогая простая форма, никакого логотипа | `quiet-luxury` |
| выразительная скульптурная форма, асимметрия, объём как главное | `sculptural` |
| тёмное дерево, кожа, бронза, книжные и кабинетные мотивы | `dark-academia` |
| смешение фактур, этнические мотивы, яркое пятно, коллекционный вид | `eclectic-collector` |

Сомнение между двумя стилями решается палитрой: тёплая гамма тянет к `warm-minimalism`
и `organic-luxe`, холодная и серо-зелёная — к `neo-japandi` и `sculptural`.

### CSV для импорта тегов

Shopify обновляет товары по колонке `Handle`. Минимальный файл — две колонки:

```csv
Handle,Tags
nordic-light-luxury-marble-lotion-bottle,"style:neo-japandi, room:bathroom, cat:dispenser, mat:marble, set:aroma-ritual"
```

Импорт **перезаписывает** теги целиком, а не дополняет — в файле должен быть полный набор.
Handle товара виден в его URL на витрине и в SEO-разделе карточки.

## Три типа коллекций

### Тип 1 — комнатный сет

Комната целиком в одном стиле. Товары **разных категорий**, объединённые комнатой и стилем.
Шаблон темы: `room-set`. Фильтры выключены — состав сета фиксирован. Сетка 3 колонки,
крупные карточки. Баннер показывает фото комнаты (изображение коллекции).

- Handle: `<комната>-<стиль>` → `bathroom-neo-japandi`
- Условия: `tag = style:neo-japandi` И `tag = room:bathroom`
- Объём: 6–15 товаров

### Тип 2 — категория в стиле

Вариативность моделей внутри одной категории. Товары **одной категории**, разные формы,
общая стилистика. Шаблон: `category`. Фильтры и сортировка включены, сетка 4 колонки,
квадратные кадры — глаз сравнивает формы.

- Handle: `<категория>-<стиль>` → `dispensers-neo-japandi`
- Условия: `tag = style:neo-japandi` И `tag = cat:dispenser`
- Объём: 8–20 товаров

### Тип 3 — мини-сет по применению

Маленькая законченная связка из 2–5 предметов **разных категорий**, связанных сценарием
использования, а не комнатой. Шаблон: `capsule`. Фильтры выключены, сетка 3 колонки,
баннер показывает flat-lay сцену.

- Handle: `<имя-капсулы>-<стиль>` → `aroma-ritual-neo-japandi`
- Условия: `tag = set:aroma-ritual` (один тег — состав задаётся вручную)
- Объём: 2–5 товаров

**Ключевое отличие от типа 1:** мини-сет не привязан к комнате. «Ароматический ритуал»
живёт и в ванной, и в спальне. Если связка осмысленна только в одной комнате — это тип 1.

## Как завести коллекцию

**Коллекции заводятся через Admin API** — доступ есть, см. скилл `shopify-admin`.
Рабочий скрипт рядом: `make_collections.py` (список коллекций в начале файла,
`collectionCreate` с `ruleSet`, `appliedDisjunctively: false`). После создания
**обязательно опубликовать** в каналах Online Store и Shop через `publishablePublish`,
иначе коллекция существует, но на витрине отдаёт 404. Счётчик товаров считается
асинхронно: сразу после создания он показывает 0, это нормально.

Ручной путь ниже оставлен для случая, когда правок одна-две и лезть в скрипт лень.

Создание коллекций требовало доступа к Admin API, которого раньше не было. Поэтому
коллекции заводит пользователь в админке, а Claude готовит точные значения полей.

1. `Products → Collections → Create collection`
2. **Title** — человеческое название
3. **Collection type: Automated**, условия — теги из таблиц выше, режим «all conditions»
4. **Description** — короткий текст, 2–3 предложения (промт ниже)
5. **Theme template** справа внизу — выбрать `room-set`, `category` или `capsule`
6. **Image** — для типов 1 и 3 обязательно: интерьер комнаты или flat-lay сцена
7. Проверить **handle** в разделе SEO: он обязан содержать слаг стиля

Пункт 7 критичен: цвет коллекции подхватывается **по слагу стиля в handle**.
`bathroom-neo-japandi` → страница получает акцент `#3A3D38` и подложку `#E6E6E3`.
Без слага коллекция останется графитовой.

Для товара работает второй путь: тег `style:<слаг>` красит страницу товара.
Логика — в `layout/theme.liquid`, перед `<body>`.

## Промт для описаний коллекций

Описание коллекции — это витринный текст, а не пересказ характеристик. Держать 2–3
предложения, писать от впечатления в интерьере, без маркетинговых штампов
(«идеальное решение», «стильный акцент», «не оставит равнодушным»).

```
Напиши описание коллекции интернет-магазина декора для дома.
Стиль интерьера: <название стиля>.
Тип подборки: <комнатный сет | категория в едином стиле | мини-сет по применению>.
Состав: <перечень предметов>.

Требования: 2-3 предложения, русский язык. Первое предложение — про ощущение
от вещей в интерьере, второе — про материалы и свет, третье (для сетов) — как
предметы работают вместе. Без превосходных степеней, без слов «идеальный»,
«стильный», «уникальный», «премиальный». Не перечислять товары списком.
```

## Страница комнатного сета: как она собрана

Референс — кадр интерьера во всю ширину сверху, под ним заголовок и описание,
дальше сетка товаров. Собирается секцией `sections/collection-room-hero.liquid`,
она подключена в `collection.room-set.json` и `collection.capsule.json` вместо
двухколоночного `main-collection-banner` из Dawn.

Настройки секции: показывать фото, кадр (`full` — целиком / `cover` — обрезать
по высоте с выбором привязки), высота фото, выравнивание текста, описание,
число товаров, цветовая схема.

Рабочие значения шаблона `room-set`, проверенные на витрине:

| Параметр | Значение | Почему |
|---|---|---|
| `image_fit` | `full` | кадр видно целиком; `cover` съедает верх и низ сцены |
| `text_alignment` | `left` | заголовок встаёт по левому краю сетки |
| `columns_desktop` | 3 | как в референсе |
| `image_ratio` | `square` | без него ряды прыгают по высоте |
| `enable_filtering` / `enable_sorting` | `false` | состав сета фиксирован |
| `padding_top` (сетка) | 0 | иначе провал между описанием и товарами |

Ширина оболочки — `--page-width: 152rem` в `assets/decor-shell.css` плюс
`.page-width { padding: 0 4rem }` на десктопе. Было 128rem — контент выглядел
узкой колонкой посреди экрана.

Карточки в `decor-shell.css` растянуты на высоту строки сетки, блок кнопки
прижат `margin-top: auto`, название обрезано двумя строками — иначе «Sold out»
и «Choose options» встают на разной высоте.

Шапка: `header-group.json`, `sticky_header_type: always` (закреплена всегда),
секция `announcement-bar` удалена целиком — «Welcome to our store» из Dawn.

## Как загрузить баннер коллекции

Кадр готовить шириной 2400px, соотношение около 1.85:1 (широкий, пол подрезан).
Резать надо низ, а не бока: по бокам стоят товары сета (душ, ванна).

Порядок в новом UI коллекции:

1. Карточка коллекции → меню на изображении → «Изменить изображение».
2. В пикере — **поиск файлов по имени**. Плитки сортируются по алфавиту, и старый
   `banner-...jpg` стоит раньше `banner-...-v2.jpg`; клик «по первой плитке»
   ставит старый файл. Отсюда правило: имя файла версионировать и искать по нему.
3. Чекбокс в углу плитки → «Готово» → «Сохранить» в верхней плашке.

## Замена первого фото товара на свой кадр

Превью в сетке — это **первое** изображение товара. Меняется так: загрузить кадр
в медиа товара и перетащить его на первую позицию (у Shopify нет кнопки
«сделать основным» — только drag-and-drop), затем «Сохранить».

Рабочий скрипт — `scratchpad/step.py`, шаг `do <product_id> <файл>`:

1. `admin.shopify.com/store/kmfmxn-r4/products/<id>`, ждать ~10 с.
2. **Дождаться `input[type=file]`** — блок медиа догружается позже страницы,
   иначе `set_input_files` падает по таймауту (ловилось на трёх товарах из десяти).
3. `set_input_files(файл)`, ждать появления плитки (до 80 с).
4. **Раскрыть свёрнутые плитки**: при большом числе медиа сетка прячет остаток
   под кнопкой `+N`, и новая плитка в DOM отсутствует — кликнуть по `+N`.
5. `scrollIntoView({block:'center'})` по первой плитке — без этого координаты
   уходят в минус и перетаскивание бьёт мимо.
6. Найти **свою** плитку по имени файла в `src` (Shopify сохраняет имя:
   `nw_buddha.png`), а не «последнюю в DOM» — порядок DOM не совпадает с видимым.
7. Тащить мышью: `down` → 3 микросдвига (dnd-kit включается только после порога) →
   40 шагов по 45 мс → дрожание над целью → `up`. Цель — центр первой плитки минус 40px.
8. `Сохранить`; если кнопка неактивна — порядок не изменился, повторить.

Id товара берётся из `products.json` витрины — он совпадает с id в админке.
Проверять результат тоже по `products.json`: `images[0].src` должен содержать
имя файла.

Соответствие кадров товарам (папка `Desktop\japandi_white\1\comfy`):
`60` — колонка, `nw_buddha` — статуя, `nw_curtain` — шторка, `nw_faucet` — смеситель,
`nw_lamp` — бра, `nw_moss` — мох-панно, `white_02` — набор с диффузором,
`white_04` — зеркало, `white_11` — квадратные дозаторы, `white_13` — полотенцедержатель,
`nw_shower` (копия `Снимок.PNG`) — душевая система.

**Кадры берутся только из `Desktop\japandi_white\1\comfy`.** В `Desktop\japan bathroom`
лежат черновые генерации с плоским фоном — они не подходят, хотя имена похожи
(`nw_shower_sq_00001_`). Файл с кириллицей в имени копировать под латинским именем:
поиск плитки идёт по имени файла в `src`.

### Удаление лишнего кадра из медиа

Плитка выделяется кликом по чекбоксу в её левом верхнем углу (появляется при
наведении), сверху возникает строка «Выбран 1 файл» и ссылка «Удалить».

- **Нельзя брать `get_by_role("button", name="Удалить").first`** — первой в DOM идёт
  кнопка удаления тега в правой панели. Такой клик снял с товара `style:neo-japandi`,
  и «Сохранить» это зафиксировало. Ссылку «Удалить» искать только внутри блока медиа,
  рядом со строкой «Выбран … файл»; в light DOM её нет — `bounding_box` возвращает
  `None`, надёжнее бить `page.mouse.click` по координатам со скриншота.
- **Не перебирать весь DOM с `innerText`** (`[...document.querySelectorAll('*')]`) —
  на карточке товара это вешает страницу до обрыва CDP-сессии.

### Совпадение имён кадров

Поиск своей плитки идёт по подстроке в `src`, поэтому `nw_shower` совпадает и с
`nw_shower_sq_00001`. Скрипт решает, что нужный кадр уже первый, и ничего не делает.
Сравнивать по `startsWith` полного имени с размерным суффиксом (`nw_shower_800x800`).

### Координаты плиток

`getBoundingClientRect` отсчитывается от viewport: при высоте окна 1000 px плитка с
`y > 1000` не кликается, перетаскивание уходит в пустоту. Перед drag всегда
`scrollIntoView({block:'center'})` по первой плитке и пересчёт координат обеих.

## Грабли

- **Handle без слага стиля** — коллекция теряет цвет и выглядит как оболочка. Проверять
  в SEO-разделе: Shopify генерирует handle из Title, и русское название даст транслит
  без слага. Handle задавать вручную латиницей.
- **Automated-коллекция с режимом «any condition»** соберёт всё подряд по одному тегу.
  Для типов 1 и 2 всегда «all conditions».
- **Пустая коллекция не видна** в навигации, но существует. Если товаров ещё нет,
  сначала заводить теги на товарах, потом коллекции.
- **Шаблон не выбран** — коллекция откроется дефолтным `collection.json` и потеряет
  особенности типа (фильтры, число колонок, фото-баннер).
- **Тип 3 нельзя собрать условием по стилю и категории** — состав произвольный,
  поэтому только ручной тег `set:`.
- **Сокращённая запись `padding` в секции убивает боковые поля `.page-width`.**
  `padding: 4.8rem 0 2.4rem` обнулила боковой отступ, и заголовок уехал на 40px
  левее сетки. Писать только `padding-top` / `padding-bottom`.
- **`"class": "section"` в схеме секции** добавляет вертикальные отступы Dawn —
  между описанием и сеткой появляется провал. Для баннера сета класс не нужен.
- **`image_ratio: adapt`** оставляет кадры в родных пропорциях: ряды разной высоты,
  вид «кривой». Для сетов всегда `square`.
- **JSON шаблонов нельзя сохранять через PowerShell `Set-Content -Encoding utf8`** —
  добавляется BOM. Писать Python-ом с `encoding="utf-8"` (читать `utf-8-sig`).
- **Тема тянет коммиты из GitHub с задержкой** — обычно 2–5 минут, иногда 10–15,
  а отдельный коммит может проскочить мимо; тогда помогает ещё один пуш.
  Проверять не глазами, а запросом: скачать `decor-shell.css` со страницы и
  поискать в нём новое правило. Редактор кода в админке для GitHub-темы закрыт.
- **Замерять вёрстку, а не смотреть на скрин**: `getBoundingClientRect` для
  `.room-hero__title` и `.product-grid` сразу показывает расхождение краёв.

## Работа в админке через Dolphin

Профиль **859648353**. Если он уже открыт вручную, Local API отдаёт 500
`E_BROWSER_RUN_DUPLICATE` — сначала `stop`, потом `start?automation=1`,
порт брать из ответа.

- `page.screenshot` в админке виснет на «waiting for fonts» — снимать через
  CDP `Page.captureScreenshot`.
- Описание коллекции живёт в TinyMCE-iframe (`about:srcdoc`,
  `body.mce-content-body`); плоская `textarea[aria-label="Описание коллекции"]`
  скрыта и `fill` по ней падает. Кликнуть в тело iframe и печатать туда.
- **Нельзя печатать `keyboard.type` в основной документ админки** — буквы
  срабатывают как глобальные горячие клавиши и уводят на другую страницу
  (у меня так открылось создание блога и пустая карточка коллекции).
- Клик по кнопке в модалке Polaris иногда не проходит из-за тоста поверх —
  бить `page.mouse.click` по координатам.
- **Вешать обработчик диалогов**: `page.on("dialog", ...accept())`. При переходе
  с несохранёнными изменениями браузер спрашивает «покинуть страницу?», и без
  обработчика падает весь скрипт (`Connection closed while reading from the driver`).
- **Cloudflare-челлендж** («Подтвердите, что вы человек») выскакивает после серии
  быстрых действий. Клик по чекбоксу координатами проходит, но начатое до него
  сохранение теряется — проверять результат и повторять шаг.
- **Повторный запуск шага загрузки создаёт дубль кадра** в медиа товара. Перед
  загрузкой проверять, нет ли плитки с таким именем файла.
