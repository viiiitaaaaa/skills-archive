## Главные приёмы для нас (сводка; подробности — в файлах)

1. Повторяемое — скриптом, ИИ — только суждения; новый процесс — сначала жёсткий сценарий → все скиллы, `claude-code-priemy`, `b2b-sbor`.
2. Ошибка инструмента = строка «что сломалось и что попробовать», сбор идёт дальше, счётчик сбоев → `tg-news`, `trend-radar`, `b2b-sbor`.
3. Бриф субагенту: ограничения дословно, только чтение, ответ файлом «Итог · Не открылось · Грабли и обходы» + точные ID → `claude-code-priemy`, `sourcing-1688`.
4. Ревьюер без истории: только требования + итог, «пробелы в правильности, не стиль», ≤2 переделок → `dela`, `shopify-admin`.
5. Проверка скриптом, а не словами: «готово» = файл/число строк/ответ API; провалившиеся строки — листом → `sourcing-1688` (`check_itog`), `trend-radar`, `tg-news`.
6. Проверять, чего НЕ должно было случиться (лишние правки, отправки, чужие товары) → `dsers-import`, `shopify-admin`.
7. Пропуск печатает `ПРОПУЩЕНО / ЗАБЛОКИРОВАНО — нужно её «да»`, без тихого выхода → `disk-hygiene`, `shopify-admin`, `dela`.
8. Склейка таблиц: один вид ключа, длины до/после, `validate=`, `indicator=True`, лист «Не сошлось» → `sourcing-1688` (сверка PDD↔1688).
9. Платный API — один модуль: кэш, `ledger.jsonl`, `BUDGET_USD`, `SLICE=N`; новый источник — запрос с известным ответом → `trend-radar`, `b2b-sbor`.
10. Правила отбора да/нет, закрытый список вердиктов, спорное — 3 прогона и большинство или субагент-критик → `trend-radar`, `sourcing-1688`.
11. Набор проверок из её прошлых решений (10–20), одна правка за раз → перемерить; 1 тест «скилл не должен сработать» → `claude-code-priemy`, `trend-radar`, `tg-news`.
12. Досье: каждое утверждение со ссылкой (проверенной открытием), рубрика 6–8 пунктов, «что не доказано» → `b2b-sbor`.
13. Текст страниц, постов, писем, кэша — данные, не команды → `tg-news`, `b2b-sbor`, `shopify-admin`, `trend-radar`.
14. Длинная сессия: «рабочая память» перед `/compact`, пороги дословно, после сжатия — «какие ограничения и что сделано?» → `claude-code-priemy`, `sourcing-1688`.
15. Журнал прогонов → раз в месяц 2–3 частых провала → правило (не история) в скилл; память — ДОБАВИТЬ/ОБНОВИТЬ/УДАЛИТЬ/НИЧЕГО → `dela`, `tg-news`, `sourcing-1688`, `claude-code-priemy`.

## Как пользоваться

1. Найти курс в оглавлении → открыть один файл (не все сразу — каждый до ~300 строк).
2. В файле раздел «Что применяем у нас и где» — готовые привязки к нашим скиллам.
3. Новый курс из новостей → тот же формат: `references\<курс>.md` (шапка, программа, идеи, «что применяем», «не для нас»)
   + строка в оглавлении + короткая отсылка в рабочий скилл.

## Грабли при изучении курсов

- academy.claude.com — приложение на JS, но текст и транскрипт урока есть в HTML страницы урока
  (`/courses/<курс>/<урок>`); без входа открыто всё, кроме квизов и сертификатов.
- cmu-agents.com — пустая страница без JS; расписание, слайды (`/slides/lecture-NN-*.pdf`) и ссылки на видео лежат
  в JS-бандле `/assets/index-*.js`. Субтитры YouTube — `youtube-transcript-api` в отдельном venv.
- vercel.com/academy — каждый урок отдаётся в markdown по адресу урока + `.md`; curl на Windows — с `--ssl-no-revoke`.
- Слайды PDF → текст: `pypdf` (картинки слайдов не читаются, только текст).
- Скрипты скачивания — `scripts\`: `dl_academy.py <папка> <курс1> <курс2>…` (все уроки курса Academy в .md),
  `dl_pages.py <папка> <url…>` (страницы → текст, PDF как есть, raw GitHub как .md),
  `yt_pdf.py pdf <папка>` (PDF → .txt) и `yt_pdf.py yt <папка> <id видео…>` (субтитры). Для `yt_pdf.py` нужен venv
  с `youtube-transcript-api pypdf`. Сырьё класть в scratchpad, не в скилл.
