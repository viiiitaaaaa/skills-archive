## Gulli «Agentic Design Patterns» (13)


### Новости, данные, Claude Code и агенты

- **Задание субагенту = «договор подрядчика».** Каждое поручение субагенту/Hermes писать как контракт: что сдать (файл, путь, формат), источники, объём, критерии приёмки, лимит времени/стоимости. Совпадает с её правилом «готово = что лежит где». (гл. 19, стр. 318) → writing-for-agents
- **Слово-сигнал «готово» у критика.** Критик отвечает одной фразой (`CODE_IS_PERFECT` / `ВСЁ_ВЕРНО`), если замечаний нет, иначе — списком; цикл максимум 3 круга. Зачем — простая автоматическая остановка и нет вечного цикла. (гл. 4, стр. 71–72) → writing-for-agents
- **«Зона подготовки» для больших задач.** Для длинной задачи складывать бриф в папку-«досье» (`task-context/`: 01_BRIEF.md, код/данные, документы) и давать агенту ссылку на неё. Совпадает с её правилом «чеклист шагов отдельным файлом». (прил. G, стр. 412) → writing-for-agents
- **Промпты — как код, в git.** Промпты-роли (критик, проверяющий пересказ, классификатор новостей) хранить файлами в репозитории скиллов и версионировать. У нас это `claude-skills` + `sync_skills.ps1`. (прил. G, стр. 413; прил. A, стр. 375) → writing-for-agents
- **Перепроверять промпты при смене модели.** После обновления Claude/Hermes прогонять ключевые промпты на 2–3 старых примерах — поведение может поменяться. (прил. A, стр. 375) → writing-for-agents
- **Компоненты системного промпта агента.** Роль и цель; список инструментов с описанием; ограничения; инструкции процесса («сначала план, потом шаги»); 1–3 примера успешной траектории «мысль → действие → наблюдение». Шаблон для новых скиллов и агентов. (FAQ, стр. 482) → writing-for-agents
- **Инструкции вместо запретов.** В скиллах писать «делай так», а запреты оставлять только для безопасности и формата; много «не делай» сдвигает модель на избегание. (прил. A, стр. 350) → writing-for-agents
- **Глаголы действия в начале задачи.** Начинать поручение с конкретного глагола (Извлеки, Классифицируй, Ранжируй, Сведи, Перепиши), а не «подумай о…». (прил. A, стр. 350) → writing-for-agents
- **«Агент как инструмент».** Узкую роль (генерация картинки, поиск по 1688) оформлять агентом, которого главный вызывает как инструмент с понятным описанием «когда звать». Описание инструмента = description скилла: от него зависит, позовут ли. (гл. 7, стр. 126–128) → writing-for-agents
- **Карточка агента = описание скилла.** Как в Agent Card: имя, что умеет, примеры запросов, теги — так писать frontmatter скиллов (триггеры = examples). (гл. 15, стр. 233) → writing-for-agents
- **Утечка инструкций в ответ.** Следить, чтобы в итоговых текстах для неё/клиентов не было внутренних пометок агента (имена инструментов, служебные правила); для критичных текстов — отдельный шаг «чистовой ответ». (FAQ, стр. 482) → writing-for-agents
- **Шаг «назад» перед задачей.** Сначала спросить модель об общих принципах («что делает хорошее описание юбки для 28+?»), потом подать ответ как контекст в конкретную задачу. Сильнее для творческих текстов. (прил. A, стр. 362–363) → writing-for-agents
- **Попросить модель улучшить промпт.** Если промпт иногда промахивается — дать его модели с описанием промаха: «предложи, как улучшить, чтобы стабильно…». (прил. A, стр. 372–373) → writing-for-agents

## Chip Huyen «AI Engineering» (7)


### Новости, данные, Claude Code и агенты

- **Три части промпта.** Описание задачи (роль, формат), примеры, сама задача. Описание — в начало (большинство моделей лучше), примеры — после; для Llama 3 — в конец. Так писать скиллы и промпты субагентам. (гл.5, стр. 418–420) → writing-for-agents
- **Мини-бенчмарк на свои инструкции.** Собрать 30–100 примеров под наши форматы (YAML, запрет «ты эксперт», русский язык ответа, длина) и прогонять новые модели/промпты по ним; книга прямо советует (IFEval). (гл.4, стр. 347) → writing-for-agents
- **Промпты — отдельными файлами с версиями.** Не зашивать в код; хранить `prompts/` с метаданными (модель, дата, приложение, автор) и в Git; правка общего промпта задевает всех, кто им пользуется — поэтому именованные версии. (гл.5, стр. 459–462) → writing-for-agents
- **Инструменты промпт-оптимизации — с осторожностью.** DSPy/Promptbreeder могут сами подобрать формулировку, но делают скрытые вызовы (сотни запросов), и опечатки в шаблонах дают тихие сбои; сначала писать вручную. (гл.5, стр. 454–459) → writing-for-agents
- **Итерации промпта — с метриками.** Версия, набор примеров, число — иначе нельзя сказать, стало ли лучше; улучшение одной подзадачи может ухудшить всю систему. (гл.5, стр. 452–454) → writing-for-agents
- **Снижать галлюцинации инструкцией и длиной.** «Отвечай максимально правдиво; если не уверен — скажи, что не знаешь»; короче ответ — меньше шансов выдумать; просить источник/цитату. (гл.2, стр. 225; гл.5, стр. 441) → writing-for-agents
- **Фильтры, а не судьи там, где можно.** Проверка длины, формата, обязательных полей, запрещённых слов — скриптом; судью-ИИ оставлять для смысла. (гл.3, стр. 253–258; гл.8, стр. 748) → writing-for-agents

## Babcock, Laschever «Ask for It» (2)


### Новости, данные, Claude Code и агенты

- **Бриф партнёра = бриф агента.** Книга перечисляет, что рассказать партнёру: общий контекст, заметки по ключевым вопросам, личность и восприятие, где трудно/легко, помехи. Это же чек-лист брифа для субагента-«оппонента». (гл. 13, стр. 240–241) → writing-for-agents

## Hur, Song «Build an AI Agent (From Scratch)» (8)


### Новости, данные, Claude Code и агенты

- **Промпт агента: «не двусмысленно — делай, неясно — минимальный вопрос».** Готовая строка для системных промптов наших агентов и бота: «When the user's intent is clear, execute immediately without confirmation. Only when intent is unclear, ask minimal questions to clarify.» Совпадает с её правилом «не спрашивать в конце». (гл. 2, стр. 52) → writing-for-agents
- **Описание скилла/инструмента = 4 части.** Отношение по умолчанию («используй сразу, не спрашивая»), триггер-фразы (явные, временные, неявные: «мы решили», «мой проект»), когда НЕ использовать, 1–2 примера «запрос → действие → ответ». Наши description скиллов уже содержат триггеры — добавлять «когда не использовать». (гл. 2, стр. 53) → writing-for-agents
- **Правило стажёра для своих инструментов и MCP.** Имя-глагол с объектом (`reserve_table`, не `book`), описание цели, типы, обязательные/необязательные поля, диапазоны и форматы (ISO-8601), enum вместо пар флагов. «Если стажёр поймёт по схеме — поймёт и модель». (гл. 3, стр. 74–76) → writing-for-agents
- **План с WHEN TO USE / WHEN NOT TO USE / HOW TO USE.** Для длинных заданий Hermes/субагентам — чек-лист `[ ] / [>] / [x]`, перегенерируемый целиком при каждом обновлении; в описании — когда план нужен (много шагов, сведение источников) и когда нет (один поиск, очевидная процедура). Наш CHECKLIST.md — то же самое; формат статусов взять отсюда. (гл. 7, стр. 224–228) → writing-for-agents
- **В задание с планом — вопросы, а не структура.** «Что мне нужно знать? В каком порядке эффективнее? Как пойму, что шаг закончен?» — три строки в начало любого задания с планом. (гл. 7, стр. 228) → writing-for-agents
- **Описания скиллов — коротко, ~50 токенов.** Расчёт книги: 100 инструментов × 500 токенов = 50 000 в каждом запросе; 100 скиллов × 50 токенов + 2 нужных × 2000 = ~9 000 (−80 %). Наши description скиллов часто по 100–200 слов — кандидаты на сокращение; подробности — в SKILL.md и references. (гл. 8, стр. 261–263) → writing-for-agents
- **Условие остановки цикла — проверяемое.** Для циклов «пишет → проверяет»: стоп по оценке ≥ порога, по слову-сигналу или «не меньше 3 кругов и текст > N» — плюс жёсткий максимум кругов. Ср. Гулли №37–38 — тут три готовых вида условий. (гл. 9, стр. 282–284) → writing-for-agents
- **Рубрики — PASS/FAIL, не 1–5.** В проверках (Hermes, тексты сайта, досье) каждый пункт — «прошёл/не прошёл» с цитатой проблемного места; итог PASS только если прошли все. Стабильнее и проще объяснить. Расходится с рубрикой 1–5 у Гулли (№21, 78) — справкой: для проверки — бинарно, для сравнения вариантов — попарно. (гл. 10, стр. 316–317) → writing-for-agents

## Dixon, Adamson «The Challenger Sale» (2)


### Новости, данные, Claude Code и агенты

- **«Намерение командира» (Commander's Intent) для агентов и Hermes.** В задании субагенту/Hermes писать цель и критерий «готово» + границы (что нельзя), а не пошаговый приказ; агент выберет путь сам, а мы проверяем итог. Согласуется с её правилом «сначала писать, каким должен быть итог». (стр. 196) → writing-for-agents
- **Гипотеза-прежде-проверки в заданиях агентам (Hypothesis-Based Coaching).** Перед проверкой результата агента выписать «как выглядит хорошо» (5–7 признаков) и сверять по ним; ответ агента — не «нравится/не нравится». PAUSE-вариант для разбора ошибок агента: подготовиться → договориться, что цель развитие → понять ожидаемое → назвать изменение → закрепить в промпте. (стр. 210–211) → writing-for-agents

## Dilts «Changing Belief Systems with NLP» (2)


### Новости, данные, Claude Code и агенты

- **Формулировать задачу агенту утвердительно, с проверяемым итогом.** Дилтс: “No outcomes stated in the negative” (стр. 62) и 5 условий хорошей цели (положительная, проверяемая по сенсорным данным, под контролем исполнителя, сохраняет полезное, вписана в окружение). Совпадает с нашим правилом «в задаче сначала писать, каким должен быть итог». (стр. 62; Прил. стр. 200) → writing-for-agents
- **Скрытые допущения в тексте (presupposition).** Врач ответил на «как поймём, что лекарство можно отменить?» — «когда перестанет работать»: внутри фразы заложено допущение «лекарство будет работать недолго». В промптах и описаниях инструментов проверять, не скрыты ли допущения, которые модель примет как факт. (стр. 27–28) → writing-for-agents

## Mollick «Co-Intelligence» (7)


### Новости, данные, Claude Code и агенты

- **Контекст и ограничения вместо «ты эксперт».** Ломать шаблонный ответ описанием задачи, аудитории, формата, ограничений и образцов; роль задаёт тон, но не добавляет ума («Act as Bill Gates» не помогает). (гл. 3, стр. 60–61) → writing-for-agents
- **Проверяемые шаги в промпте.** Разбивать задачу на шаги, где каждый результат виден и проверяем: «1) список вариантов 2) критика + ещё 3 3) таблица плюсов и минусов 4) выбор с объяснением» — так проще найти, на каком шаге испортилось. (гл. 7, стр. 140–141) → writing-for-agents
- **Пусть ИИ сам спросит, что ему нужно.** Для новой большой задачи начинать с «Я хочу сделать X; что тебе нужно знать, чтобы помочь?» (гл. 7, стр. 141–142) → writing-for-agents
- **Нейтральный деловой тон в задачах агентам.** Тон запроса задаёт роль (спорщик / преподаватель / аналитик); для агентов писать спокойно и по делу, без провокаций и эмоций. (гл. 4, стр. 76–78) → writing-for-agents
- **Не «упрощать» запрос под новичка.** Модель может давать менее точные ответы тем, кто выглядит неопытным; в задачах агентам указывать точные термины и уровень. (гл. 3, стр. 62) → writing-for-agents
- **Личная команда рецензентов.** Для её больших текстов (скилл, письмо, питч) прогонять три персоны: Озимандия (упростить), Мнемозина (неожиданные связи и истории), Стив (обычный читатель — где непонятно). (гл. 6, стр. 120–122) → writing-for-agents
- **Свой план — до черновика ИИ.** Для важного текста сначала набросать свои 3–5 тезисов, потом звать ИИ — чтобы не «заякориться» на его первой идее. (гл. 5, стр. 106–107) → writing-for-agents

## Whalen «Design for How People Think» (2)


### Новости, данные, Claude Code и агенты

- **Ловушки раскладки (в промпт агенту).** Прописать: «“не увидела / не нашла / ожидала увидеть” не кладём автоматически в Зрение — проверь Язык (не те слова) и Память (ждала в другом месте)»; «“love/hate” о конкретной функции — не обязательно Эмоция»; «“searched” — глазами или в строке поиска? уточни». ## Gabriel Wyner «Fluent Forever» (2)


### Новости, данные, Claude Code и агенты

- **Примеры в инструкциях для агентов — «comprehensible input».** Агенту, как ребёнку, нужен понятный ввод; простые конкретные примеры работают лучше абстракций. Аналогия наша. (гл. 5, стр. 112–113) → writing-for-agents
- **Один вопрос — один ответ в запросе к агенту.** Принцип «always ask for one correct answer at a time» применить к запросам: одна задача, один ожидаемый результат. (Галерея, стр. 174) → writing-for-agents

## O'Connor, Seymour «Introducing NLP» (3)


### Новости, данные, Claude Code и агенты

- **Мета-модель = чистка промптов и постановки задач агентам.** Прежде чем дать задачу Hermes/субагенту, пройти список: *Кто/что именно? Как именно? Сравнение с чем? Кто решает, что «хорошо»? Что значит "обработать"? (номинализация)* — размытые слова («собери всё», «разбери», «сделай лучше») заменить конкретными. Вписывается в `writing-for-agents`. (гл. 5, стр. 109–129) → writing-for-agents
- **«Нет вопросов "почему?"» в диагностике ошибок агента.** Спрашивать «как именно агент пришёл к этому выводу / что он видел», а не «почему он ошибся» (оправдания). (гл. 5, стр. 125) → writing-for-agents
- **Критерии-доказательства в заданиях.** Каждая задача агенту = цель + «по чему узнаю, что готово» + ограничения («экология»: что нельзя трогать). Совпадает с её принципом «сначала итог». (гл. 1, стр. 31–33) → writing-for-agents

### Новости, данные, Claude Code и агенты

## Alan Weiss «Million Dollar Consulting», 2016 (1)


### Новости, данные, Claude Code и агенты

- **Не путать занятость с результатом.** В отчётах агентов и табло фиксировать результат (что готово), а не число действий; «никому не платят за действия, платят за результаты». Использовать в формулировках итога задачи. (интерлюдия II ч.14) → writing-for-agents

## Minto «The Pyramid Principle» (3)


### Новости, данные, Claude Code и агенты

- **Задание агенту по SCQ + «готово = конечный продукт».** Промпт субагенту: ситуация (что уже есть), осложнение (что мешает), вопрос (на что ответить), и итог как конечный продукт («файл X с разделами Y»). Это совпадает с её правилом «сначала писать, каким должен быть итог». Когда — каждый Agent/Hermes-вызов. (гл. 2, стр. 35–36; гл. 7, стр. 117–121) → writing-for-agents
- **Шаги в скиллах — как действия с результатом.** Не «Проверить данные», а «Сверить цифры с оригиналом; результат — список расхождений в разделе X». Минто: если у шага нет видимого продукта, нельзя проверить, что шаги полные. Когда — при написании и чистке скиллов. (гл. 7, стр. 117–121) → writing-for-agents
- **Заголовки в SKILL.md — утверждения и параллельно.** Один уровень — одна грамматическая форма; не бывает одного подпункта; без «Общее/Введение». Когда — при правке скиллов. (гл. 10, стр. 195–196; гл. 4, стр. 59) → writing-for-agents

## Fitzpatrick «The Mom Test» (2)


### Новости, данные, Claude Code и агенты

- **Агенту — «что ещё я должна была спросить?».** В конце поручения агенту/субагенту добавлять пункт: «Что важного я не спросила, но надо было?» — аналог последнего хорошего вопроса книги; агент часто видит пропуск. (гл. 1, стр. 21) → writing-for-agents

(гл. 1, стр. 12, 14–19; гл. 2, стр. 28) → writing-for-agents

## Voss «Never Split the Difference» (2)


### Новости, данные, Claude Code и агенты

- **Лист подготовки для задачи агенту (адаптация One Sheet).** Для большого поручения агенту/Hermes: цель (что должно лежать где), резюме фактов, 3–5 рисков («что может пойти не так»), 3–5 проверочных вопросов к результату, неденежное (ограничения: не трогать X, без интернета). Формула: *"Prepare … a concise primer of nearly all our tactics and strategies"* — лист на 1 страницу. Соответствует правилу «сначала писать, каким должен быть итог». (Приложение, стр. 204–209) → writing-for-agents
- **Калиброванные вопросы в промптах агентам (формат «что/как», без «ты эксперт»).** Вместо «Сделай хорошо» — «Что считается готовым результатом? Как ты проверишь, что колонки в таблице совпадают? Что может сорваться?» Её правило: без «ты эксперт» и без «думай пошагово» — калиброванные вопросы здесь не мешают. Формула: *"How will we know we're on track?"* (гл.8, стр. 139) → writing-for-agents

## April Dunford «Obviously Awesome» (4)


### Frivent / B2B

- **Не просить «заявление о позиционировании».** Агентам и дизайнерам не ставить задачу «For… Unlike…»; вместо этого заполнить холст (ниже) и от него писать сообщения. (ч.5, ч.15) → writing-for-agents

### Новости, данные, Claude Code и агенты

- **Контекст до команды.** В промптах и скиллах сначала задать контекст («первая сцена фильма»: кто, что, для чего), потом задачу; иначе агент выберет рамку по умолчанию (аналог ловушки 1). (ч.4) → writing-for-agents
- **Порядок шагов в скиллах.** Записывать последовательность «альтернативы → особенности → польза → клиенты → категория → тренд» с проверкой на каждом шаге; не давать агенту начинать с функций. (ч.5) → writing-for-agents
- **Один источник формулировок.** Один мастер-документ, остальные тексты производные; то же для рассылок и скиллов. (ч.16) → writing-for-agents

## Keijser «OpenVPN Cookbook», 2-е изд. (4)


### Новости, данные, Claude Code и агенты

- **Общий файл + маленькие файлы на каждый запуск.** `config общий.conf` внутри конфига, плюс защита от рекурсивного включения: общее (сертификаты, поведение) в одном файле, отличия (протокол, порт, лог) — в коротких. Так же строить скиллы и сборщики: общий `base`, и маленькие «настройки запуска» с защитой от циклов. (гл. 10 / часть 118) → writing-for-agents
- **Явный флаг вместо надежды на переменные.** В плагинах `script_type` не задаётся, поэтому один и тот же скрипт для `up` и `down-root` различают аргументом `--down`. В наших скриптах с двумя режимами — явный аргумент, а не догадка по окружению. (гл. 5 / часть 71) → writing-for-agents
- **Клиент сообщает о себе — сервер подстраивается.** `push-peer-info` отправляет серверу переменные `IV_PLAT` (платформа), `IV_GUI_VER`, `IV_SSL` (версия библиотеки шифрования — по ней можно понять, уязвим ли клиент), `IV_VER` и др.; скрипт `client-connect` для Android добавляет `redirect-gateway def1`. Для бота «Дела» и агентов: передавать в запросе метки клиента (канал, версия, платформа), чтобы ответ можно было подстроить, не выдумывая. (гл. 9 / часть 116) → writing-for-agents
- **Правило «сломай → прочитай → почини» для скиллов.** Главы 6–7 — готовая структура справочника симптомов: название поломки, как воспроизвести, настоящая строка лога, почему, как лечить. Оформлять так «Грабли» в скиллах `sourcing-1688`, `pc-check`, `dela`: по каждой — настоящий текст сообщения, а не пересказ. (гл. 6 / часть 73) → writing-for-agents

## Anders Ericsson «Peak» (2)


### Новости, данные, Claude Code и агенты

- **Скилл = «на что смотреть, какие ошибки, как узнать хорошо».** Хороший учитель даёт ученику не только «что делать», но и «на какие аспекты обращать внимание, какие ошибки вы делаете, как распознать хорошее выполнение» (гл. 6, стр. 141). Это структура для скиллов и промптов. → writing-for-agents
- **Просить агента «думать вслух» на трудных случаях — для анализа, не в шаблонах промптов.** Приём изучения экспертов: записывать рассуждения на сложной задаче, чтобы понять, какие «карты» стоят за ответом. Её правило: «ты эксперт» и «думай пошагово» в промптах не писать. (гл. 5, стр. 135) → writing-for-agents

## Agrawal, Gans, Goldfarb «Prediction Machines» (4)


### Новости, данные, Claude Code и агенты

- **AI canvas для каждой поручаемой задачи.** Перед тем как отдать задачу Hermes, Claude-агенту или скрипту, заполнить 7 строк: действие, прогноз, суждение (цена ошибок), исход (метрика успеха), входные данные, обучающие данные/примеры, обратная связь. Зачем — сразу видно, чего не хватает (обычно метрики и обратной связи). Когда — новый скилл, сборщик, задача Hermes. (гл. 15, ч. 25) → writing-for-agents
- **В задании прямо писать, какая ошибка дороже.** «Что хуже — пропустить важный пост или показать лишний?» — это суждение, модель его не знает. Для tg-news по её правилу дороже лишнее (на панель только то, что меняет действие); для сбора поставщиков дороже пропуск. Писать это отдельной строкой в промпте. Когда — каждый промпт-фильтр. (гл. 9, 13; ч. 18, 22) → writing-for-agents
- **Против «переоптимизации» одной метрики — вторая метрика.** ИИ с одной мерой успеха гонит её в ущерб цели (инженерия функции вознаграждения). Ставя цель «больше приёмов», добавлять ограничитель «каждый применим к нашему делу и не повторяет записанное». Когда — постановка целей агентам. (гл. 9, ч. 18) → writing-for-agents
- **Формат вывода, где ошибку легко пропустить.** Gmail-подсказки нравятся при 70% промахов, потому что плохую не жалко проигнорировать. Агенту — 3 варианта на выбор, а не один готовый текст; Hermes — короткие пункты, а не правка файла. Когда — задачи с невысокой точностью. (гл. 19, ч. 30) → writing-for-agents

## Mendelevitch «Hands-On RAG for Production» (3)


### Новости, данные, Claude Code и агенты

- **Исполнителю — только его контекст.** Субагенту/Hermes — только нужные файлы и правила, без всей переписки; исполнители не передают друг другу, всё через главного («оркестратор — исполнители»). (гл. 7, стр. 224–225) → writing-for-agents

## Polzer «RAG with Python Cookbook» (2)


### Новости, данные, Claude Code и агенты

- **Описание инструмента = договор с моделью.** Для каждого скрипта, который вызывает агент: одна задача; в описании — что делает, входы с типами, выход, пример вызова; обработка таймаута, лимита, сбоя. ## Sam Newman «Building Resilient Distributed Systems» (5)


### Новости, данные, Claude Code и агенты

- **Слова в промптах = слова в коде.** Называть в задаче те же термины, что в коде и скиллах (имена функций, таблиц); если названия расходятся, ИИ хуже понимает, что менять. (гл. 7) → writing-for-agents
- **Понятные имена вместо «шуток для своих».** Не называть функции `doOperationTheWonderStuff` (пример из книги); читаемый человеку код лучше понимает и ИИ. (гл. 7) → writing-for-agents
- **Явно писать в скиллах, что делать при сбое.** В скилле сборщика отдельная строка: «429 → жди Retry-After; 403 → не повторять и сообщить; пустой ответ → повторить 1 раз»; иначе агент делает как придётся. (гл. 4) → writing-for-agents
- **Не писать «отказоустойчивый» без уточнения.** В скиллах и промптах всегда: к каким отказам и до какой степени (fault tolerance без уточнения — пустое слово). (гл. 1) → writing-for-agents
- **Чек-листы в скиллах — рекомендательные, с пометкой «необязательно».** Помечать обязательные и «по ситуации» пункты; жёсткий список заставляет делать всё подряд и терять главное, когда время или контекст на исходе. (гл. 14) → writing-for-agents

## Bandler «How to Take Charge of Your Life» (2)

## Bandler «Using Your Brain — for a Change» (4)


### Новости, данные, Claude Code и агенты

- **Агент — как мозг: делает ровно то, что сказано.** Что делать: писать инструкции с точной последовательностью и без «и так понятно» («мозги и компьютеры не дружелюбны к пользователю»). Зачем: ошибка в инструкции даёт ровно ту ошибку (гл. I, стр. 20). → writing-for-agents
- **Порядок меняет смысл.** Что делать: в промптах и контекстах порядок важнее, чем кажется: проверять варианты порядка (инструкции → пример → данные против наоборот) (гл. VI, стр. 107–108). → writing-for-agents
- **Скилл = поваренная книга.** Что делать: описывать экспертную работу шагами «ингредиент → действие → результат», проверять по принципу «получится ли у новичка»; не нужно знать «почему» — нужно, чтобы работало (гл. I, стр. 20–21). → writing-for-agents
- **Разбивка задачи (chunking).** Что делать: агентам давать кусками, а не общей задачей; память и результат лучше (гл. VIII, стр. 131). → writing-for-agents
