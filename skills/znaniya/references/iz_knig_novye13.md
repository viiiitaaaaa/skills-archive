## Mendelevitch «Hands-On RAG for Production» (8)

- **Журнал «не нашлось» в poisk.py.** Каждый запрос, по которому нет кусков «со всеми словами» (`full` = 0) или она сказала «не то», дописывать строкой в `znaniya\ne_naydeno.jsonl` (дата, запрос, сколько нашлось). Раз в неделю смотреть: это пробел в знаниях (надо изучить/записать) или плохой поиск (нужны синонимы). Книга называет причиной плохих ответов №1 «нужных данных в базе нет» и лечит отслеживанием таких вопросов. (гл. 4, стр. 133) → znaniya
- **Убирать «команду» из запроса перед поиском.** «Напомни, что мы решили про доставку» → искать только «доставка»; слова «найди, напомни, скажи, был, есть, решили, какие, нас» — в стоп-слова `STOP` poisk.py (сейчас там только «что, мы, про, знаем, умеем…»). Книга: поисковый запрос ≠ вопрос пользователя, инструкцию («напиши стих») отделять от темы («мои поездки»). (гл. 2, стр. 52–53) → znaniya

Для каждого правила одна строка-«канон» с датой; старое не удалять, а помечать «⛔ устарело с ДД.ММ, см. …» («надгробие»), а poisk.py понижать вес таких кусков (например ×0,3) и показывать пометку. Книга: «устаревший документ подаётся как актуальный» — отдельный вид поломки; лекарство — ID + версия, старые версии из выдачи убирать. (гл. 6, стр. 189; гл. 9, стр. 332) → znaniya
- **Удалённое — убрать из базы.** Сейчас poisk.py читает файлы заново при каждом запуске — это правильно. Но в будущем векторном индексе (Polzer №2) при пересчёте только изменённых файлов обязательно удалять векторы удалённых и переименованных файлов, иначе всплывёт то, чего уже нет. (гл. 3, стр. 91, 99–100) (дополняет Polzer №2) → znaniya
- **Промежуточная проверка перед большим пополнением.** Когда в скиллы разом добавляется пачка (как книги 13.10), прогнать 10–20 контрольных вопросов poisk.py «до» и «после»: её короткие правила не должны вытесняться длинными конспектами книг. Вытеснили — поднять вес памяти/её правил. Книга: staging-коллекция + автотесты поиска, потом перенос в рабочую. (гл. 4, стр. 133–134) (дополняет Polzer №3) → znaniya
- **Один «золотой путь» к знаниям.** Знания у нас в 6 местах (скиллы, память, принятое, книги, курсы, Диск). Не плодить отдельные поиски под каждое (свой в tg-news, свой в базе поставщиков) — всё через poisk.py с ярлыком «вид». Книга: «расползание RAG» — разные базы с разными правилами → правила расходятся. (гл. 5, стр. 166–168) → znaniya
- **Не тащить таблицы в базу текстом.** xlsx/tsv (отбор 1688, поставщики, досье) не копировать в базу знаний — poisk.py должен знать, что «про поставщиков» надо открыть `postavshchiki_baza.tsv` готовым запросом pandas (Polzer №42). Книга: «федеративный поиск» — данные остаются в источнике, к ним ходит инструмент. (гл. 10, стр. 340–341) → znaniya

## Polzer «RAG with Python Cookbook» (13)


### Новости, данные, Claude Code и агенты

- **Гибридный поиск в poisk.py.** Сейчас `znaniya\poisk.py` ищет только совпадение корней слов (это по сути упрощённый BM25). Добавить второй список — по смыслу (эмбеддинги кусков) и сливать два рейтинга формулой RRF: `балл = 1/(60 + место_по_словам) + 1/(60 + место_по_смыслу)`. Зачем: «доставка в США» найдёт и «shipping to US», и «логистика посредника», а ID/артикулы по-прежнему найдутся точно. Когда: следующая доработка znaniya, после теста №3. (5.7, стр. 155–159) → znaniya
- **Эмбеддинги — локально и многоязычные.** Наши знания на русском и английском вперемешку, в памяти есть личное — значит векторы считать на ПК (Ollama-модель эмбеддингов или Sentence Transformers), а не в облаке. Брать многоязычную модель (сверить по рейтингу MIRACL), а не all-MiniLM-L6-v2 — она англоязычная. Векторы считать один раз и хранить в файле рядом (пересчёт — только для изменённых .md). Установка модели — с её «да». (5.1, 5.4, стр. 132–134, 145–146; 6.1 стр. 162) → znaniya
- **Тест поиска на 50–100 её вопросах.** Файл `вопрос → какой файл/раздел должен найтись` (брать настоящие «что мы знаем про…» из переписки), скрипт считает, в скольких случаях нужный кусок в первых 5. Прогонять до и после каждой правки poisk.py — так видно, помогло или нет, а не «кажется». (5.4 стр. 145–146; 10.1 стр. 303) → znaniya
- **Путь заголовков внутри куска.** poisk.py уже режет .md по заголовкам `#` — это «нарезка по разметке», которую книга называет одной из самых эффективных. Добавить: перед текстом куска при индексации дописывать «скилл › раздел › подраздел», чтобы кусок был понятен в отрыве (как «новый алгоритм индексации ускорил поиск на 40%» вместо «он ускорил на 40%»). (4.6 стр. 119–122; табл. 4-1 стр. 109) → znaniya

Вопрос «что было в новостях на этой неделе» → сначала фильтр «принято, последние 7 дней», потом поиск. Флаг `--vse` — это уже грубый фильтр; расширить до `--vid книга`, `--dni 30` (за 30 дней).
