## Tiago Forte «Building a Second Brain» (12)


### Как ей учиться и запоминать

- **Старт учебного проекта: 5 шагов за 20–30 минут.** (1) Выписать, что я уже знаю/чего не знаю/цель/у кого спросить/что почитать; (2) просмотреть папки, где уже что-то есть; (3) поискать по ключевым словам во всём своём; (4) перенести найденное в папку проекта; (5) составить план-«архипелаг». Зачем: часто половина материала у тебя уже есть (в скиллах, памяти, конспектах). Когда: в начале любой новой темы — вместе со скиллом `znaniya`. (гл. 9, стр. 181–184) → znaniya

### CODE и PARA для нашей системы (скиллы Claude, память, `znaniya`, Диск, бот «Дела», новости, конспекты)

- **Назвать разделы памяти по PARA.** В `MEMORY.md` (около 150 строк плоским списком) добавить пометки или секции: **Проекты** (идут сейчас), **Области** (магазин, Frivent, дела, учёба — постоянные), **Ресурсы** (инструменты, API, ключи, справки), **Архив** (закрытые «Сессия …», отвергнутые решения). Зачем: файл грузится в каждую сессию, и по нему Claude находит нужное; плоский список растёт и «шумит». Когда: при ближайшей уборке памяти — только по её слову (память — её решения, содержание не менять). (гл. 5, стр. 77–88) → znaniya
- **Старые «Сессия …» уходят в архив после закрытия проекта.** Файлы итогов сессий (26–27.09, 07–08.10, 12.10, 13.10…) — проектные заметки; когда проект закрыт, переносить в «Архив» (поиск их всё равно найдёт), в списке памяти оставлять только «хвосты» (что ждёт её). Зачем: «завершённые проекты — кислород»: меньше шума, и видны живые хвосты. Когда: раз в месяц. (гл. 5, стр. 90–93, 95) → znaniya
- **В каталоге умений `znaniya` показывать «Активные проекты» сверху.** Страница `katalog_umeniy.html` — сначала 5–10 живых проектов и по каждому — какие скиллы и знания к нему относятся, потом остальное. Зачем: по книге в среднем 5–15 активных проектов; список проектов — «центральный принцип организации»; когда папка проекта готова, мозг начинает замечать нужное. Когда: при ближайшей пересборке каталога. (гл. 5, стр. 83; гл. 9, стр. 191) → znaniya
- **Старт проекта = мини-протокол «поднять наше».** Порядок: (1) записать, что думаю о проекте; (2) посмотреть уже существующие папки/скиллы; (3) поиск по словам (`poisk.py`); (4) перенести найденное в папку проекта; (5) собрать «архипелаг» — план из найденных кусков, и только потом работать. Уже есть правило «в начале проекта — `znaniya`, 3–7 строк»; приём дополняет его шагами 4–5. Зачем: книга считает это самой частой дырой («проект стартует наугад»). Когда: каждый новый проект. (гл. 9, стр. 180–184) → znaniya
- **Не больше ~10 активных проектов в поле зрения.** Остальные — «на паузе» с запиской «Текущий статус». Зачем: иначе приоритеты размываются; книга приводит 5–15 как норму. Когда: при месячном обзоре. (гл. 5, стр. 83; гл. 9, стр. 186–187) → znaniya
- **Скиллы Claude — это «Ресурсы и Области», а не «Проекты».** Новый скилл создавать, когда тема повторяется и нужна как справочник/регламент; разовые работы живут в папке проекта, а выжимка уходит в подходящий скилл. Не множить скиллы «на всякий случай» (главная опасность — «сохранить слишком много»). Зачем: каталог не должен превратиться в ленту соцсетей. Когда: при идее нового скилла — вопрос «это повторяющаяся область или разовый проект?». (гл. 4, стр. 58; гл. 5, стр. 77–82) → znaniya
- **Теги как «перекрёстная ссылка», не как основа.** Если нужно собрать куски из разных папок для нового проекта — пометить найденное одним тегом («FAQ», «питч-v8»), затем один поиск по тегу покажет всё в одном месте; основной порядок — папки по проектам. У нас роль тега играет слово в тексте для `poisk.py` (`znaniya`) — поддерживать единые ключевые слова в заголовках. Зачем: теги дорого вести на каждой заметке. Когда: при сборке материалов под внезапный проект. (гл. 7, стр. 144) → znaniya
- **Перекладывание заметок между категориями — нормально.** Заметка живёт: проект → область → ресурс → архив → снова проект (пример с коучингом). Не искать «идеальное место»; хорошо помогает поиск. Когда: каждый раз при пересмотре; не ругать себя. (гл. 5, стр. 89–90) → znaniya
- **PARA для памяти Claude: «Области» — постоянные правила.** Её решения (`Ранее принятые решения считаются решёнными`) — это «стандарты» областей (аудитория 28+, не писать жителям, магазин не её). Их не пересматривать при уборке, только переносить. Когда: при любой переорганизации памяти. (гл. 5, стр. 79–81) → znaniya
- **Два уровня глубины в каталоге: «найти» и «открыть».** Каталог `katalog_umeniy.html` — для просмотра за 30 секунд (слой 3–4: название, фраза вызова, одна строка «когда»); сами скиллы — «слой 1». Не раздувать описания. Когда: при пересборке каталога. (гл. 6, стр. 112) → znaniya
