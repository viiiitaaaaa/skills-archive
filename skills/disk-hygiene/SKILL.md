# Порядок на дисках (C: и Google Диск)

Три работы, у каждой свои скрипты в `scripts\` и `referats\`. Все скрипты по умолчанию работают
**вхолостую** (показывают, что сделают) — реальное действие только с ключом `-Apply` / `--apply`.
Объяснять ей простыми словами; перед необратимым (удаление без корзины, очистка корзины Диска) —
спросить, что именно удалять, и перечислить, что пропадёт навсегда.

## Как устроены её диски (выяснено 28.09.2026 — не забывать)

- Google Drive на ПК синхронизирует **только `C:\Users\User\Desktop`**, и то в раздел «Компьютеры»,
  а не в «Мой диск» (G:). `C:\Users\User\Downloads` ни с чем не связана. Проверка: `python scripts\drive_sync_roots.py`.
- Перетаскивание папки C: → G: в проводнике = **копия** (оригинал остаётся). Отсюда дубли и «удалила, а место
  не освободилось». Переносить: Ctrl+X / Ctrl+V или перетаскивание с Shift. После любого переноса C:→G:
  проверить, что оригинала на C: больше нет (`python scripts\compare_dirs.py`).
- Удаление на G: = корзина Google Диска; место освобождается только после очистки корзины
  (drive.google.com/drive/trash → «Очистить корзину»), счётчик падает с задержкой до нескольких часов.
- Лимит 15 ГБ общий: Диск + Gmail + Фото + «Компьютеры» (копия Рабочего стола). Разбивка: drive.google.com/drive/quota.
- Удалять на G: можно (уходит в корзину Диска). Удалять на C: через PowerShell — **безвозвратно**, мимо корзины Windows.

## 1. Разбор Google Диска / папок по темам

Структура G:\Мой диск (её решения): `Дела\<Фамилия — суть>\` (юр. дела, правила — `Дела\_ПРАВИЛА.md`, скилл dela),
`Мои задачи\<тема>\`, `Личное\`, `Магазин и маркетплейсы\`, `Учёба — …` (только рефераты), `Программы и ярлыки`,
`доступ\` (её папка для ключей/паролей), `_Можно удалить (дубли и мусор)\`, журнал `_журнал разбора диска <дата>.csv`.
Служебные папки приложений (From_BrotherDevice, ClearScannerData, simple_ml_for_sheets) не трогать.

Порядок:
1. Опись: что лежит, сколько, какие типы; прочитать `_ПРАВИЛА.md`/`_описание.md` существующих дел и тем.
2. Непонятное — открыть: текст docx/pdf (первые строки), сканы — лист превью (pypdfium2 → одна картинка), голосовые —
   расшифровать (`referats\transcribe.py`). Имена в файлах бывают обманчивы: «Докукина» оказалась улицей,
   «Даша» — лекциями по WB, «рыба» — интенсивом Рыбко.
3. Правила «шаблон имени → папка» — в `scripts\rules.local.json` (личное, в git не попадает; образец — `rules.example.json`).
   Прогон вхолостую: `python scripts\sort_by_rules.py <откуда...> --rules scripts\rules.local.json`,
   потом с `--apply`. Скрипт: не затирает одноимённые (дописывает « (2)»), одинаковые по имени+размеру копии
   кладёт в `_Можно удалить\Копии…`, пустые недокачанные файлы — туда же, пишет журнал откуда→куда.
4. Пароли и ключи не удалять и не переносить в рефераты — в папку `доступ`. Юр. материалы — в `Дела\_Входящие`.
5. Перед переносом **перечитать структуру** — она двигает папки сама параллельно (так было 28.09).
6. Итог — таблица «что куда», что не удалось отнести, находки (секреты, чужие дела).

## 2. Полные рефераты вместо учебных исходников

Её требование: реферат заменяет исходники полностью — после него исходники удаляются. Потеря знания хуже лишней страницы.
1. `python referats\extract_text.py "<папка>" <рабочая папка>` — текст из docx (все w:t из XML — python-docx теряет
   пункты списков!), pdf, md/txt/csv, html, rtf, ipynb, drawio, pptx, fb2, xlsx. Google Docs (.gdoc) локально пустые —
   читать коннектором Google Drive (read_file_content) по id из поиска `parentId = '<id папки>'`.
2. Видео/аудио: `python referats\transcribe.py "<папка>" <рабочая папка>\tr --lang ru` (large-v3-turbo; английский —
   `--model small.en --lang en`, в 6 раз быстрее). Ноутбук i7-9750H без CUDA: ~1× реального времени, две модели сразу
   не помещаются в память — запускать по очереди.
3. Манифест «файл → тема»: каждый файл ровно в одну тему (`referats\manifest_template.py` — правила-шаблоны).
   Проверить, что в манифесте все файлы папки.
4. Помощники (по одному на тему, фоном) по инструкции `referats\BRIEF.md`; большие темы (>1,5 МБ текста) — делить
   на части и потом сливать отдельным помощником без потерь (проверка: ни одна строка частей не пропала).
   Файлы «не по теме», найденные помощниками, перекладывать в нужную тему или в `keep` манифеста.
   Модели (12.10): реферат темы — `model: sonnet`; слияние частей и проверка «ни одна строка не пропала» — `model: haiku`
   (сверку строк делает скрипт, помощник только запускает); решения что удалять и `finalize.py --apply` — Opus в основной
   сессии. В брифе — что сделать и «готово» = какой файл; без «подумай / шаг за шагом».
5. `python referats\md2docx.py ref\X.md "NN Реферат — Тема.docx"` — Word с оглавлением-списком (видно и в Google Диске).
6. `python referats\finalize.py --apply` — сохраняет `keep` (пароли → доступ, личное, юр.), кладёт рефераты,
   удаляет остальное (в корзину Диска), пишет журнал. Сначала без `--apply`.
7. Курсы, которые она велит «оставить на потом», — не удалять, вынести в подпапку «… — на потом» вместе с готовыми расшифровками.

## 3. Место на C: и в Google Диске

1. `powershell -ExecutionPolicy Bypass -File scripts\scan_disk.ps1` — WizTree (C:\Program Files\WizTree) выгружает
   диск в CSV, `report.py` печатает: крупные папки по разделам, 40 крупнейших файлов, повторы (имя+размер),
   размеры известных кэшей и старых версий программ, какие версии браузеров playwright реально нужны скриптам.
2. Показать ей таблицу: «можно удалить сам» / «через настройки Windows (делает она)» / «не трогать (рабочее)».
3. `powershell -ExecutionPolicy Bypass -File scripts\clean.ps1 -Items <ключи>` (вхолостую), затем с `-Apply`.
   Ключи: `capcut-cache npm-cache pip-cache temp chrome-cache telegram-cache amd old-versions playwright-unused
   whisper-small`. `temp` не трогает `Temp\claude` (рабочая папка Claude Code).
4. Не трогать: pagefile.sys; hiberfil.sys (отключает она: `powercfg /h off` от администратора); WinSxS (она: «Очистка
   диска» → системные файлы); модель large-v3-turbo (бот «Дела»); rembg-модели (фото товаров); программы 1688/АлиВанван,
   WeChat, Dolphin, CapCut; `C:\chrome-wb`, `C:\chrome-debug` (профили скриптов).
   **playwright**: удалять только ревизии, которых нет ни в одном `browsers.json` (28.09: 1187 нужна Python 3.13,
   1234 — my-bot и node-скриптам, 1243 — Python 3.14/радару). `clean.ps1` это проверяет сам.
5. Visual Studio Build Tools + Windows SDK (5,7 ГБ) — компилятор для установки Python/Node-библиотек; для запуска
   готовых скриптов не нужен. Удалять через «Параметры → Приложения», по её слову.
6. Скрипты не молчат о пропусках (курс Vercel, kursy-konspekty): всё, что не удалено, печатается строкой
   `ПРОПУЩЕНО: <что> — <причина>` или `ЗАБЛОКИРОВАНО: <что> — нужно её «да»` (без `-Apply` / `--apply`);
   в отчёте ей эти строки перечислить.
