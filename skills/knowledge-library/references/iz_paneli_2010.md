## Безопасность кода
- **pickle.loads на входящих данных = выполнение чужого кода** — Никогда не распаковывать pickle из внешних данных (pickle.loads = выполнение чужого кода), в наших ботах и скриптах принимать только JSON. (c/3128735547/1000)
- **Bandit — сканер дыр в Python-коде за секунды** — Прогнать `bandit -r папка/` по нашим репозиториям (case-bot, tg_monitor, радар): он находит eval, pickle.loads и ключи, забытые в коде. (c/3128735547/986)
- **SQL-инъекция через f-строку в запросе** — Запросы в sqlite писать только с параметрами `cur.execute("... = ?", (x,))`, а не через f-строку: иначе ввод вида `admin' --` ломает запрос. (c/3128735547/989)
- **Для паролей и токенов — secrets, не random** — Токены и секреты для ботов и вебхуков генерировать через `secrets.token_urlsafe(32)`, не через random; хеши сравнивать через `hmac.compare_digest`. (c/3128735547/994)
- **Проверка паролей на утечки через HaveIBeenPwned без отправки пароля** — Пароли можно проверить на утечки через api.pwnedpasswords.com: на сервер уходят только первые 5 символов SHA-1, ключ не нужен. Можно сделать маленький локальный скрипт. (c/3128735547/996)

## Окружения и пакеты
- **venv и uv — отдельное окружение на каждый проект** — Для проектов с конфликтом библиотек завести .venv в корне (радар, tg_monitor), не коммитить его в git, версии фиксировать в requirements.txt; uv ставит быстрее pip (канал пишет: в 10–100 раз). (c/3128735547/1013)
- **uv — быстрый менеджер пакетов вместо pip, poetry и virtualenv** — Для нового проекта (сайт-сборщик, бот) попробовать uv вместо ручных venv и pip (`uv add`, `uv run`); существующее не переносить. (c/3128735547/1048)
- **pipx — ставить Python-утилиты в отдельные окружения** — Чужие Python-утилиты из новостей ставить через `pipx install`, а не `pip install` в системный Python. (c/3128735547/1049)
- **uv — один инструмент вместо pip, pyenv, virtualenv, poetry и ещё нескольких** — Новые проекты ставить через `uv` (окружение, зависимости, lock-файл; канал пишет — в 10–100 раз быстрее pip); старые не трогать, пока работают. (python_tg/4050)
- **Современный старт Python-проекта: uv + Ruff + pyproject.toml + uv.lock** — Шаблон старта нового сборщика: uv + Ruff (линтер/форматтер) + pyproject.toml + uv.lock; старые проекты не переделывать. (python_tg/4062)

## asyncio и параллельные запросы
- **Шпора asyncio: gather, create_task, Semaphore, Queue** — В asyncio.gather ставить return_exceptions=True, чтобы один упавший запрос не ронял остальные, и не использовать time.sleep в корутине; число параллельных запросов ограничивать Semaphore. (c/3128735547/1022)
- **requests → httpx async: 200 запросов с 40 до 4 секунд** — В сборщиках с сотнями запросов использовать httpx.AsyncClient + семафор вместо цикла requests (канал пишет: 200 запросов с 40 до 4 секунд); клиент открывать через `async with` и задавать таймауты. (c/3128735547/1043)

## Прогресс и повторы
- **tqdm — прогресс-бар для долгих циклов одной строкой** — Долгие циклы сборщиков (Apify, treg, tg_monitor) оборачивать в tqdm: `for x in tqdm(items):` сам показывает «N из M» и оставшееся время. (c/3128735547/1030)
- **rich, typer, loguru, pydantic, tenacity — 5 полезных библиотек** — В сборщики (treg, Apify, tg_monitor) вместо самописных повторов при обрывах сети/VPN поставить tenacity (`@retry(stop=stop_after_attempt(3))`), а лог долгих сборов вести через loguru. (c/3128735547/980)

## Приёмы Python
- **@functools.cache — кэш результатов функции одной строкой** — Повторяющиеся дорогие вызовы в сборщиках оборачивать в `@functools.cache` / `@lru_cache(maxsize=128)`; аргументы должны быть хешируемыми. (c/3128735547/999)
- **Python 3.14.5 отказался от нового сборщика мусора** — Канал пишет: в Python 3.14.5 вернули старый сборщик мусора из-за расхода памяти; если наши скрипты на 3.14 ели много памяти — обновиться до 3.14.5. (python_tg/3960)

## Ловушки Python
- **Грабля Python: `if text.find("слово"):` работает неправильно** — Наличие слова проверять `if "слово" in text:`, а не `if text.find("слово"):` — find даёт 0 в начале строки (это «ложь») и -1 при отсутствии (это «истина»); важно для фильтров по ключевым словам в сборщиках. (python_tg/3976)

## Асинхронность
- **Ловушка async: один блокирующий `requests.get()` останавливает всю программу** — Внутри `async def` не вызывать блокирующие `requests.get()` и `time.sleep`: один такой вызов останавливает всё (в тесте 192 → 4,9 запроса/с); для синхронных библиотек — обычный `def` или `run_in_threadpool`. Проверить наши асинхронные скрипты. (python_tg/4041)
