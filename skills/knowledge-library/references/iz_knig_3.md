## Мукминов «Claude Code» (4)


### Новости, данные, Claude Code

- **Команда «новый сборщик» — скелет с нашими обязательными частями.** По образцу команды `new-feature` из книги: папка; `CLAUDE.md` на 4 раздела (dop №57); `.env.example` (dop №48); `diagnose.py` (1-й №7); логи через `log_setup.py`; файл прогресса «N из M»; первый коммит. Зачем: каждый новый сборщик сразу со всеми «предохранителями». (стр. 164) → `claude-code-priemy`, `knowledge-library`
- **Общий код — в одном месте, не копиями по проектам.** Правило из шаблона монорепозитория: общий код живёт в одной общей папке, проекты не берут код друг у друга. У нас: `log_setup.py`, клиент treg, загрузка `.env` — импортировать из одного места (`knowledge-library\scripts`), а не копировать в каждый сборщик. Иначе исправление в одном месте не попадает в остальные. (прил. Б.5, стр. 246) → `knowledge-library`
- **Пример в docstring как самопроверка (doctest).** В строке описания функции разбора («35–70» → (35, 70); «1万+» → 10000) записать 2–3 примера «вызов → результат» и проверять командой `python -m doctest файл.py`. Описание тогда не расходится с кодом. Состав описания: что делает, параметры, что возвращает, какие ошибки бросает, пример, «грабли». (стр. 138–140) → `knowledge-library`
- **Запрет `print` в сборщиках — проверкой, а не просьбой.** В образце CLAUDE.md правило «не используй print(), только logging» закреплено линтером. У нас: `ruff check --select T20` находит `print` (ruff ставить только по её слову). Вариант без установки: поиск `print(` по папке перед коммитом. (стр. 23, 91) → `knowledge-library`

## Котлер «10 смертных грехов» (4)


### Магазин одежды

- **Считать долю ответивших, прежде чем делать вывод.** К каждому опросу покупательниц писать: «разослано N, ответили M (M/N %)». Если ответили меньше ~20 человек или ответы сильно расходятся, вывод помечать «гипотеза». Зачем: анкета даёт достоверную картину, только «если ответы будут получены»; разрозненные ответы не обобщаются. Когда: каждый опрос после покупки. (гл. 2, стр. 41–42) → `dropship-lessons`, `knowledge-library`
- **Прибыль по срезам, а не только по SKU.** Раз в месяц собирать в pandas таблицу прибыли (не выручки) по 5 срезам: штат/регион, модель, сегмент покупательниц (новые/повторные), канал рекламы (Meta/TikTok/Google), источник поставки (поставщик). Котлер называет эти пять срезов прямо. Зачем: прибыль не пропорциональна продажам, затраты и маржа разные. Когда: ежемесячная чистка каталога. (гл. 9, стр. 130–131, 137) (дополняет первый №9) → `knowledge-library`, `shopify-admin`
