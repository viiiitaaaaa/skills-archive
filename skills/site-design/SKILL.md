## Выжимка: как применять (обновлять при накоплении нового)

**Добор к анти-шаблону из taste-skill (leonxlnx, MIT; прочитан текстом 19.10, не ставили)** — дописывать в промпт страницы:
- Главный заголовок — не больше 2–3 строк: лучше уменьшить шрифт или расширить блок.
- На первом экране нет значков-«штампов» поверх текста, «таблеток»-тегов под заголовком и цифр статистики.
- Нет надписей-меток «Раздел 01», «О НАС», «ВОПРОС 05» — выглядят дёшево.
- Карточек в блоке 3–5 продуманных, не 8 одинаковых. Между разделами — большие отступы (каждый раздел как отдельная «глава»).
- Без серых рамок 1px и тяжёлых чёрных теней — тени мягкие, тёплого оттенка.
- Без эмодзи и заглушек («Иван Иванов», «Lorem ipsum», «Компания Х») — только настоящий текст.
- Слова-клише запрещены: «новый уровень», «бесшовный», «откройте для себя», «премиальный опыт», «инновационный».
- Если будет движение: двигать только `transform` и `opacity`, без `linear`; при настройке «меньше движения»
  (`prefers-reduced-motion`) всё стоит неподвижно; зерно — на фиксированном слое, не на прокрутке.
- НЕ берём оттуда: «анимация обязательна (GSAP)», «никогда не повторять вид», фото-заглушки picsum, их списки шрифтов
  (у нас Vela Sans).

**Вид «дорого» (тихая роскошь)**
- Палитра из 4 цветов: 1 базовый тёплый фон + 2 поддерживающих + 1 акцент только для кнопки заявки и деталей.
  Стартовый вариант: фон `#E5DFD6`, тёмный `#3C2418`, акцент-бронза `#B19061`. Чисто белый `#FFFFFF` фоном не брать.
- Первый экран: один очень крупный заголовок + короткий абзац мелким шрифтом, приглушённый фон с едва заметным зерном,
  мягкие градиенты и тени. Ярких цветов и стены текста нет.
- Фактура вместо пустоты: зерно, фото материалов, один источник света — тени везде в одну сторону.
- Шрифт — Vela Sans (решено). Проверено 09.10: у Plus Jakarta Sans, Syne, REM, Aston Script кириллицы НЕТ, Neue Montreal —
  кириллица не подтверждена и бесплатно только для личного. Новый шрифт брать только после проверки кириллицы и лицензии OFL.
- Запасной шрифт: `--font-main: "Vela Sans", system-ui, sans-serif` и шрифт везде только через переменную (иначе Times и скачок блоков).

**Блоки**
- Направления — раскрывающиеся полосы с фото; этапы работы — шкала с карточками; объекты — крупное фото с кнопкой в
  вырезанном углу, фото приглушённые и оживают цветом при наведении. На телефоне наведения нет — раскрытие по нажатию.
- Анимации: одно спокойное появление блоков на весь сайт — `transition-delay: calc(sibling-index() * 90ms)` (работает во всех
  браузерах) + ~15 строк IntersectionObserver; AOS не брать (заброшен с 2018). Только под `prefers-reduced-motion: no-preference`;
  медленно, без «прыжков»; в анимациях не менять `width/height/top/left`. Бегущая строка — максимум одна.
- Мобильное меню — простая иконка-крестик; в раскрытом меню обязательно телефон и кнопка заявки.

- Фото объектов: в покое `filter: saturate(.35)`, при наведении `saturate(1)` + лёгкий `scale(1.05)`, 600ms.
- Бегущая строка марок: список дважды + `translateX(-50%)`, края гаснут градиентом в цвет фона, при наведении пауза.
- FAQ: `<details name="faq">` — открыт один пункт, ответы находит Ctrl+F, без JS.
- «Фонарик» (под курсором видна инженерия за отделкой): маска `radial-gradient(circle at var(--x) var(--y), black 25%, transparent 0)`
  + mousemove; круг небольшой с мягким краем, на телефоне выключить.
- Оттенки фирменных цветов: `color-mix(in oklch, #6b1a24 70%, white)` или шкала tints.dev / colorpalette.pro.
- Карточки и форма — `@container` + размер шрифта `clamp(… cqi …)` вместо привязки к ширине экрана.

**Форма заявки**
- Минимум полей, `autocomplete="name"` / `autocomplete="tel"`, тип `tel`; на кнопке значок и конкретная подпись,
  не «Отправить». Контур фокуса не убирать: `outline: 2px solid transparent; outline-offset: 2px` + своё кольцо
  `box-shadow: 0 0 0 2px #f5f1ea, 0 0 0 4px #6b1a24`; поля `font: inherit`; проверить форму клавишей Tab.

**Правила вёрстки для Claude Code**
- Старт с CSS reset (Josh W. Comeau); цвета и шрифты — CSS-переменные; запасной шрифт у каждого `font-family`.
- Собрать `DESIGN.md` (app.initium.sh) и положить в проект; каждую дизайн-правку записывать правилом в `CLAUDE.md` проекта.
