## Официальный блог React: в версии 19.3 стал стабильным компонент <ViewTransition> (плавная смена содержимого через браузерный View Transition API), плюс Fragment Refs, browser() и др.
https://react.dev/blog/2026/09/09/react-19-3 · [пост](https://t.me/tproger_web/6586) · изучено
- Анимируются только «неспешные» обновления (startTransition, показ Suspense, useDeferredValue); обычные клики без перехода не анимируются. По умолчанию — простое перетекание (cross-fade).
- Четыре вида смены: enter (появилось), exit (исчезло), update (поменялось содержимое), share (один и тот же элемент «переехал» из одного места в другое по общему name).
- Заглушка → готовое: <ViewTransition update="auto" default="none"><Suspense fallback={...}>…</Suspense></ViewTransition> — заглушка появляется сразу, готовое содержимое въезжает плавно.
- Сама анимация задаётся обычным CSS по псевдоэлементам браузера: ::view-transition-old(*), ::view-transition-new(*) { animation-duration: 250ms; animation-timing-function: cubic-bezier(0.22, 1, 0.36, 1); }
- Направление (вперёд/назад) — через «тип перехода»: addTransitionType('next') и CSS-селектор :active-view-transition-type(next) — для карусели «влево/вправо».

**Для нашего сайта:** React нам не нужен: на чистом JS то же даёт document.startViewTransition(() => { /* поменять содержимое */ }), а между страницами — @view-transition { navigation: auto; } в CSS. Берём их тайминг 250 мс и мягкую кривую cubic-bezier(0.22, 1, 0.36, 1) — это как раз «тихая роскошь».

## json-server — программа на Node.js, которая из одного файла db.json поднимает пробный REST API (адреса для чтения/записи данных) на localhost:3000 без программирования.
https://github.com/typicode/json-server · [пост](https://t.me/sitodel/3931) · изучено
- Запуск: npx json-server db.json → по адресам /posts, /posts/1 можно GET/POST/PUT/PATCH/DELETE.
- Фильтры прямо в адресе: ?views:gt=100, сортировка ?_sort=-views, страницы ?_page=1&_per_page=10, связанные данные ?_embed=comments.
- Папка ./public отдаётся как статический сайт — можно смотреть вёрстку и «данные» вместе.
- Сейчас ветка 1.0 в стадии бета (1.0.0-beta.15, март 2026): id всегда строка, _limit заменён на _per_page, опции --delay больше нет.

**Для нашего сайта:** Нашему лендингу не нужен: данных с сервера нет, а форма заявки уходит в CRM. Может пригодиться, только если захотим локально сымитировать приём заявок до подключения Bitrix24.

**Безопасность:** 🟢 MIT, 75,7 тыс. звёзд, автор typicode известен; в npm-пакете нет install-скриптов (только dev/build/test), работает только на своём компьютере, наружу ничего не шлёт. Не ставили.

## Статья Ахмада Шадида: как на чистом CSS спрятать декоративный элемент, когда он подъезжает к тексту, — без медиазапросов и без JS.
https://ishadeed.com/article/css-detect-overlap/ · [пост](https://t.me/tproger_web/6583) · изучено
- Дать якоря (anchor-name) декору и секции и растянуть между ними невидимую «линейку»: `.measure { position: absolute; left: anchor(--line right); right: anchor(--section left); }` — её ширина = свободное место между ними.
- Внутрь линейки положить псевдоэлемент шириной 20px и задать линейке `overflow-x: auto`: когда места меньше 20px, линейка «переполняется» — это сигнал «столкнулись».
- Сигнал передаётся через анимацию от прокрутки (scroll-driven animation): `scroll-timeline: --touch x;` на линейке, `timeline-scope: --touch` у общего родителя, а на body анимация с одним кадром `from, to { --touching: 1; }`.
- Декор реагирует через style container query (запрос по значению CSS-переменной): `.decor { @container style(--touching: 1) { opacity: 0; } }`.
- Работает только в браузерах, где есть и anchor positioning, и scroll-driven animations; в остальных декор просто остаётся видимым — делать как необязательное улучшение.

**Для нашего сайта:** Если на средних экранах декоративная графика (линия, фото, орнамент) налезает на заголовок первого экрана — этот приём прячет её плавно ровно в момент касания. Чистый CSS, подходит нашей сборке; но сначала проще попробовать обычный @container по ширине секции.

## Разбор случая: на сайте с 6 языками китайские страницы выпали из Google, потому что canonical был со слешем в конце, а sitemap — без, да ещё Cloudflare переписывал адреса.
https://dev.to/korelyy/4-hours-lost-to-a-trailing-slash-what-shipping-multilingual-seo-actually-looks-like-4jni · [пост](https://t.me/tproger_web/6581) · изучено
- Google сравнивает адрес страницы и её canonical (адрес-«оригинал») посимвольно: разница в 2 символа — и он берёт тот, что увидел первым, а второй игнорирует.
- Выбрать одну форму адреса на весь сайт (со слешем или без, только строчные буквы, без ?параметров) и использовать её в canonical, hreflang (ссылки на языковые версии) и sitemap (карте сайта) одинаково.
- Проверить правила Cloudflare «нормализация/переписывание URL» и плагины, которые меняют href, — они меняют адреса незаметно.
- hreflang работает, только если каждая языковая версия ссылается на все остальные (и на себя).
- Автор планирует проверку при сборке: сборка падает, если canonical не совпадает с адресом в sitemap. После исправления ошибки в Search Console ушли за ~3 дня.

**Для нашего сайта:** В build.py добавить проверку: для каждой страницы canonical == адрес в sitemap.xml == внутренние ссылки (одна форма, например всегда со слешем). Если будет английская версия — сразу прописать hreflang в обе стороны.

## Обзор Флавио Копса: 12 возможностей современного CSS, которые заменяют старые костыли и часть JS.
https://flaviocopes.com/modern-css-features/ · [пост](https://t.me/tproger_web/6576) · изучено
- Слои каскада: `@layer reset, base, components, utilities;` — поздний слой побеждает ранний независимо от «силы» селектора; базу писать в `:where(...)` (нулевая специфичность), чтобы компоненты легко её перебивали.
- Выбор родителя по содержимому: `.field:has(input:invalid) { ... }` — подсветить поле формы с ошибкой без JS.
- Цвета: `--brand: oklch(55% 0.2 250);` и оттенки от него `color-mix(in oklch, var(--brand), white 15%)` — светлая/тёмная версия кнопки без ручного подбора.
- Высота экрана на телефоне без прыжков: `min-height: 100svh;` (учитывает панели браузера).
- Плавное появление из `display:none`: `@starting-style { ... }` + `transition: ... display 0.3s allow-discrete` — для выпадающего меню и модалки без JS-таймеров.
- Анимация от прокрутки `animation-timeline: view(); animation-range: entry 0% entry 100%;` — только внутри `@supports`, это ещё не во всех браузерах.

**Для нашего сайта:** Каркас CSS лендинга разложить по @layer, базу обернуть в :where(); оттенки бордового #6b1a24 и синего #222947 для наведения/нажатия получать через color-mix, первый экран — min-height: 100svh. Всё чистый CSS.

## Пен Aaron Iker «Truck button»: кнопка заказа переворачивается, по «дороге» уезжает грузовичок с коробкой, затем кнопка возвращается с зелёной галочкой «Order placed».
https://codepen.io/aaroniker/pen/oNgPOwo · [пост](https://t.me/sitodel/3924) · изучено
- Это не чистый CSS: анимацию двигает библиотека GSAP (JS), CSS только рисует грузовик и меняет состояния по классам `.animation` и `.done`.
- Переворот кнопки «плашмя»: `transform: rotateX(var(--rx, 0deg))`, в состоянии `.animation` — `--rx: -90deg; --br: 0;`, затем `.done` возвращает `--rx: 0deg`.
- Прогресс-полоса — псевдоэлемент `:after` с `transform: scaleX(var(--progress, 0))`; JS плавно меняет CSS-переменную: `gsap.to(button, {'--progress': 1, duration: 2.4, ease: 'power2.in'})`.
- Две подписи в кнопке: `.default` и `.success` наложены друг на друга, меняются через `opacity`; галочка рисуется SVG-обводкой `stroke-dasharray: 16px; stroke-dashoffset: var(--offset, 16px)` → 0.
- Общая длительность ~4 с, яркие цвета (фиолетовый, жёлтая коробка).

**Для нашего сайта:** Сам грузовик для премиум-инженерии слишком игривый. Взять идею «кнопка сама показывает результат»: после отправки заявки подпись плавно сменяется на «Заявка принята» с рисующейся галочкой (stroke-dashoffset) — это делается без GSAP, обычным transition на CSS-переменных и одним классом из JS.

## Андреа Бидзотто перенёс сайт на 400+ страниц на Astro с помощью ИИ-агентов за ~2 недели (100 задач, 80 закрытых PR) и описал, что сработало.
https://codewithandrea.com/articles/ai-agents-migrate-site-astro/ · [пост](https://t.me/tproger_web/6564) · изучено
- «100% как раньше» превратил в проверяемый контракт: список всех адресов, редиректов, метаданных, картинок, форм и явных исключений; отдельно записал, что сознательно выкидываем, чтобы агент не копировал мёртвый код.
- Сначала надиктовал мысли, потом попросил ИИ задать ему вопросы и разбить всё на фазы и задачи с критериями приёмки; не больше 2 агентов одновременно, каждый в своей копии репозитория (git worktree).
- Рискованное проверял одноразовым прототипом заранее (так нашёл проблему с картинками до того, как она задела сотни страниц).

## Статья-чеклист tproger: как облегчить картинки на сайте — размер, формат, второй проход сжатия, метаданные, AVIF.

## Статья Мануэля Матузовича: тень box-shadow не заменяет контур фокуса outline — в режиме принудительных цветов (для слабовидящих) тени отключаются.

## Классическая статья Джейка Арчибальда о правилах HTTP-кэша: два надёжных шаблона и один опасный.
https://jakearchibald.com/2016/caching-best-practices/ · [пост](https://t.me/tproger_web/6509) · изучено
- Файлы CSS/JS/картинки с хешем или версией в имени (`style.3f2a1c.css`) отдавать с `Cache-Control: max-age=31536000` — браузер год берёт их без запроса к серверу; при изменении меняется имя файла.
- HTML отдавать с `Cache-Control: no-cache` + `ETag` или `Last-Modified`: копия хранится, но каждый раз сверяется (сервер отвечает 304, если не изменилось).
- Антишаблон: `Cache-Control: must-revalidate, max-age=600` для изменяемых файлов — HTML, CSS и JS устаревают в разное время, пользователь получает несовместимую смесь версий; `must-revalidate` НЕ значит «проверять всегда».
- `no-store` — запрет кэша совсем (для личных данных).
- Service worker: при `cache.addAll` можно закэшировать старые версии из HTTP-кэша — лечится правильными заголовками по двум шаблонам выше.

**Для нашего сайта:** В build.py добавлять хеш содержимого в имена CSS/JS (style.<hash>.css) и подставлять в HTML; на хостинге — год кэша для этих файлов и no-cache для HTML. Тогда правки видны сразу и сайт не «ломается» у вернувшихся клиентов.

## Статья web.dev о том, как браузер рисует кадр, и почему одни анимации плавные, а другие дёргаются.
https://web.dev/articles/rendering-performance · [пост](https://t.me/tproger_web/6507) · изучено

## Tproger: CSS-функции sibling-index() (номер элемента среди соседей) и sibling-count() (сколько всего соседей) теперь работают во всех трёх движках браузеров.
https://tproger.ru/news/css-funkcii-sibling-index-i-sibling-count-zarabotali-vo-vseh · [пост](https://t.me/tproger_web/6452) · изучено
- Лесенка появления без JS: li { animation: fade-in 0.4s both; animation-delay: calc(sibling-index() * 80ms); }
- Ширина по числу карточек: .cards > * { flex-basis: calc(100% / sibling-count()); } — а для раскладки обернуть в @supports (width: calc(sibling-count() * 1px)) { … }.
