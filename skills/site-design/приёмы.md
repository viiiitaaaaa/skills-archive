2026-10-07 · [пост](https://t.me/tproger_web/6581)

## ★ Порядок стилей через @layer и :where() — без !important
2026-10-06 · [пост](https://t.me/tproger_web/6576)
В CSS можно заранее задать, какие стили главнее: `@layer reset, base, components, utilities;`. Правило из более позднего слоя всегда побеждает правило из раннего, даже если его селектор «слабее». Так утилита (мелкий класс вроде «отступ сверху») перебьёт стиль компонента без костылей `!important`.
Для базовых правил полезен `:where()` — он выбирает элементы, но не добавляет им «веса», и компонент потом легко задаёт своё оформление. Две оговорки: стили вне слоёв сильнее любых слоёв, а для `!important` порядок слоёв переворачивается.
**Для нашего сайта:** Когда Claude Code будет верстать лендинг, сразу разложим CSS по слоям reset → base → components → utilities, базу обернём в :where() — тогда правки стилей не будут драться друг с другом.

## ★ Картинки: сначала размер, потом формат
2026-10-03 · [пост](https://t.me/tproger_web/6562)
Чеклист оптимизации изображений. Начинать надо не с формата, а с размера: фото 6000×4000 в блоке шириной 1200 пикселей передаёт в 25 раз больше пикселей, чем нужно. Уменьшение до отображаемого размера сократило тестовый файл с 4,7 до 1,1 МБ без потери качества. Для экранов с высокой плотностью пикселей готовят несколько вариантов в `srcset` (список версий картинки, из которого браузер сам берёт подходящую).
Затем формат: WebP или AVIF для фото, PNG либо WebP без потерь для скриншотов, SVG для логотипов. В тесте AVIF занял 210 КБ против 420 КБ у JPEG при сопоставимом качестве, но кодируется примерно в 15 раз дольше — его делают заранее, при сборке сайта, а не на каждый запрос.
Порядок проверки: размеры → формат → качество → метаданные.
**Для нашего сайта:** У нас сайт держится на больших фото домов и интерьеров. Попросить Claude Code при сборке: каждое фото уменьшить до реального размера блока, сделать 2–3 варианта в `srcset`, сохранить в AVIF/WebP с запасным JPEG, логотип и иконки — в SVG.

## ★ Контур фокуса: не убирать outline ради тени
2026-09-19 · [пост](https://t.me/tproger_web/6521)
Фокус — подсветка кнопки или поля, на котором сейчас стоит клавиатура. Его часто рисуют тенью `box-shadow`, но в режиме принудительных цветов (настройка для слабовидящих) браузер тень отключает, и человек не видит, где он находится.
Нельзя писать `outline: none`. Если нужна красивая тень — добавить `outline: 2px solid transparent` и `outline-offset: 2px`: в обычном режиме контур прозрачен, в режиме принудительных цветов становится видимым.
Проверка в Chrome DevTools: вкладка Rendering, параметр `forced-colors` = `active`. Разбор — Manuel Matuzović.
**Для нашего сайта:** В стилях кнопок и полей формы заявки запретить Claude Code `outline: none`; использовать прозрачный контур плюс нашу тень. Проверить форму клавишей Tab.

## ★ Запасной шрифт надо писать при каждом font-family
2026-09-17 · [пост](https://t.me/tproger_web/6518)
Если на `body` задан набор `system-ui, sans-serif`, а на заголовке только «Open Sans», браузер НЕ вернётся к набору от `body`. Пока веб-шрифт грузится, он возьмёт свой шрифт по умолчанию — часто Times New Roman.
Если у запасного и основного шрифта разная ширина и высота букв, при подмене текст дёргается и сдвигает соседние блоки. Это ухудшает CLS (показатель неожиданных сдвигов макета, один из Core Web Vitals — оценок Google).

**Для нашего сайта:** В CSS-переменных со шрифтами сайта после имени фирменного шрифта всегда ставить запасной (`serif` или `sans-serif`), в том числе у заголовков. Проверить у Claude Code каждое место, где задан `font-family`.

Путь изменения: расчёт стилей и геометрии → отрисовка пикселей → сборка слоёв. Свойства `width`, `height`, `left`, `top` запускают все этапы. Цвет, фон, тень не требуют пересчёта геометрии. Если не нужна и перерисовка, браузер сразу собирает готовые слои.

**Для нашего сайта:** Правило для Claude Code: в анимациях появления блоков и наведения не менять `width`/`height`/`top`/`left`; если что-то дёргается — проверять в DevTools, какие этапы запускает анимация.

## ★ Правильная HTML-разметка: header, nav, main, alt
2026-09-11 · [пост](https://t.me/tproger_web/6487)
Исследование 2656 главных страниц крупных сайтов: полностью правильный HTML только у 12,8%. 41,6% страниц не размечают смысловые области, 20,4% сайтов оставляют картинки без `alt` (текстового описания).
Chrome сам «достраивает» кривую разметку, а скринридер (программа, читающая сайт вслух) читает именно её и путается.
Проверка за минуту: вкладка Accessibility в DevTools — если дерево областей пустое, начать с `header`, `nav` и `main`. Картинки без `alt` ловит инструмент `html-validate`.
**Для нашего сайта:** Попросить Claude Code верстать на смысловых тегах (`header`, `nav`, `main`), дать осмысленный `alt` каждому фото и прогнать готовую страницу через `html-validate`.

## ★ ИИ-поисковики видят только начальный HTML
2026-09-06 · [пост](https://t.me/tproger_web/6465)

## ★ Появление элементов по очереди одной строкой CSS
2026-09-03 · [пост](https://t.me/tproger_web/6452)
`sibling-index()` возвращает номер элемента среди соседей (с 1), `sibling-count()` — сколько всего детей у родителя; обе работают в `calc()`. С Firefox 154 их поддерживают все три движка (Chrome с 138, Safari с 26.2).
Примеры из поста: `li { animation-delay: calc(sibling-index() * 80ms); }` — каждый следующий пункт появляется на 80 мс позже; `.cards > * { flex-basis: calc(100% / sibling-count()); }` — ширина карточек по их числу.
Для декоративных задержек можно использовать сразу: старый браузер просто не применит правило. Для раскладки — завернуть в `@supports`. Считаются все соседи, включая скрытые.
**Для нашего сайта:** Карточки услуг, этапы работы, фото проектов выводить «лесенкой» через `animation-delay: calc(sibling-index() * 80ms)` — без JavaScript и без ручной нумерации элементов.

## ★ Ambient CSS: один источник света — согласованные тени
2026-09-02 · [пост](https://t.me/tproger_web/6444)
Библиотека Ambient CSS предлагает вместо ручных теней описать свет: направление, силу основного и заполняющего света, оттенок, высоту. Каждый элемент получает пятислойный `box-shadow` — тень, блики, фаски и внутренние затемнения, согласованные между собой.

**Для нашего сайта:** Посмотреть демо с компьютера. Если объём выглядит дорого — подключить `@ambientcss/css` для карточек и кнопок; если нет — взять сам принцип: один источник света и одинаковое направление всех теней на сайте.

## ★ Почему «светло и просто» выглядит дёшево — и как сделать тоньше
2026-03-25 · [пост](https://t.me/intelligentdesign/3658)
Пост про интерьер: скандинавский стиль часто выглядит дёшево, потому что его упрощают — убирают цвет, ставят белые стены и светлую мебель и на этом останавливаются. В оригинале он держится на нюансах: мягкий сложный свет, тёплые оттенки вместо чисто белого, фактуры (дерево, текстиль, матовые поверхности). Формула поста: это не «проще», а «тоньше».
Про сайты в посте не говорится, но принцип переносится напрямую: белый фон и пустота без нюансов дают «пустую светлую комнату».
**Для нашего сайта:** Не делать фон чисто белым `#FFFFFF` — взять тёплый оттенок; добавить фактуру (лёгкое зерно, фото материалов) и мягкие тени. Минимализм лендинга собирать из нюансов, а не из пустоты.

## ★ Формула спокойной палитры: 1 базовый + 2 поддерживающих + 1 акцент
2026-01-31 · [пост](https://t.me/intelligentdesign/3643)
Пост про интерьер. Спокойная палитра: один базовый оттенок, два поддерживающих, один акцентный, и все — в близкой температуре (все тёплые или все холодные). Цвета выбирают не по отдельности, а смотрят, как они работают вместе. Такая палитра — основа интерьера, который долго не устаревает.
**Для нашего сайта:** Ограничить палитру сайта четырьмя цветами по этой формуле: базовый тёплый фон, два поддерживающих (тёмный для текста и промежуточный для плашек), один акцент только для кнопки заявки и ключевых деталей. Проверять сочетание на готовом экране, а не на образцах.
