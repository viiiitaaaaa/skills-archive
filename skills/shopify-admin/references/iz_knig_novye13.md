## Gulli «Agentic Design Patterns» (4)


### Магазин одежды

- **Описание товара цепочкой, а не одним промптом.** Делать карточку в 3–4 отдельных шага: (1) из данных 1688/фото вытащить факты в JSON (ткань, длина, посадка, уход), (2) по фактам — выгоды для женщины 28+, (3) текст описания, (4) самокоррекция по шаблону «Self-Correction Agent». Зачем — один длинный промпт теряет часть требований и выдумывает. Когда — при заведении каждой новой юбки/вещи в Shopify. (гл. 1, стр. 24; гл. 17, стр. 268) → shopify-admin
- **Факты товара — только из JSON-шага.** Шаг «текст» получает лишь проверенный JSON, а не сырую страницу поставщика; в промпте: «опирайся только на переданные поля, недостающее помечай „нет данных“». Зачем — не выдумывать состав и размеры (риск возвратов и жалоб). Когда — всегда при генерации описаний. (гл. 3, стр. 60–61; гл. 5, стр. 88–89) → shopify-admin
- **Фильтр-«контролёр» для будущего чат-бота магазина.** Если ставим бота в Shopify: перед основным ответом дешёвая модель с температурой 0 проверяет вход на попытку взлома инструкций («забудь правила»), оскорбления, политику/религию, просьбы о конкурентах — и отвечает JSON `compliant/non-compliant`. Когда — при подключении любого ИИ-чата на сайт. (гл. 18, стр. 289–290) → shopify-admin
- **Проверять, что инструмент честно сообщает «нет данных».** Скрипты, которые берут остатки/цены (Shopify, посредник), должны возвращать явную ошибку, а агент — говорить «не удалось получить», а не угадывать. Когда — любые автоматические ответы про наличие товара. (гл. 5, стр. 87–89) → shopify-admin

## Hur, Song «Build an AI Agent (From Scratch)» (2)


### Магазин одежды

- **Возврат: модель даёт только причину, номер заказа подставляет код.** В автоматике возвратов/обменов инструмент `submit_refund(reason)`, а `order_id` берётся из сессии кодом. Зачем — модель путает похожие номера между ходами («дрейф ID»); меньше токенов и ошибок. Когда — если будем делать ИИ-обработку обращений. (гл. 3, стр. 76–77) → shopify-admin
- **Подтверждение «денежных» действий с паузой и правкой аргументов.** Если делаем автоматику цен/скидок/закупок: агент собирает предложения, ставит каждое «на подтверждение» (что, с какими параметрами), она в Telegram одобряет часть, может поправить цифру (`modified_arguments`) — и только тогда выполняется; неодобренное агент получает как отказ с причиной. Ср. Гулли №8 (что утверждать) — здесь КАК: пауза и продолжение через сохранённое состояние. (гл. 6, стр. 194–203) → shopify-admin

## Mollick «Co-Intelligence» (1)


### Магазин одежды

- **Описания товаров — «поручаемая» задача.** ИИ пишет описание, человек обязательно сверяет точные данные (состав, размеры, обхваты, уход) с карточкой поставщика: точные цифры — то, что ИИ дорисовывает. (гл. 5, стр. 90; гл. 6, стр. 117) → shopify-admin

## Whalen «Design for How People Think» (5)


### Магазин одежды

- **Значки способов оплаты — рано.** Логотипы PayPal / Apple Pay / Shop Pay / карт показывать уже на карточке товара (под ценой), а не только в чекауте. Зачем — многие сначала проверяют «примут ли мой способ», иначе не идут дальше. Когда — тема Shopify, блок под кнопкой. (гл. 13, стр. 147) → shopify-admin
- **Купон — до решения о покупке.** Дать понять на карточке/в корзине, что скидка уже применится (автоскидка Shopify или поле промокода в корзине, цена «после скидки» видна сразу). Не заставлять «соглашаться на полную цену», чтобы потом ввести код. Когда — настройка скидок и корзины, любая промо-акция. (гл. 13, стр. 147, 149) → shopify-admin
- **Слово «Cart», а не «Bag» (или с подписью).** Для США привычнее «cart»; если тема пишет «Bag», проверить, понимают ли; надёжнее иконка + подпись. Проверить и другие названия меню: не использовать красивые внутренние слова («Edit», «Drop», «Issue 03») без пояснения — «Issues» у IMLS поняли как «проблемы». (гл. 10, стр. 120–121, 123–124) → shopify-admin
- **Две глубины текста на карточке.** Коротко простыми словами для новичка (как сидит, с чем носить) + раскрывающийся блок «детали» для знатока (состав, плотность, крой, мерки в см/дюймах). Как Cancer.gov: версия для пациента и для врача. Если выбирать — в пользу новичка. (гл. 5, стр. 67; гл. 10, стр. 120) → shopify-admin
- **Поиск понимает оба слова.** В тегах/синонимах товара держать и «модное» слово, и бытовое («pleated» и «with folds», «plaid» и «checkered», «tartan»); как MedlinePlus — «TIA» и «mini-stroke». Когда — заполнение тегов, настройка Search & Discovery в Shopify. (гл. 10, стр. 119–120) → shopify-admin

## «The 0→1 Loop Engineering Playbook» (2026) (1)


### Магазин одежды

- **Описание товара — максимум 2 круга правки.** Черновик → оценка по рубрике (точность фактов из карточки 1688, ясность, тон, SEO) → улучшить только самое слабое измерение → стоп после 2 кругов или если прирост < 0,05. Зачем: по книге описание товара даёт +20 % конверсии за 2 круга, дальше «правка по кругу». Когда: массовая заливка описаний. (гл. 17, стр. 223–227) → shopify-admin

## Minto «The Pyramid Principle» (1)


### Магазин одежды

- **Описание товара — пирамидой.** Первая строка — главная выгода для женщины 28+, затем 3 довода одного типа (ткань / посадка / уход), без «Описание», «Характеристики» как пустых категорий наверху. Когда — при чистке описаний через Admin API. (гл. 4, стр. 59; гл. 1, стр. 26–28) → shopify-admin

## Fitzpatrick «The Mom Test» (1)


### Магазин одежды

- **Цитаты покупательниц — в тексты.** Записывать дословные фразы покупательниц (из отзывов, переписки) в кавычках и по ним писать описания, заголовки, рекламу. Когда: карточки, лендинг, креативы. (гл. 8, стр. 104) → shopify-admin

## Klaff «Pitch Anything» (1)


### Магазин одежды

- **В описании — одна сильная выгода, а не пять средних.** Зачем: впечатление — среднее, а не сумма. Когда: тексты карточек и баннеров. (гл. 4 / ч. 11) → shopify-admin

## Agrawal, Gans, Goldfarb «Prediction Machines» (5)


### Магазин одежды

- **Выписывать цену обеих ошибок у каждого автофильтра.** Для любого автоправила магазина (антифрод заказов, авто-скрытие товара без остатка, автоответ в чате) записать: сколько стоит ложная тревога (зря отказали честной покупательнице) и сколько стоит пропуск (пропустили мошенника, продали несуществующий товар). Зачем — порог фильтра ставится по ценам ошибок, а не «по точности». Когда — при настройке любого автоматического правила. (гл. 9, 13; ч. 18, 22) → shopify-admin
- **Порог отмены заказа по формуле кредитки.** Отменять подозрительный заказ, если вероятность мошенничества × потеря от него > вероятность честного заказа × цена её недовольства (включая потерю будущих покупок). Зачем — антифрод Shopify даёт риск «high/medium», а решение — наше. Когда — каждый заказ с пометкой риска; крупные суммы считать отдельно. (гл. 9, ч. 18) → shopify-admin
- **Автомат там, где ставки низкие; человек — где высокие.** Блоки «с этим покупают», похожие товары, сортировку каталога отдавать алгоритму полностью (ошибка дешёвая, как у Amazon), а ответы про размер, возврат, сроки и жалобы — живому человеку или проверенному шаблону (ошибка теряет покупательницу навсегда, как у Tesla). Зачем — не тратить ручной труд на дешёвые ошибки и не экономить на дорогих. Когда — настройка чата, рекомендаций, писем. (гл. 13, ч. 22) → shopify-admin
- **Антифрод «по исключениям».** Обычные заказы проходят автоматически по оценке Shopify, вручную она смотрит только выбивающиеся (большая сумма, разные адреса, необычная страна). Зачем — её время только на редкое. Когда — после запуска продаж. (гл. 7, ч. 15) → shopify-admin
- **«Зашивать» ответ заранее — только для точных и частых вопросов.** Автоответы — на вопросы с однозначным ответом (сроки доставки, состав, таблица размеров); всё, где надо взвесить «а что если ошиблись», — ей. Зачем — суждение можно закодировать, только когда прогноз точный (Ada Support). Когда — настройка чата и FAQ. (гл. 9, ч. 18) → shopify-admin

## Mendelevitch «Hands-On RAG for Production» (2)


### Магазин одежды

- **Поиск по сайту: нет в наличии — вниз, новое — вверх.** Если делаем свой поиск/подборки: после сортировки по смыслу — правила (нет в наличии → вниз или скрыть, новинки → выше, одна модель в 5 цветах → одна строка). (гл. 3, стр. 109) (дополняет Polzer №52) → shopify-admin
- **Своё приложение vs готовое — ×3 к оценке.** Решая «свой скрипт для Shopify или приложение», закладывать в «своё» в 3–5 раз больше времени/денег (поддержка, поломки после обновлений темы/API). (гл. 4, стр. 149) → shopify-admin

## Polzer «RAG with Python Cookbook» (1)


### Магазин одежды

- **Описания и alt-тексты фото моделью.** Мультимодальная модель описывает фото товара (фасон, вид ткани, длина, детали) → черновик alt-текста и описания для SEO; цифры (длина, состав) — только из карточки поставщика, не «с картинки». (3.8 стр. 82–84; 3.7 стр. 81) → shopify-admin

## Knaflic «Storytelling with Data: Before and After» (4)


### Магазин одежды

- **Письмо покупателю в три блока по важности для неё.** Сначала то, что важно покупательнице (заказ, скидка, статус), потом цифры, потом наша просьба (отзыв, обновить данные); мелочи (опрос) — в самом конце мелким. Зачем: в исходном письме GFST самым заметным было неважное. Когда: шаблоны писем Shopify о заказе, брошенной корзине, отзыве. (гл. 13, стр. 250–256) → shopify-admin
- **Кнопка сразу после шагов.** В письме и на странице кнопку действия ставить прямо под нумерованными шагами, а не отдельно сверху. Когда: письма и всплывающие окна магазина. (гл. 13, стр. 256) → shopify-admin
- **Текст для быстрого просмотра.** Описания и баннеры: не меньше 16 px на экране, заголовки категорий жирным и цветом, одна строка подзаголовка. Зачем: решение «читать дальше или нет» принимается за секунды. Когда: описания товаров, страницы коллекций. (гл. 16, стр. 293–294) → shopify-admin
- **Сокращения писать полностью.** Не «sz», «qty», «pcs» на витрине; любое сокращение расшифровать при первом упоминании. Когда: описания, таблицы размеров, письма. (гл. 7, стр. 140–141) → shopify-admin
