# Улучшить скилл по прошлым ошибкам

Идея: скилл — это текст, который можно «тренировать» как ученика: берём примеры, где он ошибся, правим текст,
проверяем на этих и на старых примерах, оставляем правку, только если хуже не стало.
Всё делаем руками здесь, в одной вкладке: **без хуков, без расписания, без сети, без чтения всех сессий подряд**
(это и было причиной, почему SkillOpt целиком мы не поставили).

## Откуда брать ошибки (только эти места, ничего лишнего)

1. Её поправки: `~\.claude\projects\...\memory\` (файлы `uchitsya-na-popravkah` и записи «не так», «опять»), CLAUDE.md.
2. Вердикты проверяльщика (`proverka`): ❌ и ⚠️, особенно строка «Урок».
3. `python C:\Users\User\komputer\proverki\sverka.py --zhurnal` — повторы в журнале.
4. То, что она сказала в ЭТОЙ вкладке.
Сессии целиком не читать. Нужно 3–8 случаев; меньше трёх — рано, сказать ей «мало примеров, жду ещё».

## Замечать ошибки САМОЙ (её слово 26.10.2026: «я не смогу отследить, правильно ли скилл сработал — ты должен сам понять»)

Не ждать её поправки. После каждого дела, где брали скилл с книгами (Lean, Minto, Storytelling, Make It Stick, Peak, Mind и др.):
1. Пройти «Самопроверку» из самого скилла (если её нет — добавить при первой правке).
2. Сверить 2–3 числа/страницы скилла с текстом книги (`knigi_kupleno	xt13\*.txt`, метки «=== стр. N ===»).
3. Спросить себя: подал ли я чужую цифру как норму для её дела? выдумал ли порог? ответил ли, не открыв скилл?
4. Нашла промах — сразу исправить скилл (по шагам ниже), одной строкой сказать ей «поправила в <скилле>: …».
Её саму просить оценивать работу скилла не надо.

## Шаги

0. **Копия.** Положить копию `SKILL.md` рядом: `SKILL.md.do_<ДДММ>`. Откат = вернуть копию.
1. **Мини-набор (5–10 проверок).** Из случаев выше: «ситуация → что скилл должен сделать». Одна проверка — одна строка
   с ответом «верно / неверно», который можно решить по тексту, а не на глаз. Хотя бы 2 проверки — на то, что скилл
   делал ПРАВИЛЬНО до правки (чтобы не сломать).
2. **Прогон ДО.** Для каждой проверки: что сделал бы скилл в старом виде. Записать «до: N из M».
3. **Правка.** Одна-две небольшие правки (добавить правило, убрать лишнее, уточнить фразу). Не переписывать скилл целиком.
   Слова — её, дословно, если она давала формулировку.
4. **Мини-набор ПОСЛЕ.** Тот же набор по новому тексту. Не стало лучше — откат, другая правка. Третья неудача подряд —
   стоп и сказать ей (правило «одно действие 3 раза без новой информации»).
5. **Полный набор.** Все проверки, включая «старые правильные» и случаи из других скиллов, где этот скилл подключается.
   Проверку делает не тот, кто правил: отдать `proverka` (Sonnet) — задание файлом, с ответом «до / после» по строкам.
6. **Принять — только если** «после» строго лучше «до» И ни одна «старая правильная» не сломалась. Иначе откат.
7. **Журнал.** Одна запись в `<папка скилла>\ZHURNAL_pravok.md`: дата, что поправили, «до N из M → после N из M», как откатить.
8. Сказать ей тремя строками: что поправили, было/стало, как откатить.

## Чего не делаем

- Не ставим хуки и ночные задачи «само улучшается». Правим только по её просьбе или на второй повтор ошибки.
- Не отправляем куски её разговоров в чужие модели и облако. Проверки пишем сами, из её слов.
- Правила для CLAUDE.md и памяти правим так же, но сначала показываем ей строку «было → стало».
- Чужие скиллы (из карантина) не правим — сначала проверка по `proverka_chuzhogo.md`.
- «Стало лучше» без цифр «до/после» не принимается.
