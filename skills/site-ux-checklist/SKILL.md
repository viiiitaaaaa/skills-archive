# Чек-лист сайта (по идеям ui-ux-pro-max, 27.10.2026; чужой код не ставили)
Порядок важности: сверху вниз. Цвета, шрифт, шкала размеров и отступы — НАШИ из site/DESIGN.md, этот список их не меняет.
Перед правкой вида — читать site/DESIGN.md и site/UX.md; дизайн не трогать без её «да» (каркас сначала).

1. **Доступность (критично).** Текст ≥ 4,5:1 к фону. alt у смысловых картинок. Заголовки по порядку h1→h2→h3. Кнопка-иконка — с aria-label. Поле формы — с видимой подписью (не только placeholder). Фокус виден (outline не убирать). Есть ссылка «Перейти к содержимому» в самом верху. Цвет — не единственный признак (ошибка = цвет + текст).
2. **Нажатия.** На телефоне зона ≥ 24×24 px (минимум WCAG; наша цель ≥ 44 для главных кнопок). Важное действие не только по наведению (hover). Кнопка «Отправить» при отправке блокируется и показывает «Отправляем…».
3. **Скорость.** Картинки webp/avif нужного размера, ленивая загрузка ниже первого экрана, место под картинку зарезервировано (width/height, aspect-ratio) — сдвига нет. Шрифт: font-display: swap. Скрипты сторонних сервисов — async/defer.
4. **Одна страница с якорями (наш случай).** Плавная прокрутка (scroll-behavior: smooth) + `scroll-padding-top` = высота шапки, иначе шапка закрывает заголовок блока и элемент в фокусе. Активный пункт подсвечен. Для 100vh на телефоне — svh/dvh.
5. **Вёрстка.** Нет прокрутки вбок на 320/375/414/768/1024/1440. Строка текста 65–75 знаков (max-width в ch). Межстрочный 1,5–1,75. Тело текста на телефоне ≥ 14–16 px (наша шкала: 14). Длинные слова/ссылки не ломают блок (overflow-wrap). Карточки не обрезают смысл («…»).
6. **Анимация.** Двигаем только transform и opacity. Уважать prefers-reduced-motion. Слайдер: кнопка паузы, стоп при наведении и фокусе, стрелки (у нас есть). 1–2 движущихся элемента на экран; бесконечные эффекты — только индикатор загрузки.
7. **Формы (у нас — телефон + согласие).** Тип `tel`, autocomplete, ошибка под полем и читается скринридером (aria-live/role=alert), после отправки — «принято» или «ошибка, повторите»; не просить одно и то же дважды.
8. **Структура лендинга под нашу цель (заявки).** Образец «Доверие и авторитет + заявка»: сильный первый экран (результат + кнопка) → доказательства (объекты, процесс) → решение/услуги → одна понятная кнопка-заявка, повторённая после доказательств и внизу; кнопка заявки видна в шапке. Одно главное действие на экран.
9. **Содержание.** Реальные тексты, не lorem; числа с неразрывным пробелом; пустых состояний нет.

Как применять: пройти пункты по порядку, записать «нашла N, исправила M, ждёт её слова K». Исправления вида (дизайн) — только с её согласия.

10. **Приёмы вёрстки из новостей 27.10.2026** (по пересказам помощников, в браузере НЕ проверено; источник — канал/номер в `site-design/references/iz_novostey_2710.md`). Перед применением проверить поддержку браузеров (Safari!):
   - Кнопкам и интерактивным элементам — `touch-action: manipulation` (нет зума при двойном тапе) [frontend_baza/2500].
   - В базовые стили — `scrollbar-gutter: stable` (страница не дёргается при появлении полосы прокрутки) [tproger_web/6633].
   - Flex-строка с длинным текстом и многоточием — `min-width: 0` у обёртки [tproger_web/6637].
   - Выезжающая корзина и меню: `overscroll-behavior-y: contain` (фон под ними не листается) [6640]; закрытое меню/панель — атрибут `inert` [6642].
   - Шрифты: размеры через `clamp()` без лишних брейкпоинтов [frontend_baza/2512]; `preconnect` только на домен шрифтов [tproger_web/6643].
   - Не использовать `unload` (в Chrome 155 перестаёт срабатывать): отправку аналитики — по `visibilitychange`/`pagehide` [6646]. Отправку формы из JS — `form.requestSubmit()`, а не `submit()` [6632].
   - Не вешать `:root:has(...)` на весь документ (тормозит); следить за сдвигами вёрстки [frontend_baza/2514]. `ResizeObserver` не должен менять размер наблюдаемого элемента без конечного состояния (цикл) [6636].
   - Видео на лендинге: постер WebP, сжатие FFmpeg, запуск по первому действию (с 3,1 МБ до 400 КБ) [2487]. Фото: JPEG XL сравнить с WebP, но оставить запасной формат [2515].
   - Иконки на CSS (`mask`, переменные) вместо спрайтов — проверить в Safari [2504, 6645]. Тултипы и меню на CSS anchor + `popover`, scrollspy на CSS — только с проверкой поддержки [2513, 2525].
   - Если появится сборка JS: лимит размера бандла (Size Limit) [2496].
11. **Перед запуском сайта и приёмом оплаты** (из новостей 27.10.2026; не проверено на практике):
   - Список из поста vibecoding_tg/4142 «23 пункта перед первым платежом» (в канале пост обрезан на 13-м; полный — открыть в канале): дизайн-система, экраны «загрузка / пусто / ошибка», секретные ключи только на сервере, проверка прав на каждом входе (эндпоинте), лимиты на платные сервисы, проверка подписи платёжных вебхуков и защита от повторов, тест возвратов и неудачных списаний, суммы целыми числами в минимальных единицах валюты, защита от двойного нажатия, налог с продаж и юридические страницы.

Задать на хостинге и проверить ответ сервера [c/3493639787/838].
