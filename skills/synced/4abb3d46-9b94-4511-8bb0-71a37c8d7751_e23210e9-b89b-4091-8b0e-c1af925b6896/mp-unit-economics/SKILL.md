# Юнит-экономика маркетплейсов (WB / Ozon)

Пользователь каждый период выгружает отчёты из личного кабинета и хочет одно: вставить их в файл и получить готовую статистику по каждому артикулу — продажи, возвраты, комиссию, логистику, рекламу, хранение, налоги, прибыль, маржу.

Задача скилла — собрать такой файл или починить сломавшийся, **не сломав при этом то, что пользователь уже настроил сам**.

## Главное правило: почему эти файлы ломаются

Excel **отслеживает** обычные ссылки вида `Sheet1!$N:$N`. Когда пользователь удаляет строки или столбцы внутри листа-приёмника (а он делает это каждый период, очищая старые данные), Excel физически переписывает все формулы, которые на этот лист ссылались, превращая их в `#ССЫЛКА!` / `#REF!`. Файл выглядит «сломавшимся сам по себе».

**Решение — ДВССЫЛ (`INDIRECT`).** Для Excel `"Sheet1!N:N"` — это просто текст в кавычках, отследить и сломать его нельзя:

```
=СУММЕСЛИМН(ДВССЫЛ("Sheet1!N:N");ДВССЫЛ("Sheet1!F:F");$A4;ДВССЫЛ("Sheet1!K:K");"Продажа")
```

Все формулы, которые ссылаются на листы-приёмники, пиши через ДВССЫЛ. Это единственный способ сделать файл действительно устойчивым.

### Ловушка: не заворачивай `ИНДЕКС+ПОИСКПОЗ` внутрь `СУММЕСЛИМН`

Соблазнительно искать колонку по названию заголовка:

```
СУММЕСЛИМН(ИНДЕКС(Sheet1!$1:$1048576;0;ПОИСКПОЗ("Кол-во";Sheet1!$1:$1;0)); ...)   ← НЕ ДЕЛАЙ ТАК
```

Выглядит умно, но **ломает регистронезависимость СУММЕСЛИМН**: артикул `JK-577` в сводной перестаёт находить `jk-577` в отчёте, и деньги молча теряются. Это реальный баг, который стоил ~13 000 ₽ логистики в проде. Для поиска значения по одному ключу `ИНДЕКС+ПОИСКПОЗ` — нормально, внутри `СУММЕСЛИМН` — нет.

## Порядок работы

### 1. Сначала разведка, потом код

Никогда не предполагай структуру отчёта — открой и посмотри. Маркетплейсы регулярно добавляют колонки и служебные строки. Проверь для каждого файла: где заголовки (строка 1? 2? двухуровневые?), где артикул, где нужные суммы.

```python
import openpyxl
wb = openpyxl.load_workbook(f, data_only=True)
for r in range(1, 4):
    for c in range(1, ws.max_column + 1):
        v = ws.cell(row=r, column=c).value
        if v is not None:
            print(f"  {openpyxl.utils.get_column_letter(c)}{r}: {v!r}")
```

Точные раскладки известных отчётов — в `references/report-layouts.md`. Сверяйся с ними, но всегда подтверждай по факту: если реальный файл разошёлся с описанием, прав файл, а справочник надо обновить.

### 2. Определи, что уже настроил пользователь

Если работаешь с действующей книгой Ozon — её раскладка, рабочий цикл и контрольные цифры описаны в `references/user-workbook.md`, а список артикулов, за которыми пользователь следит, — в `references/articles.md`. **Прочитай эти файлы первыми** и сохраняй структуру: строка итогов, порядок колонок и архивные листы по месяцам уже завязаны на дашборд.

Если файл существует — он почти наверняка содержит ручную работу: листы с историей по периодам, дашборд «Динамика финансы», свои колонки. **Это надо сохранить.** Перед любой правкой найди, на какие ячейки ссылается дашборд:

```python
import re
refs = set()
for row in wb['Динамика финансы'].iter_rows():
    for cell in row:
        if isinstance(cell.value, str) and cell.value.startswith('='):
            for m in re.finditer(r"'?([^'!]+)'?!\$?([A-Z]+)\$?(\d+)", cell.value):
                refs.add((m.group(1), m.group(2), int(m.group(3))))
print(sorted(refs))
```

Если дашборд читает итоги из строки 333 — итоги обязаны остаться в строке 333. Вставка строки выше сдвинет всё и обнулит дашборд. Пиши в свободные строки ниже данных, а не `insert_rows`.

### 3. Собери сводную на СУММЕСЛИМН

Обычную сводную таблицу Excel нужно обновлять вручную — это ровно то, от чего пользователь хочет уйти. Замени её листом с формулами: столбец артикулов + СУММЕСЛИМН по каждому показателю. Пересчитывается сам, обновлять нечего.

Формулы должны читать **сырые колонки отчёта напрямую**. Не заводи вспомогательные колонки в листе-приёмнике (типа «КОЛ ПРОДАЖ» рядом с данными) — пользователю придётся дописывать их после каждой вставки, а это и есть та ручная работа, которую убираем. Разделение продаж и возвратов делается вторым условием СУММЕСЛИМН.

### 4. Проверь результат независимым пересчётом

Обязательный шаг. Посчитай итоги питоном прямо из исходных файлов и сравни с тем, что показывает книга. Готовый скрипт: `scripts/reconcile.py`.

```bash
python3 /mnt/skills/public/xlsx/scripts/recalc.py файл.xlsx 180   # 0 ошибок формул
python3 scripts/reconcile.py файл.xlsx                            # цифры сходятся
```

Ноль ошибок формул — необходимое, но недостаточное условие. Файл без единой ошибки может молча недосчитывать деньги. Проверяй сходимость сумм.

### 5. Расхождение в сумме = пропущенный артикул

Если итог сводной меньше сырых данных — почти всегда какого-то артикула нет в списке сводной. Типичные виновники:

- **`неопознанный товар`** — WB подставляет его сам, когда не может определить товар; в списке артикулов пользователя его нет
- новые артикулы, появившиеся в продаже, но не заведённые в юните
- разный регистр (`JK-577` против `jk-577`) — при дедупликации списка сравнивай в нижнем регистре, иначе получишь строку-дубль и двойной счёт

Найди виновника, а не подгоняй итог:

```python
missing = [a for a in raw_by_article if a.lower() not in {x.lower() for x in pivot_articles}]
```

### 6. Сверься с экраном «Экономика магазина»

У Ozon в разделе Финансы → Начисления и документы есть сводка за период — это независимая проверка от самой площадки. Попроси у пользователя скриншот или сверь по числам, которые он назовёт: «Продажи и возвраты», «Итого» и разбивка начислений по группам.

Сходиться должно точно, до рубля:

```python
screen = {'Вознаграждение Ozon': -447820, 'Услуги доставки': -98458,
          'Продвижение и реклама': -54691, 'Услуги партнёров': -27263,
          'Услуги FBO': -15539}
for k, v in screen.items():
    print(k, groups.get(k, 0) - v)
```

Учти, как Ozon группирует на этом экране: блок «Начисления» показывает **только расходы** — возвраты туда не входят, они в первом блоке вместе с выручкой. Поэтому сумма отрицательных групп из отчёта будет больше числа на экране ровно на величину возвратов. «Итого» же сходится напрямую с суммой всех групп.

### 7. Отдельно сверь остатки

Товары **без продаж в периоде** не попадают в юнит через сводную — продаж нет, значит и строки нет. Но на складе они лежат, и итог остатков окажется занижен. Пользователь это замечает: «на складе 6935, а ты вывел 5042».

Поэтому сверяй остатки отдельно от денег — сумма по отчёту остатков против итоговой ячейки:

```python
raw = sum(ws_o.cell(row=r, column=10).value or 0        # J — остаток
          for r in range(3, ws_o.max_row + 1)
          if ws_o.cell(row=r, column=4).value)          # D — артикул
```

Расходятся — добавь недостающие артикулы в юнит, сводную и справочник себестоимости. Прибыль от этого не изменится (продаж нет), зато станут видны замороженные в товаре деньги.

## Закрытие периода

Типовая просьба — «сделай период с 1 по 16 августа». Порядок:

1. **Проверь структуру свежих отчётов** — не поменялись ли колонки (см. шаг 1).
2. **Убедись, что прошлый период заархивирован** — лист с именем периода, только значения, без формул. Если пользователь скопировал лист сам, он мог называться `1 (2)` и содержать живые формулы: переименуй по периоду и пересохрани снимком значений, иначе архив «поедет» при следующем пересчёте.
3. **Очисти листы-приёмники, сохранив шапку**, и вставь новые отчёты с нужной строки.
4. Обнови маркер периода в `A1` листа начислений.
5. **Пересчитай и сверь** — `recalc.py`, затем `reconcile.py`, затем отдельно остатки.
6. **Создай архив нового периода** — копия рабочего листа значениями:

```python
dst = wbf.create_sheet(NAME, idx)
for row in src_f.iter_rows():
    for cell in row:
        new = dst.cell(row=cell.row, column=cell.column,
                       value=src_v.cell(row=cell.row, column=cell.column).value)
        if cell.has_style:
            new.font = copy(cell.font); new.fill = copy(cell.fill)
            new.border = copy(cell.border); new.number_format = cell.number_format
```

`src_f` — книга с `data_only=False` (для стилей), `src_v` — с `data_only=True` (для значений).

Отчёт по остаткам может не прийти вместе с остальными — он снимок на дату, а не за период. Тогда оставь прежний и скажи об этом пользователю.

## Если нужно добавить строки

Строка итогов адресуется дашбордом напрямую, поэтому просто так вставить артикулы нельзя. И `insert_rows` в openpyxl **не сдвигает ссылки внутри формул** — строки переедут, а формулы будут указывать на старые адреса.

Порядок, который работает:

1. Посчитай новый номер строки итогов: `NEW_TOT = последний_артикул + количество_новых + 2` (одна строка-разделитель).
2. Сотри старую строку итогов и мусор под данными.
3. Возьми **шаблон формул с любой заполненной строки** и подставь новый номер:
   ```python
   nf = re.sub(r'(?<![0-9$])20(?![0-9])', str(r), formula_from_row_20)
   ```
   Негативный lookbehind по `$` защищает абсолютные ссылки вида `$T$166` — их менять нельзя как номер строки.
4. **Обнови ссылки на итоги во всех строках** — формула доп услуг тянет `$T$166/$G$166`, эти адреса должны указывать на новую строку итогов.
5. Перепиши строку итогов на новом месте, расширив диапазоны `СУММ`.
6. **Перенастрой дашборд** — найди и замени все ссылки на старую строку:
   ```python
   if re.search(r"'1'!\$?[A-Z]+\$?166", v):
       cell.value = re.sub(r"('1'!\$?[A-Z]+\$?)166", rf"\g<1>{NEW_TOT}", v)
   ```
7. Добавь те же артикулы в сводную и в справочник себестоимости.
8. Пересчитай и сверь: прибыль не должна измениться, если у новых артикулов не было продаж.

После такой операции обязательно скажи пользователю, что строка итогов переехала — он копирует лист вручную и должен знать новый адрес.

Когда пользователь пишет «опять ошибка» — не переписывай файл заново. Пройди по чеклисту в `references/troubleshooting.md`: там симптом → причина → фикс для всех случаев, которые уже встречались (`#REF!` после вставки, `export!#REF!`, нули по всему юниту, лишняя строка «Период» в отчёте Ozon, расхождение логистики, слетевший дашборд).

Начинай всегда с полного скана — он за секунду показывает, где именно беда:

```python
for sn in wb.sheetnames:
    for row in wb[sn].iter_rows():
        for cell in row:
            v = cell.value
            if isinstance(v, str) and v.startswith('=') and ('#REF!' in v or '[' in v.split('"')[0]):
                print(sn, cell.coordinate, v[:80])
```

`[` в формуле означает ссылку на **внешний файл** (`[1]Лист1`) — данные будут браться из чужой книги или не браться вовсе. Такие ссылки надо переводить на локальные листы.

## Экономика: чем WB отличается от Ozon

Разница не косметическая, перепутать нельзя. Полные формулы обеих моделей — в `references/unit-economics.md`. Ключевое:

| | Wildberries | Ozon |
|---|---|---|
| Разделение продаж/возвратов | одно поле «Обоснование для оплаты» | два поля: «Группа услуг» + «Тип начисления» |
| Знак возвратов | положительный → выручка `= продажи − возвраты` | **отрицательный** → выручка `= продажи + возвраты` |
| Реклама | в отчёте аналитики, по артикулам | в начислениях **без артикула**; по артикулам только из ListExpense |
| Прочие расходы | — | «Доп услуги»: всё, кроме 5 основных групп, распределяется по количеству |

## Оформление файла

Пользователь работает с этим файлом каждую неделю — навигация должна читаться с одного взгляда.

- 🟢 зелёные ярлычки — листы, куда вставляют отчёты
- 🔵 голубой — сводная (считается сама)
- 🟠 оранжевый — итоговая статистика
- 🟡 жёлтый — себестоимость (справочник, заполняется руками)
- 🔷 тёмно-синий — инструкция

В шапке листов-приёмников подсвечивай ключевые колонки: зелёным — артикул для сопоставления, голубым — суммируемые значения. Лист «Инструкция» первым: куда что вставлять, с какой ячейки, что считается само.

Себестоимость держи отдельным листом-справочником (артикул → цена). Она не приходит ни в одном отчёте, и если её тянуть из внешнего файла, связь однажды порвётся.

## Общение с пользователем

Отвечай по-русски. Пользователь — селлер, не программист: говори про артикулы, логистику и прибыль, а не про `INDIRECT` и `openpyxl`.

Когда объясняешь поломку, назови причину прямо («Ozon добавил строку "Период" сверху, из-за этого колонки съехали»), а не «возникла ошибка в формулах». И если ошибку допустил ты сам — скажи об этом коротко и переходи к исправлению.
