# Разбор поломок

Все случаи ниже встречались в реальной работе. Прежде чем чинить — просканируй файл целиком и определи симптом, а не переписывай наугад.

## Диагностика за один проход

```python
import openpyxl
from collections import Counter

wb = openpyxl.load_workbook(path, data_only=False)
problems = []
for sn in wb.sheetnames:
    for row in wb[sn].iter_rows():
        for cell in row:
            v = cell.value
            if isinstance(v, str) and v.startswith('=') and ('#REF!' in v or '[' in v.split('"')[0]):
                problems.append((sn, cell.coordinate, v[:90]))

print(Counter(s for s, _, _ in problems))
shown = set()
for sn, coord, v in problems:
    if sn not in shown:
        print(f"[{sn}] {coord}: {v}")
        shown.add(sn)
```

## `#REF!` в сводной после вставки отчёта

**Симптом.** Тысячи формул вида `=СУММЕСЛИМН(Sheet1!#REF!;Sheet1!#REF!;$A4;...)`.

**Причина.** Пользователь удалил строки или столбцы в листе-приёмнике (обычная операция при очистке старых данных). Excel отследил ссылки и переписал их.

**Фикс.** Перепиши формулы через ДВССЫЛ — только это защищает навсегда:

```python
def sif(sheet, src, *crit):
    parts = [f'INDIRECT("{sheet}!{src}:{src}")']
    for cr, val in crit:
        parts += [f'INDIRECT("{sheet}!{cr}:{cr}")', val]
    return '=SUMIFS(' + ','.join(parts) + ')'
```

Если файл уже переводили на ДВССЫЛ, а `#REF!` вернулся — значит, часть формул осталась старой. Просканируй все листы, а не только сводную.

## `export!#REF!` — ВПР на лист аналитики

**Симптом.** В юните нули в остатках, оборачиваемости, рекламе, хранении. Формулы вида `=ЕСЛИОШИБКА(ВПР(A2;export!#REF!;41;0);0)`.

**Причина.** Та же — правка структуры листа Export.

**Фикс.** ДВССЫЛ + ИНДЕКС/ПОИСКПОЗ по колонке артикула:

```python
f'=IFERROR(INDEX(INDIRECT("Export!{col}:{col}"),MATCH(A{r},INDIRECT("Export!B:B"),0)),0)'
```

Здесь ИНДЕКС+ПОИСКПОЗ уместен — это поиск одного значения по ключу, не агрегация.

**Не делай так:** `ВПР(артикул; ИНДЕКС(...); 1; 0)` — ИНДЕКС вернёт столбец значений, и ВПР будет искать артикул среди сумм. Вернёт нули без единой ошибки.

## Лишняя строка «Период» в отчёте Ozon

**Симптом.** После вставки свежего отчёта Ozon вся сводная в `#REF!` или в нулях.

**Причина.** Ozon кладёт в строку 1 текст `Период: 01.07.2026-31.07.2026`, заголовки уезжают в строку 2, данные — в строку 3.

**Фикс.** Не заставляй пользователя удалять эту строку каждый раз — построй лист, который её ожидает: строка 1 — маркер, строка 2 — заголовки, данные с 3. Тогда отчёт вставляется целиком с A1.

Если чинишь существующий файл, где строка уже уехала:

```python
while ws.cell(row=1, column=1).value and 'Период' in str(ws.cell(row=1, column=1).value):
    ws.delete_rows(1)
```

## В юните везде нули

**Причина 1 — лист-приёмник пуст.** Если отдаёшь пользователю шаблон с пустым Sheet1, он откроет файл и увидит нули по всей статистике. Загружай в шаблон его же данные, чтобы файл открывался «живым».

**Причина 2 — сломанные ВПР** (см. `export!#REF!` выше).

**Причина 3 — не совпадают артикулы.** Сравни ключи из двух листов в нижнем регистре и посмотри, пересекаются ли они вообще.

## Итог не сходится с отчётом

**Симптом.** Логистика в сводной 91 123 ₽, а в отчёте 108 973 ₽.

**Причина.** Артикул есть в отчёте, но отсутствует в списке сводной, — СУММЕСЛИМН его молча не считает.

**Поиск:**

```python
raw_by_art = {}   # из сырого отчёта
pivot_arts = {str(a).lower() for a in pivot_articles}
missing = [(a, v) for a, v in raw_by_art.items() if a.lower() not in pivot_arts and abs(v) > 0.01]
```

Типовые находки:

- **`неопознанный товар`** — WB подставляет его сам; в номенклатуре пользователя такого артикула нет. Добавь строкой в сводную. Если строка в юните не нужна, учти его сумму прямо в формуле итога:
  `=СУММ(T2:T332)+ЕСЛИОШИБКА(ВПР("неопознанный товар";Лист1!$A:$J;10;0);0)`
- **новые артикулы**, появившиеся в продаже
- **разный регистр** — `JK-577` в сводной, `jk-577` в отчёте

---

## Регистр: дубли и потери

СУММЕСЛИМН в Excel регистронезависим, но только с прямыми ссылками на диапазоны. Два следствия:

1. При дедупликации списка артикулов сравнивай в нижнем регистре — иначе `JK-577` и `jk-577` дадут две строки и **двойной счёт** в итоге.
2. Не оборачивай диапазоны в `ИНДЕКС+ПОИСКПОЗ` внутри СУММЕСЛИМН — теряется регистронезависимость, и суммы молча недосчитываются.

Артикулы с **пробелом на конце** (`huawei-8-milan-loop/розовый `) — реальный случай. Не делай `.strip()` при построении списка: ключ должен совпадать с отчётом байт в байт.

## Слетел дашборд «Динамика финансы»

**Симптом.** После правки итоговой строки дашборд показывает нули.

**Причина.** Дашборд ссылается на **фиксированные адреса** (`='1'!$H$333`). Вставка строки выше сдвинула итоги на 334.

**Фикс и профилактика.** Перед правкой найди, какие строки читает дашборд, и сохрани их за итогами. Пиши в свободные строки ниже данных, **не используй `insert_rows`** на листах, куда смотрит дашборд.

```python
import re
refs = set()
for row in wb['Динамика финансы'].iter_rows():
    for cell in row:
        if isinstance(cell.value, str) and "'1'" in str(cell.value):
            for m in re.finditer(r"'1'!\$?([A-Z]+)\$?(\d+)", cell.value):
                refs.add(int(m.group(2)))
print(sorted(refs))   # → {333} — итоги обязаны остаться в 333
```

## `#ДЕЛ/0!` на дашборде

Деление на предыдущий период, которого ещё нет. Оберни в ЕСЛИОШИБКА:

```python
if isinstance(v, str) and v.startswith('=') and 'IFERROR' not in v.upper():
    cell.value = f'=IFERROR({v[1:]},0)'
```

## Ссылки на внешний файл `[1]Лист1`

**Симптом.** `#ИМЯ?` или устаревшие данные; в формуле есть `[1]`, `[2]`.

**Причина.** Файл собирали из нескольких книг, часть ссылок осталась наружу.

**Фикс.** Переведи на локальные листы. Если данные брались из внешнего справочника (например, себестоимость) — вытащи закешированные значения через `data_only=True` **до** правки и положи их в локальный лист-справочник, иначе они потеряются.

## Ошибка после сохранения через openpyxl

Формулы вида `=СУММЕСЛИМН(...)` в текстовых пояснениях (на листе «Инструкция») Excel попытается вычислить. Ставь перед ними неразрывный ноль-ширины:

```python
ws[f'B{i}'] = '\u200b' + text if text.startswith('=') else text
```

Ещё: openpyxl **не пересчитывает** формулы. Закешированные значения остаются старыми, пока не прогонишь `recalc.py`. Не делай выводов о цифрах по свежесохранённому файлу без пересчёта.
