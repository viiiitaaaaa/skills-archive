# Раскладки отчётов

Проверено на реальных выгрузках 2026 года. Маркетплейсы меняют структуру — **всегда подтверждай по факту**, прежде чем писать формулы. Если файл разошёлся с этим описанием, прав файл; обнови справочник.

## Wildberries — «Еженедельный детализированный отчёт»

Отчёт реализации. 82 колонки, заголовки в строке 1, данные со строки 2.

| Колонка | Заголовок | Роль |
|---|---|---|
| **F** | Артикул поставщика | ключ сопоставления |
| **K** | Обоснование для оплаты | тип строки |
| **N** | Кол-во | количество |
| **O** | Цена розничная | выручка |
| **P** | Вайлдберриз реализовал Товар (Пр) | сумма реализации |
| **AH** | К перечислению Продавцу за реализованный Товар | к перечислению |
| **AK** | Услуги по доставке товара покупателю | логистика |

Значения колонки K: `Продажа`, `Возврат`, `Логистика`, `Коррекция логистики`, `Хранение`, `Удержание`, `Компенсация скидки по программе лояльности`, `Возмещение издержек по перевозке/по складским операциям с товаром`, `Возмещение за выдачу и возврат товаров на ПВЗ`, `Добровольная компенсация при возврате`.

Логистика (AK) заполнена в строках с `K = "Логистика"` — суммируй **по артикулу без условия на K**, иначе потеряешь её.

### Частая ошибка

Пользователи вручную вставляли в отчёт вспомогательные колонки («КОЛ ПРОДАЖ», «ВЫРУЧКА ПРОДАЖ» и т.д.), из-за чего файл раздувался до 91 колонки и все ссылки съезжали. В автоматизированном файле этих колонок быть не должно — разделение делается вторым условием СУММЕСЛИМН.

### WB — отчёт аналитики (лист Export)

Заголовки в строке 1, артикул в колонке **B**.

| Колонка | Заголовок |
|---|---|
| C | Дней до обнуления остатков |
| V | Рекламные расходы, ₽ |
| W | Платное хранение, ₽ |
| AP | Остатки на всех складах, шт |

Позиции колонок здесь плавают между версиями выгрузки чаще, чем в отчёте реализации. Проверяй заголовки, прежде чем брать колонку по букве.

## Ozon — «Отчёт по начислениям»

16 колонок. **Строка 1 — служебная** (`Период: 01.07.2026-31.07.2026`), заголовки в **строке 2**, данные с **строки 3**.

Это главный источник поломок: если ожидать заголовки в строке 1, все ссылки съедут на строку. Не борись с этим — сделай лист, который эту строку ожидает.

| Колонка | Заголовок | Роль |
|---|---|---|
| **C** | Группа услуг | тип строки (уровень 1) |
| **D** | Тип начисления | тип строки (уровень 2) |
| **E** | Артикул | ключ сопоставления |
| **H** | Количество | количество |
| **I** | Цена продавца | выручка |
| **P** | Сумма итого, руб. | сумма начисления |

Классификация:

| Показатель | Группа услуг | Тип начисления |
|---|---|---|
| Продажа | `Продажи` | `Выручка` |
| Возврат | `Возвраты` | `Возврат выручки` |
| Комиссия | `Вознаграждение Ozon` | любой |
| Логистика | `Услуги доставки` | любой |
| Реклама | `Продвижение и реклама` | любой |
| Доп услуги | всё остальное | — |

Прочие группы: `Услуги партнёров`, `Услуги FBO`, `Обработка отправлений`, `Прочее`, `Штрафы`.

**Возвраты приходят с минусом.** Поэтому чистая выручка = продажи **+** возвраты. Вычитание даст завышенный результат.

**Реклама в начислениях идёт без артикула** — все строки «Оплата за клик» имеют пустую колонку E. Разнести её по товарам из этого отчёта невозможно; нужен ListExpense.

## Ozon — ListExpense (детализация рекламы)

7 колонок. Строка 1 — `Детализация расходов`, заголовки в **строке 2**, данные с **строки 3**.

| Колонка | Заголовок | Роль |
|---|---|---|
| **B** | Название кампании | **это артикул** — ключ сопоставления |
| **F** | Расход, ₽ | сумма рекламы |

Кампании называются по артикулу товара, поэтому колонка B работает как ключ напрямую. Это единственный способ получить рекламу по артикулам в Ozon.

## Ozon — «Стоимость размещения по товарам» (хранение)

12 колонок, заголовки в строке 1, данные со строки 2. Одна строка = товар × склад × день, поэтому строк много (десятки тысяч) — суммируй по артикулу.

| Колонка | Заголовок | Роль |
|---|---|---|
| **C** | Артикул | ключ сопоставления |
| **L** | Начисленная стоимость размещения | сумма хранения |

## Ozon — «Стоимость размещения по товарам на складе» (остатки)

27 колонок, **двухуровневая шапка**: строка 1 — группы, строка 2 — названия полей, данные с **строки 3**.

| Колонка | Заголовок (строка 2) | Роль |
|---|---|---|
| **D** | Артикул | ключ сопоставления |
| **J** | Остаток на складах, шт | остаток |
| *см. ниже* | Дней до конца остатка | оборачиваемость |

Названия в строке 1 повторяются как групповые заголовки («Размещение на 20.08.2026», «Аналитика за последние 28 дней») — ориентируйся на строку 2.

### Этот отчёт меняет ширину — колонки ищи по заголовку

Ozon добавляет сюда поля между выгрузками. Реальный случай: с 17.08 на 20.08 отчёт вырос с 27 до 29 колонок (появились «Транзит, шт/л» и «Вынужденное размещение»), и **«Дней до конца остатка» уехало с X на Z**. Артикул (D) и остаток (J) остались на месте, поэтому сумма остатков сходилась, а оборачиваемость молча поехала бы на чужие числа.

Перед каждой вставкой находи нужные колонки по тексту заголовка в строке 2, а не по букве:

```python
idx = {}
for c in range(1, ws.max_column + 1):
    for r in (1, 2):                      # шапка двухуровневая
        v = ws.cell(row=r, column=c).value
        if v: idx[str(v).strip()] = c
dni = idx['Дней до конца остатка']        # 24 в старой версии, 26 в новой
```

Если ширина изменилась — обнови формулы на листе юнита и заголовки листа-приёмника.

## Как построить лист-приёмник

Воспроизведи шапку отчёта ровно в тех строках, где она приходит из выгрузки. Тогда пользователь вставляет файл целиком с A1 и ничего не сдвигается:

| Лист | Шапка | Данные с |
|---|---|---|
| Начисления (Ozon) | строка 1 — маркер «Период», строка 2 — заголовки | строка 3 |
| Реклама (ListExpense) | строка 1 — маркер, строка 2 — заголовки | строка 3 |
| Хранение (Ozon) | строка 1 | строка 2 |
| Остатки (Ozon) | строки 1–2 (двухуровневая) | строка 3 |
| Sheet1 (WB) | строка 1 | строка 2 |
| Export (WB) | строка 1 | строка 2 |
