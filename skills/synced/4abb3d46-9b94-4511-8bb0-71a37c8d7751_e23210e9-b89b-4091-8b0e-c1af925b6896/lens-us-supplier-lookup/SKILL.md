# Поиск продавцов товара по фото через Google Lens

## Зачем этот скилл

Текстовый поиск («LED collar for dogs») находит **категорию**, а не тот же товар.
Пользователю почти всегда нужен именно тот же самый SKU с той же фабрики — чтобы
понять, кто им уже торгует в США, по какой цене, и насколько занята ниша.
Единственный способ это установить — обратный поиск по изображению.

**Правило номер один: никогда не выдавай результаты текстового поиска за найденный
«тот же товар».** Если Lens недоступен — скажи об этом прямо, а не подменяй
категорийной выдачей.

## Что нужно на входе

- Фотографии товаров (чистые, без рамки браузера — см. «Подготовка изображений»)
- Работающий Claude in Chrome
- Если картинок нет на диске — извлеки их из .xlsx (см. ниже)

## Шаг 0. Извлечение картинок из .xlsx

Часто товары лежат встроенными картинками в подборке-таблице. Не проси пользователя
сохранять их вручную — вытащи сам:

```python
import openpyxl, os, re
wb = openpyxl.load_workbook(path)
ws = wb['ИмяЛиста']
# Собери карту {номер строки: название товара} из колонок с номером и названием
rows = {r[0].row: (str(r[0].value), str(r[3].value))
        for r in ws.iter_rows(min_row=2) if r[3].value}
for im in ws._images:
    row = im.anchor._from.row + 1           # к какой строке привязана картинка
    # если точного совпадения нет — бери ближайшую строку выше
    open(f'{out}/{name}.png', 'wb').write(im._data())
```

Обязательно **привязывай картинку к строке** через `im.anchor._from.row`, иначе
получится безымянная каша из `image1.png … image88.png`, с которой невозможно работать.
Именуй файлы `{номер}_{название товара}.png`.

## Шаг 1. Подготовка изображений

`file_upload` в Chrome **не принимает пути с диска контейнера**. Единственный рабочий
способ передать картинку в Lens — `upload_image` с `imageId` от предыдущего скриншота.

Отсюда схема: картинка должна быть **открыта на экране браузера**, чтобы её снять.

Лучший вариант — залить папку с картинками в Google Drive и открывать по одному:
`https://drive.google.com/file/d/{fileId}/view` — картинка занимает почти весь кадр,
рамки минимум.

Критично: **не снимай скриншот списка файлов или окна с интерфейсом вокруг картинки.**
Lens тогда ищет «скриншот Google Drive», и вкладка «Точные совпадения» отдаёт пусто.

`zoom` для обрезки использовать нельзя — упирается в лимит 1 МБ на результат.

## Шаг 2. Регион выдачи

По умолчанию браузер может сидеть в локали пользователя (например, RU), и тогда Lens
вернёт Ozon, Wildberries, Яндекс Маркет и Авито вместо американских магазинов.

Признак проблемы: в выдаче доминируют RU-магазины, в URL — `hl=ru`.

Решение — после получения результатов подменить параметры в URL выдачи:

```
&udm=44          → вкладка «Совпадения» (visual matches), самая полезная
&hl=en&gl=us&cr=countryUS   → американская выдача
```

`udm=26` — общая вкладка, `udm=48` — «Точные совпадения».
Просто открой тот же URL результата с этими параметрами через `navigate`.

## Шаг 3. Цикл по товарам

Для каждого товара:

1. `navigate` → `https://drive.google.com/file/d/{fileId}/view`, подождать 4 с
2. `computer screenshot` → получить `imageId`
3. `navigate` → `https://lens.google.com/`, подождать 3 с
4. `find` → «file input for uploading an image». Вернёт несколько ref;
   **рабочий обычно последний** (напр. `ref_141`, не `ref_31`) — если первый не сработал,
   страница останется с пустым диалогом загрузки, просто попробуй следующий
5. `upload_image` с `imageId` и этим `ref`
6. Подождать 4 с, взять URL результата (через `find` или `screenshot` — он в tab context)
7. `navigate` на тот же URL с `udm=44&hl=en&gl=us&cr=countryUS`
8. `get_page_text` → список продавцов

Батчи (`browser_batch`) экономят время, но `upload_image` вызывай отдельно.

## Шаг 4. Как читать и подавать результат

Из выдачи вытащи и сгруппируй:

- **Маркетплейсы США**: Amazon.com, Walmart, eBay, Etsy, Temu, TikTok Shop, SHEIN US
- **Shopify-магазины и D2C-бренды** — самое ценное. Это прямые конкуренты-дропшипперы,
  которые уже льют трафик на этот товар. Если их много — ниша занята.
- **Оригинальный бренд/фабрика**: Taobao, 1688, Made-in-China, Alibaba, DHgate.
  Позволяет назвать реального производителя (напр. HiDREAM, Cdycam).
- **Не-US Amazon** (co.uk, .ca, .in, .ae) — отметь отдельно: значит, на Amazon.com
  товара, скорее всего, ещё нет. Это сигнал о свободной нише, а не мусор.

Отфильтруй шум: Instagram, TikTok-профили, Facebook, Pinterest, случайные блоги,
RU-магазины, если просили США.

Формат ответа — по товару список площадок с названиями листингов. Без выводов и
рассуждений, если пользователь их не просил: он чаще всего хочет именно ссылки.

## Частые проблемы

| Симптом | Причина | Что делать |
|---|---|---|
| «Точных совпадений не найдено» | загружен скриншот с рамкой интерфейса | открыть картинку на весь экран, переснять |
| В выдаче Ozon/WB/Авито | RU-локаль | добавить `hl=en&gl=us&cr=countryUS` |
| `file_upload` ругается на путь | пути с диска запрещены | только `upload_image` с `imageId` |
| `zoom` → «result too large» | лимит 1 МБ | не обрезать, а открывать картинку крупно |
| Диалог Lens остался пустым | взят не тот `ref` файлового инпута | попробовать следующий ref из списка |
| Папка Drive не открывается | не тот Google-аккаунт в коннекторе | попросить расшарить папку на подключённый аккаунт |

## Масштаб

Каждый товар — примерно 5–7 вызовов браузера и заметный объём текста выдачи.
Больше 8–10 товаров за один разговор не стоит: контекст переполняется и работа
замедляется. Если товаров много, предупреди пользователя заранее и предложи
разбить на несколько заходов.
